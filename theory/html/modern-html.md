# X. Современный HTML

### 1. Для чего используется `<dialog>`?

Элемент `<dialog>` предназначен для создания **диалоговых окон и других интерфейсов, которые временно взаимодействуют с пользователем поверх основного содержимого**.

Например:

```html
<dialog id="confirm-dialog">
  <p>Удалить файл?</p>

  <button type="button">
    Отмена
  </button>

  <button type="button">
    Удалить
  </button>
</dialog>
```

Сам по себе `<dialog>` изначально закрыт.

Открыть его можно через JavaScript:

```js
const dialog = document.querySelector('#confirm-dialog');

dialog.show();
```

или как модальное окно:

```js
dialog.showModal();
```

Закрывается диалог методом:

```js
dialog.close();
```

Главное преимущество `<dialog>` — браузер уже предоставляет нативную семантику и часть поведения диалогового окна.

---

### 2. Чем модальный dialog отличается от немодального?

Главное отличие — возможность взаимодействовать с остальной страницей.

#### Немодальный dialog

Открывается методом:

```js
dialog.show();
```

Пользователь может продолжать взаимодействовать с другими элементами страницы.

#### Модальный dialog

Открывается:

```js
dialog.showModal();
```

Он требует внимания пользователя, а остальная часть документа временно становится недоступной для обычного взаимодействия.

---

### 3. Что происходит с остальной страницей при `dialog.showModal()`?

При вызове:

```js
dialog.showModal();
```

диалог добавляется в **top layer** браузера.

Остальная часть документа становится **inert**.

Это означает, что пользователь не может нормально взаимодействовать с содержимым за модальным окном:

- элементы нельзя активировать;
- они не получают обычный фокус;
- взаимодействие с ними блокируется.

Сам dialog при этом остаётся интерактивным.

Браузер также создаёт специальный псевдоэлемент:

```css
dialog::backdrop {
  background: rgb(0 0 0 / 0.5);
}
```

который можно использовать для оформления области за модальным окном.

### 4. Что такое Popover API?

**Popover API** — нативный механизм веб-платформы для отображения содержимого поверх другого содержимого страницы.

Поповер создаётся с помощью глобального атрибута:

```html
<div popover>
  Настройки
</div>
```

Например:

```html
<button popovertarget="menu">
  Открыть меню
</button>

<div id="menu" popover>
  Содержимое меню
</div>
```

Браузер самостоятельно управляет показом и скрытием такого элемента.

Открытый popover помещается в **top layer**, поэтому ему не приходится вручную решать многие проблемы с:

```text
z-index
overflow
positioning contexts
```

Popover API подходит, например, для:

- небольших меню;
- подсказок;
- дополнительных панелей;
- selection UI;
- некоторых уведомлений.

Popover по своей природе является **немодальным**: остальная страница не становится inert.

---

### 5. В каких случаях popover позволяет обойтись без собственного JavaScript?

Для простого открытия и закрытия popover JavaScript вообще не обязателен.

Например:

```html
<button popovertarget="profile-menu">
  Профиль
</button>

<div
  id="profile-menu"
  popover
>
  ...
</div>
```

`popovertarget` связывает кнопку с popover по его `id`.

Браузер самостоятельно обрабатывает открытие и закрытие.

Можно также явно указать действие:

```html
<button
  popovertarget="menu"
  popovertargetaction="show"
>
  Открыть
</button>
```

Доступны:

```text
show
hide
toggle
```

Для `popover="auto"` браузер также предоставляет **light dismiss** — например, закрытие при взаимодействии вне popover или при соответствующем запросе закрытия.

Поэтому собственный JavaScript не требуется, если нужно только стандартное управление показом и скрытием.

### 6. Что такое атрибут `inert`?

`inert` — глобальный булев HTML-атрибут, который делает элемент и его потомков **неактивными для взаимодействия пользователя**.

Например:

```html
<div inert>
  <button>
    Купить
  </button>

  <a href="/catalog">
    Каталог
  </a>
</div>
```

Элементы внутри inert-поддерева:

- не участвуют в обычной фокус-навигации;
- не могут нормально активироваться пользователем;
- исключаются из accessibility tree;
- не должны быть доступны вспомогательным технологиям как интерактивное содержимое.

```html
<div inert>
  ...
</div>
```

не означает, что элемент обязательно исчезает визуально.

Он может оставаться видимым, но быть неактивным.

#### Короче:

`inert` делает элемент и его потомков неинтерактивными и исключает их из обычного фокуса и accessibility tree.

---

### 7. Чем `hidden` отличается от `inert`?

`hidden` и `inert` решают разные задачи.

### `hidden`

```html
<div hidden>
  Содержимое
</div>
```

указывает, что содержимое сейчас не должно представляться пользователю.

Обычно такой элемент не отображается.

### `inert`

```html
<div inert>
  Содержимое
</div>
```

может оставаться визуально видимым, но становится неактивным.

`inert` также влияет на фокус и accessibility tree.

#### Короче:

`hidden` скрывает содержимое.

`inert` делает содержимое неинтерактивным и недоступным для фокус-навигации и вспомогательных технологий, но не обязательно скрывает его визуально.

### 8. Что такое `contenteditable`?

`contenteditable` — глобальный атрибут, позволяющий сделать содержимое HTML-элемента **редактируемым пользователем**.

Например:

```html
<p contenteditable="true">
  Этот текст можно редактировать.
</p>
```

Пользователь может установить курсор внутрь элемента и изменять его содержимое непосредственно на странице.

Например:

```html
<div contenteditable="true">
  Редактируемая область
</div>
```

`contenteditable` не превращает элемент в обычный `<input>` или `<textarea>`.

Разработчику самостоятельно приходится решать вопросы:

- сохранения содержимого;
- валидации;
- обработки вставленного текста;
- управления HTML-разметкой;
- accessibility.

Существуют значения:

```text
true
false
plaintext-only
```

`plaintext-only` позволяет редактировать текст без rich-text форматирования там, где это поддерживается.

### 9. Для чего используются `<details>` и `<summary>`?

`<details>` и `<summary>` создают нативный **раскрывающийся блок**.

Например:

```html
<details>
  <summary>
    Что такое HTML?
  </summary>

  <p>
    HTML — язык разметки.
  </p>
</details>
```

`<summary>` является видимой частью, по которой пользователь может активировать раскрытие.

Содержимое `<details>` показывается или скрывается браузером.

Открытое состояние обозначается атрибутом:

```html
<details open>
  ...
</details>
```

Браузер предоставляет нативное интерактивное поведение без необходимости самостоятельно реализовывать его через JavaScript.

---

### 10. Когда лучше использовать нативный `<details>` вместо самостоятельно написанного accordion?

`<details>` хорошо подходит, когда интерфейс представляет простое раскрытие дополнительного содержимого.

Например:

```html
<details>
  <summary>
    Доставка
  </summary>

  <p>
    Доставка занимает 2–3 дня.
  </p>
</details>
```

Преимущества:

- работает без JavaScript;
- имеет встроенное keyboard-поведение;
- имеет нативную семантику;
- поддерживает состояние `open`;
- проще в реализации и поддержке.

Собственный accordion нужен, если интерфейс требует поведения, которое нельзя удобно выразить через `<details>`.

Например:

- сложная логика переключения;
- нестандартное управление фокусом;
- интеграция с состоянием приложения;
- специфические требования к компоненту.

При простой задаче предпочтительно использовать нативный элемент.

### 11. Что такое `<template>`?

`<template>` — HTML-элемент для хранения фрагмента разметки, который **не отображается как обычное содержимое страницы при первоначальном разборе документа**.

Например:

```html
<template id="card-template">
  <article class="card">
    <h2 class="card__title"></h2>
  </article>
</template>
```

Содержимое шаблона хранится отдельно и доступно через JavaScript:

```js
const template =
  document.querySelector('#card-template');

console.log(template.content);
```

`template.content` представляет собой:

```text
DocumentFragment
```

Его можно клонировать и вставлять в документ.

#### Короче:

`<template>` хранит неотрендеренный HTML-фрагмент для последующего использования.

Его содержимое доступно через `template.content`.

### 12. Для чего используется `<template>`?

`<template>` в HTML используется как контейнер для хранения клиентского содержимого, которое не должно отображаться на странице сразу после загрузки.

Например:

```html
<template id="product-template">
  <article class="product">
    <h2 class="product__title"></h2>
    <p class="product__price"></p>
  </article>
</template>
```

JavaScript:

```js
const template =
  document.querySelector('#product-template');

const product =
  template.content.cloneNode(true);

product.querySelector('.product__title')
  .textContent = 'Кольцо';

product.querySelector('.product__price')
  .textContent = '50 000 ₸';

document.body.append(product);
```

`<template>` полезен для:

- повторяющихся компонентов;
- динамически создаваемой разметки;
- Web Components;
- клиентского рендеринга небольших HTML-фрагментов.

Главное преимущество заключается в том, что шаблон можно описать в HTML, но он не участвует в обычном отображении страницы до использования.

#### Короче:

`<template>` используется как заготовка HTML-разметки, которую можно клонировать и вставлять в документ через JavaScript.

### 13. Что такое `<slot>` и как он связан с Web Components?

`<slot>` используется в **Shadow DOM** и определяет место, куда будет вставлено содержимое, переданное пользователем Web Component.

Допустим, существует компонент:

```html
<user-card>
  Diana
</user-card>
```

В его Shadow DOM может находиться:

```html
<div class="card">
  <slot></slot>
</div>
```

Текст:

```text
Diana
```

будет отображён в месте `<slot>`.

Это называется **slotting**.

Можно создавать именованные slots:

```html
<article>
  <slot name="title"></slot>
  <slot name="content"></slot>
</article>
```

Использование:

```html
<user-card>
  <h2 slot="title">
    Diana
  </h2>

  <p slot="content">
    Frontend Developer
  </p>
</user-card>
```

Связь выглядит так:

```text
slot="title"
        ↓
<slot name="title">
```

Если `name` отсутствует:

```html
<slot></slot>
```

это **default slot**.

`<slot>` имеет смысл прежде всего внутри shadow tree.

### 14. Какие состояния существуют у `popover`?

У `popover` существуют разные режимы поведения.

Основные:

```text
auto
manual
hint
```

### `popover="auto"`

```html
<div popover="auto">
  ...
</div>
```

Это стандартный режим.

Такой popover поддерживает light dismiss и обычно автоматически закрывается при открытии другого несовместимого `auto` popover.

Запись:

```html
<div popover>
```

эквивалентна:

```html
<div popover="auto">
```

### `popover="manual"`

```html
<div popover="manual">
  ...
</div>
```

Такой popover не закрывается автоматически через стандартный light dismiss.

Его показом и скрытием нужно управлять явно.

### `popover="hint"`

`hint` предназначен для более лёгких временных popover-интерфейсов, например некоторых подсказок.

Он имеет отдельные правила взаимодействия со стеком других popovers.

#### Короче:

Основные состояния:

```text
auto   → стандартное поведение и light dismiss
manual → ручное управление
hint   → временный вспомогательный popover
```
