## I. База

### 1. Что такое HTML и для чего он используется?

HTML (HyperText Markup Language — «язык гипертекстовой разметки») — это язык, на котором создают структуру веб‑страниц. Если перевести дословно, hypertext — это текст со ссылками, которые связывают страницы между собой, а markup — разметка, то есть система тегов. 

HTML задает структуру страницы — организует содержимое в иерархию, которая понятна браузерам и поисковикам. Во‑вторых, HTML описывает контент: текст, изображения, таблицы, формы — всё это появляется на странице благодаря тегам. И в‑третьих, HTML служит основой для всего остального: без разметки CSS не понимает, что стилизовать, а JavaScript — с какими элементами работать.

История: В 1991 году учёный Тим Бернерс‑Ли предложил первую версию HTML. С тех пор HTML прошёл долгий путь: появились HTML 2.0, HTML 4.01, XHTML — и каждая версия расширяла возможности языка. Сегодня современный веб в основном опирается на стандарт HTML5, который появился в 2014 году. Его развивает и поддерживает W3C (World Wide Web Consortium) — международная некоммерческая организация, основанная Тимом Бернерсом‑Ли в 1994 году.

### 2. Почему HTML — это язык разметки, а не язык программирования?

HTML — это не язык программирования. Представьте редактора, который работает с рукописью в издательстве: он берёт текст и карандашом помечает — этот фрагмент выделить жирным, этот оформить как заголовок, здесь вставить картинку. Редактор не переписывает текст, а размечает инструкции по структуре текста. 

HTML делает похожую разметку: с помощью тегов он объясняет браузеру, какие элементы есть на странице и как они связаны между собой. И на этом всё: HTML не управляет логикой, не выполняет вычисления и не реагирует на действия пользователя. Для этого нужно подключать языки программирования. Например, вы заходите в интернет‑магазин и видите каталог: карточки товаров, названия, цены, описания, кнопки «В корзину». Вот за то, какие элементы есть на странице и как они организованы, отвечает HTML. CSS задает внешний вид этих элементов. А когда вы добавляете товар в корзину и после этого что‑то меняется на странице — в работу вступает язык JavaScript.

### 3. Что такое HTML-элемент?

Это основная структурная единица веб-страницы, которая определяет её содержимое и внешний вид. Большинство элементов состоит из трех частей: Открывающий тег — имя элемента в угловых скобках (например, `<p>`), которое показывает, где элемент начинается. Содержимое — текст, картинки или другие элементы, расположенные внутри. Закрывающий тег.

**Например:** 

- `<html>` — представляет собой корень (элемент верхнего уровня) HTML-документа, поэтому его так же называют корневым элементом. Все другие элементы должны быть потомками этого элемента (должны находиться внутри него).
- `<base>` — определяет основной адрес (URL), используемый для всех относительных адресов (URLs) в документе. Может быть только один `<base>` элемент в одном документе.
- `<meta>` — служебная информацией о странице, которая не может быть представлена другими HTML-метатегами, такими как `<base>`, `<link>`, `<script>`, `<style>` или `<title>`.
- `<head>` — служебная часть документа — здесь хранятся метаданные, заголовок страницы, а также подключаемые стили, шрифты и другие файлы
- `<body>` — Тело страницы — здесь находится основной контент, который видит пользователь на странице в браузере

Директива `<! DOCTYPE html>` в самом начале файла сообщает браузеру, что перед ним HTML5-документ. 

### 4. Чем отличаются тег, элемент и атрибут?

**Тег** — это маркер в угловых скобках, который указывает браузеру, где начинается и заканчивается элемент на странице (например, `<p>` или `</p>`).

**Элемент** — это вся конструкция целиком, включая открывающий тег, содержимое и закрывающий тег (например, `<p>Привет</p>`).

**Атрибут** — это свойство внутри открывающего тега, которое расширяет возможности тега: задают стили, добавляют ссылки, управляют мультимедиа.

У каждого тега есть атрибуты. Н-р, элемент `<img>` включает в себя два основных атрибута — `src` и `alt`. Первый добавляет ссылку на файл, а второй — подпись к картинке, которая покажется, если файл не загрузится.

### 5. Что такое вложенность элементов?

Это размещение одних тегов внутри других, создающее иерархические связи «родитель — потомок».

### 6. Что такое глобальные атрибуты HTML?

Это атрибуты общие для всех HTML-элементов; они могут использоваться всеми элементами, хотя на некоторые элементы могут не оказывать влияния.

### 7. Какие глобальные атрибуты вы знаете?

Основные:

- `id` — уникальный идентификатор элемента в документе.
- `class` — задаёт один или несколько классов, используется для CSS и JavaScript.
- `style` — позволяет задать inline CSS-стили элементу.
- `title` — содержит дополнительную информацию об элементе, часто отображается как подсказка.
- `lang` — указывает язык содержимого элемента.
- `dir` — задаёт направление текста: `ltr`, `rtl` или `auto`.
- `hidden` — скрывает элемент, который в данный момент не должен отображаться.
- `tabindex` — управляет возможностью получения фокуса и участием элемента в навигации с клавиатуры:
  - `tabindex="0"` — элемент участвует в обычном порядке навигации;
  - `tabindex="-1"` — может получить фокус программно, но не через последовательную навигацию Tab;
  - положительные значения задают порядок фокуса, но использовать их обычно не рекомендуется.
- `contenteditable` — определяет, может ли пользователь редактировать содержимое элемента.
- `draggable` — определяет, можно ли перетаскивать элемент с помощью Drag and Drop API.
- `spellcheck` — включает или отключает проверку орфографии.
- `translate` — указывает, следует ли переводить содержимое элемента при локализации.
- `accesskey` — задаёт клавишу для быстрого доступа к элементу.
- `data-*` — позволяет хранить пользовательские данные непосредственно в HTML. В JavaScript к ним можно обращаться через `element.dataset`.

Также к глобальным относятся:

- `aria-*` — ARIA-атрибуты, используемые для улучшения доступности интерфейса;
- атрибуты обработчиков событий: `onclick`, `oninput`, `onchange`, `onkeydown`, `onfocus`, `onsubmit` и другие;
- `itemid`, `itemprop`, `itemref`, `itemscope`, `itemtype` — используются для HTML-микроданных.

Также существуют устаревшие или исторические глобальные атрибуты, например `xml:lang`, `xml:base`, `contextmenu` и `dropzone`. В современном HTML они практически не используются.

### 8. Что такое `data-*` атрибуты и для чего они используются?

`data-*` — это пользовательские HTML-атрибуты для хранения дополнительной информации непосредственно в HTML-элементах. Они начинаются с префикса `data-`, после которого указывается собственное имя атрибута.

Например: `<button data-size="large">Button</button>`.

`data-*` атрибуты используются для хранения состояния и дополнительной информации об элементе, стилизации через CSS, управления через JavaScript и передачи настроек компонентам.

В CSS к ним можно обращаться через селекторы атрибутов: `[data-size="large"]`.

В JavaScript данные можно получать и изменять через `dataset`: `element.dataset.size`. Также можно использовать `getAttribute()` и `setAttribute()`.

Например, `data-size` в HTML соответствует `dataset.size` в JavaScript.

### 9. Что такое булевы атрибуты? Приведите примеры.

**Булевы атрибуты** — это HTML-атрибуты, для которых важно само наличие атрибута у элемента.

Если булев атрибут присутствует — его значение считается `true`.  
Если отсутствует — `false`.

Например:

```html
<input type="checkbox" checked>
<input type="text" disabled>
<input type="email" required>
```

Булев атрибут можно записать несколькими способами:

```html
<input disabled>
<input disabled="">
<input disabled="disabled">
```

Все эти варианты означают одно и то же — `disabled` включён.

Важно: значения `"true"` и `"false"` не задают логическое значение атрибута. Если атрибут присутствует, он считается истинным даже при записи:

```html
<input disabled="false">
```

Этот элемент всё равно будет `disabled`.

Примеры булевых атрибутов: `disabled`, `checked`, `required`, `readonly`, `multiple`, `selected`, `autofocus`, `autoplay`, `controls`, `loop`, `muted`, `inert`.

### 10. Что такое void elements? Какие элементы относятся к ним?

**Void elements** — это HTML-элементы, которые не могут содержать внутри себя никакого контента и поэтому не имеют закрывающего тега.

Например:

```html
<img src="photo.jpg" alt="Фото">
```

У `<img>` нет парного `</img>`, потому что изображение не содержит текст или другие HTML-элементы внутри себя.

Для сравнения обычный элемент:

```html
<p>Текст</p>
```

`<p>` содержит контент, поэтому у него есть открывающий и закрывающий теги.

В современном HTML void elements это:

- `<area>`
- `<base>`
- `<br>`
- `<col>`
- `<embed>`
- `<hr>`
- `<img>`
- `<input>`
- `<link>`
- `<meta>`
- `<source>`
- `<track>`
- `<wbr>`

Например:

```html
<input type="email">
<br>
<hr>
<img src="cat.jpg" alt="Кот">
<meta charset="UTF-8">
<link rel="stylesheet" href="style.css">
```

В HTML не нужно писать `/` в конце void-элемента:

```html
<img src="photo.jpg" alt="Фото">
```

Запись:

```html
<img src="photo.jpg" alt="Фото" />
```

тоже часто встречается и браузером обрабатывается нормально, но `/` здесь не является закрывающим тегом и в HTML не требуется.

### 11. Что происходит, если HTML написан с ошибками?

Браузер обычно **не прекращает обработку страницы при ошибках в HTML**. Вместо этого HTML-парсер пытается исправить ошибки и построить корректное DOM-дерево по правилам стандарта.

Например, если не закрыть тег:

```html
<p>Первый абзац
<p>Второй абзац
```

браузер автоматически закроет первый `<p>` перед началом второго.

При неправильной вложенности:

```html
<p><strong>Текст</p></strong>
```

браузер также попытается восстановить корректную структуру документа.

Из-за этого страница может визуально отображаться нормально, даже если HTML содержит ошибки. Однако браузер может построить DOM не так, как ожидал разработчик, что способно привести к проблемам со стилями, JavaScript и доступностью.

Поэтому HTML следует проверять валидатором и не полагаться на автоматическое исправление ошибок браузером.

#### Короче:
Если HTML содержит ошибки, браузер обычно не останавливает загрузку страницы. HTML-парсер пытается исправить разметку по определённым правилам и построить DOM-дерево. Поэтому страница может работать, но структура DOM может отличаться от ожидаемой разработчиком.

### 12. Что такое DOM и как он связан с HTML?

**DOM (Document Object Model)** — это представление HTML-документа в виде древовидной структуры объектов.

Браузер читает HTML-код, разбирает его и на его основе строит **DOM-дерево**.

Например, HTML:

```html
<body>
  <h1>Заголовок</h1>
  <p>Текст</p>
</body>
```

будет представлен в DOM примерно так:

```text
body
├── h1
│   └── "Заголовок"
└── p
    └── "Текст"
```

Каждый элемент и фрагмент текста становится отдельным **узлом (node)** в DOM.

**Узел (node)** — это базовая единица DOM, из которой строится всё DOM-дерево.

Чаще всего используются два типа узлов:

- **Element nodes** — HTML-элементы: `<div>`, `<p>`, `<button>`, `<h1>`. Они образуют структуру страницы.
- **Text nodes** — текст внутри элементов.

Например:

```html
<h1>Заголовок</h1>
```

`<h1>` — это узел-элемент, а `Заголовок` — отдельный текстовый узел внутри него.

#### Как DOM связан с HTML?

**HTML — это исходная разметка документа, а DOM — объектное представление этой разметки, созданное браузером.**

Через DOM JavaScript может получать доступ к элементам страницы, изменять их содержимое, атрибуты и структуру.

#### Короче:
**DOM (Document Object Model)** — это объектное представление HTML-документа в виде дерева узлов. Браузер парсит HTML и строит на его основе DOM-дерево, с которым затем может работать JavaScript.

### 13. Что делает браузер с HTML после его получения от сервера?

После получения HTML-кода от сервера браузер начинает его обработку и постепенно превращает исходный код в визуальную страницу.

Основные этапы:

#### 1. Парсинг HTML и построение DOM

Браузер читает HTML и выполняет **токенизацию** — преобразует исходный код в токены, например открывающие и закрывающие теги.

На основе этих токенов браузер строит **DOM (Document Object Model)** — древовидное объектное представление HTML-документа.

Во время парсинга браузер также обнаруживает дополнительные ресурсы: CSS, JavaScript, изображения, шрифты и начинает их загрузку.

#### 2. Обработка CSS и построение CSSOM

Браузер обрабатывает загруженные CSS-стили и строит **CSSOM (CSS Object Model)** — объектное представление CSS-правил.

CSS обычно является render-blocking ресурсом: браузеру необходима информация о стилях для корректной отрисовки страницы.

#### 3. Создание Render Tree

Браузер использует DOM и информацию из CSSOM для формирования **Render Tree**.

Render Tree содержит элементы, которые необходимо отобразить, и информацию об их вычисленных стилях.

Например, элементы с:

```css
display: none;
```

не попадают в Render Tree.

#### 4. Layout

На этапе **Layout** браузер рассчитывает геометрию элементов:

- ширину и высоту;
- положение на странице;
- координаты относительно других элементов.

То есть браузер определяет, **где и какого размера будет каждый элемент**.

#### 5. Paint

На этапе **Paint** браузер определяет, как должны выглядеть элементы: текст, цвета, границы, тени, фоновые изображения и другие визуальные свойства.

После этого происходит растеризация — преобразование этой информации в пиксели.

#### 6. Compositing

Некоторые части страницы могут находиться на отдельных слоях.

На этапе **Compositing** браузер объединяет эти слои в правильном порядке и формирует итоговое изображение страницы на экране.

Таким образом, упрощённо процесс можно представить так:

```text
HTML → DOM
CSS  → CSSOM

DOM + CSSOM
      ↓
 Render Tree
      ↓
    Layout
      ↓
    Paint
      ↓
 Compositing
```

#### Влияние JavaScript

Обычный внешний `<script>` без `async` или `defer` может остановить парсинг HTML, пока скрипт не загрузится и не выполнится, поскольку JavaScript способен изменять DOM.

Атрибуты `async` и `defer` позволяют загружать внешний скрипт параллельно с парсингом HTML:

- `defer` — скрипт выполняется после завершения парсинга HTML;
- `async` — скрипт выполняется сразу после загрузки и в этот момент может приостановить парсинг HTML.

#### Короче:
После получения HTML браузер парсит его и строит DOM. Параллельно загружаются дополнительные ресурсы, включая CSS и JavaScript. Из CSS строится CSSOM, после чего DOM и CSSOM используются для формирования Render Tree. Затем браузер выполняет Layout, определяя размеры и положение элементов, Paint — их отрисовку, и Compositing — объединение слоёв в итоговое изображение страницы.

### 14. Как HTML parser обрабатывает неправильную разметку и почему итоговый DOM может отличаться от исходного HTML?

HTML parser не прекращает работу при большинстве ошибок в разметке. Вместо этого браузер применяет определённые правила восстановления и продолжает строить DOM. Эти правила стандартизированы, поэтому современным браузерам предписано одинаково интерпретировать даже многие некорректные HTML-конструкции.

Например:

```html
<p>
  Первый абзац
<p>
  Второй абзац
```

В исходном HTML первый `<p>` явно не закрыт.

Но при появлении второго `<p>` parser понимает, что предыдущий абзац должен быть завершён, и DOM фактически будет соответствовать структуре:

```html
<p>Первый абзац</p>
<p>Второй абзац</p>
```

То есть:

```text
HTML source
     ↓
HTML parser
     ↓
правила parsing + error recovery
     ↓
DOM
```

Поэтому **DOM — это не буквальная копия HTML-файла**.

Браузер может:

- автоматически закрыть элемент;
- проигнорировать некоторые теги;
- изменить вложенность;
- создать недостающий элемент;
- переместить узлы в другое место дерева.

Например, если исходная разметка нарушает правила вложенности, browser parser может перестроить её так, чтобы получить DOM согласно алгоритму HTML parsing.

Именно поэтому при отладке важно смотреть не только исходный HTML, но и DOM в DevTools.

### 15. Как работает HTML parser?

HTML parser преобразует HTML-код в DOM-дерево.

Упрощённо процесс состоит из двух основных этапов:

```text
HTML
 ↓
tokenization
 ↓
tokens
 ↓
tree construction
 ↓
DOM
```

#### 1. Tokenization

Parser читает последовательность символов HTML и преобразует её в **токены**.

Например:

```html
<p>Hello</p>
```

концептуально превращается в:

```text
start tag: p
text: Hello
end tag: p
```

Токенами могут быть:

- start tags;
- end tags;
- текст;
- комментарии;
- DOCTYPE;
- атрибуты в составе тегов.

#### 2. Tree construction

Затем браузер использует токены для построения DOM-дерева.

Например:

```html
<body>
  <h1>Hello</h1>
  <p>Text</p>
</body>
```

становится примерно таким деревом:

```text
body
├── h1
│   └── "Hello"
└── p
    └── "Text"
```

При построении дерева parser учитывает не только порядок тегов, но и **специальные правила HTML parsing**.

Поэтому запись:

```html
<p>
  Text
  <div>Block</div>
</p>
```

не означает, что `<div>` обязательно станет дочерним элементом `<p>`.

HTML не разрешает такую структуру, поэтому parser автоматически завершит `<p>` перед `<div>`.

DOM будет концептуально ближе к:

```html
<p>Text</p>

<div>Block</div>

<p></p>
```

Точная структура зависит от parsing algorithm.

Поэтому:

```text
HTML source ≠ гарантированно DOM
```

HTML source — входные данные для parser.

DOM — результат их обработки.

### 16. Что такое error recovery в HTML parser?

**Error recovery** — это механизм, с помощью которого HTML parser продолжает обрабатывать документ после обнаружения некорректной разметки.

В отличие, например, от строгого XML parsing, HTML обычно не прекращает обработку документа из-за синтаксической ошибки.

В HTML Standard определены **parse errors** и правила того, что parser должен делать после их обнаружения.

Например:

```html
<ul>
  <li>Первый
  <li>Второй
</ul>
```

Закрывающие `</li>` отсутствуют.

Parser способен определить границы элементов и построить DOM, эквивалентный:

```html
<ul>
  <li>Первый</li>
  <li>Второй</li>
</ul>
```

Другой пример:

```html
<p>Первый
<p>Второй
```

при появлении нового `<p>` предыдущий абзац автоматически завершается.

Error recovery нужен в том числе потому, что браузеры должны уметь отображать огромное количество существующих страниц, включая страницы с несовершенной разметкой.

Но это не означает, что ошибки можно игнорировать.

Parser может восстановить структуру **не так, как предполагал разработчик**, что затем влияет на:

- CSS;
- JavaScript;
- DOM traversal;
- accessibility;
- поведение интерфейса.

Поэтому корректность разметки всё равно следует проверять.

#### Короче

Error recovery — набор правил HTML parser для обработки некорректной разметки.

Браузер обычно не прекращает parsing, а исправляет или переинтерпретирует HTML и продолжает строить DOM.

### 17. Почему неправильная вложенность элементов может привести к неожиданной структуре DOM?

HTML имеет правила о том, какие элементы могут находиться внутри других элементов.

Если разметка нарушает эти правила, parser не обязан сохранять написанную разработчиком вложенность.

Например:

```html
<p>
  Текст
  <div>
    Блок
  </div>
</p>
```

На первый взгляд кажется, что DOM будет:

```text
p
├── text
└── div
```

Но `<div>` не может находиться внутри `<p>` таким образом.

При встрече `<div>` parser автоматически завершает открытый `<p>`.

Поэтому итоговое дерево меняется.

Ещё один пример — неправильно вложенные formatting elements:

```html
<p>
  <strong>
    Bold
    <em>text
  </strong>
  other
  </em>
</p>
```

Для подобных случаев HTML parser использует специальные алгоритмы восстановления, включая так называемый **adoption agency algorithm**, который может изменить родителей узлов и создать дополнительные элементы.

Поэтому визуально код может выглядеть почти нормально, но реальная DOM-структура будет другой.

Это важно для JavaScript.

Например:

```js
element.parentElement
```

может вернуть не тот элемент, который разработчик ожидал на основании исходного HTML.
