# III. Семантическая HTML-разметка

### 1. Что такое семантическая HTML-разметка?

**Семантическая HTML-разметка** — это подход к созданию HTML-документа, при котором элементы выбираются не по внешнему виду, а по их **смыслу и роли в структуре документа**.

Например:

```html
<header>
  ...
</header>

<nav>
  ...
</nav>

<main>
  ...
</main>

<footer>
  ...
</footer>
```

Здесь каждый элемент сообщает, какую роль выполняет соответствующая часть страницы.

Семантика элемента — это его значение в модели документа.

Например:

```html
<nav>
```

означает область навигации,

```html
<article>
```

— самостоятельный материал,

```html
<aside>
```

— дополнительный контент, связанный с основным содержимым.

Семантическая разметка помогает браузерам, вспомогательным технологиям и другим программам понимать структуру документа.

---

### 2. Какие преимущества даёт семантическая разметка по сравнению с набором `<div>` и `<span>`?

`<div>` и `<span>` — универсальные элементы без собственной семантики.

Например:

```html
<div class="navigation">
  ...
</div>
```

и:

```html
<nav>
  ...
</nav>
```

могут визуально выглядеть одинаково, но второй вариант явно сообщает, что эта область содержит навигацию.

Семантические элементы дают несколько преимуществ:

- делают структуру документа понятнее;
- улучшают читаемость HTML;
- помогают вспомогательным технологиям;
- позволяют браузеру и другим инструментам лучше интерпретировать документ;
- упрощают поддержку кода;
- могут давать поисковым системам дополнительную информацию о структуре страницы.

`<div>` и `<span>` всё равно остаются важными элементами и используются там, где подходящего семантического элемента нет.

---

### 3. Какие семантические элементы HTML вы знаете?

К семантическим HTML-элементам относятся элементы, название и назначение которых описывают роль содержимого.

Например:

```html
<header>
<footer>
<main>
<nav>
<section>
<article>
<aside>
```

Также семантическими являются многие другие элементы:

```html
<h1>–<h6>
<p>
<address>
<figure>
<figcaption>
<time>
<mark>
<blockquote>
<cite>
<details>
<summary>
```

Семантика есть не только у элементов, появившихся в HTML5.

Например:

```html
<p>
```

семантически обозначает абзац,

```html
<h1>
```

— заголовок,

```html
<button>
```

— кнопку,

```html
<a>
```

— гиперссылку.

Поэтому выражение «семантические теги» не означает только набор `<header>`, `<main>`, `<section>` и подобных элементов.

---

### 4. Чем `<main>` отличается от обычного `<div>`?

`<main>` представляет **основное содержимое документа**.

Это содержимое должно быть непосредственно связано с главной темой или основной функцией страницы.

Например:

```html
<main>
  <h1>Каталог товаров</h1>
  ...
</main>
```

`<div>` не имеет собственной семантики:

```html
<div>
  ...
</div>
```

Он используется как универсальный контейнер, когда более подходящего семантического элемента нет.

Главное различие:

```text
<main> → основной контент страницы
<div>  → нейтральный контейнер
```

`<main>` также может использоваться вспомогательными технологиями как ориентир для быстрого перехода к основному содержимому.

---

### 5. Для чего используется `<header>`?

`<header>` используется для **вводного содержимого** или группы навигационных и служебных элементов, относящихся к странице или конкретному разделу.

Например:

```html
<header>
  <h1>Frontend Blog</h1>
  <nav>
    ...
  </nav>
</header>
```

Внутри `<header>` часто располагаются:

- заголовок;
- логотип;
- навигация;
- вводный текст;
- поисковая форма;
- метаданные раздела.

`<header>` не обязательно означает только верхнюю часть всей страницы.

Он может относиться и к отдельному `<article>` или `<section>`.

---

### 6. Может ли на странице быть несколько `<header>`?

Да.

На странице может быть несколько `<header>`, если они относятся к разным частям документа.

Например:

```html
<header>
  <h1>Новостной сайт</h1>
</header>

<main>
  <article>
    <header>
      <h2>Заголовок статьи</h2>
      <p>Автор: Diana</p>
    </header>

    ...
  </article>
</main>
```

Первый `<header>` относится ко всей странице.

Второй — к конкретному `<article>`.

Поэтому `<header>` не является элементом, который разрешено использовать только один раз.

---

### 7. Для чего используется `<footer>`?

`<footer>` представляет **завершающую информацию** для страницы или отдельной части документа.

Например:

```html
<footer>
  <p>© 2026 Frontend Blog</p>
</footer>
```

В `<footer>` часто располагаются:

- информация об авторе;
- copyright;
- контактная информация;
- ссылки на связанные материалы;
- служебная навигация;
- информация о документе.

`<footer>` может относиться не только ко всей странице, но и к `<article>` или другой части документа.

---

### 8. Может ли на странице быть несколько `<footer>`?

Да.

На странице может быть несколько `<footer>`, если каждый относится к своему контексту.

Например:

```html
<article>
  <h2>Статья</h2>

  <p>...</p>

  <footer>
    Автор: Diana
  </footer>
</article>

<footer>
  © 2026 Example
</footer>
```

Первый `<footer>` завершает статью.

Второй относится ко всей странице.

---

### 9. Для чего используется `<nav>`?

`<nav>` представляет **раздел страницы, содержащий основные навигационные ссылки**.

Например:

```html
<nav>
  <a href="/">Главная</a>
  <a href="/catalog">Каталог</a>
  <a href="/contacts">Контакты</a>
</nav>
```

`<nav>` используют для значимых навигационных блоков:

- основное меню;
- навигация по разделам;
- оглавление;
- хлебные крошки;
- навигация по страницам.

Семантика `<nav>` сообщает, что ссылки внутри образуют навигационную область.

---

### 10. Нужно ли помещать в `<nav>` абсолютно все ссылки страницы?

Нет.

`<nav>` предназначен для **основных или значимых навигационных групп ссылок**, а не для каждой отдельной ссылки.

Например:

```html
<p>
  Подробнее можно прочитать
  <a href="/article">в этой статье</a>.
</p>
```

Такую ссылку не нужно помещать в `<nav>`.

`<nav>` имеет смысл использовать, когда набор ссылок выполняет именно навигационную функцию.

Например:

```html
<nav>
  <a href="/">Главная</a>
  <a href="/blog">Блог</a>
  <a href="/contacts">Контакты</a>
</nav>
```

---

### 11. Чем `<section>` отличается от `<div>`?

`<section>` представляет **тематически связанную часть документа**.

Например:

```html
<section>
  <h2>Преимущества</h2>
  ...
</section>
```

Обычно `<section>` имеет собственную тему, которая может быть выражена заголовком.

`<div>` — нейтральный контейнер без семантического значения:

```html
<div class="wrapper">
  ...
</div>
```

Главное различие:

```text
<section> → смысловой тематический раздел
<div>     → технический контейнер
```

---

### 12. Когда стоит использовать `<section>`, а когда `<div>`?

`<section>` используют, когда содержимое образует **отдельный тематический раздел документа**.

Например:

```html
<section>
  <h2>Отзывы</h2>
  ...
</section>
```

Здесь блок имеет собственную тему — отзывы.

`<div>` используют, когда контейнер нужен только для:

- стилизации;
- layout;
- группировки элементов;
- JavaScript;
- технической структуры.

Например:

```html
<div class="cards-grid">
  ...
</div>
```

У такого контейнера нет отдельного смысла в структуре документа.

Практический вопрос:

> Есть ли у этой части страницы самостоятельная тема?

Если да — возможно, подходит `<section>`.

Если нет и контейнер нужен только технически — вероятнее всего, `<div>`.

---

### 13. Для чего используется `<article>`?

`<article>` представляет **самостоятельный, законченный фрагмент содержимого**, который имеет смысл независимо от остальной страницы.

Например:

```html
<article>
  <h2>Как работает Event Loop</h2>

  <p>...</p>
</article>
```

Типичные примеры:

- статья;
- пост в блоге;
- новость;
- комментарий;
- карточка публикации;
- сообщение на форуме.

Ключевая идея — содержимое `<article>` должно быть достаточно самостоятельным, чтобы его можно было рассматривать или распространять отдельно.

---

### 14. Чем `<article>` отличается от `<section>`?

Оба элемента создают смысловые части документа, но имеют разное назначение.

`<article>` используется для **самостоятельного контента**:

```html
<article>
  <h2>Новость</h2>
  ...
</article>
```

`<section>` используется для **тематического раздела**:

```html
<section>
  <h2>Последние новости</h2>

  <article>...</article>
  <article>...</article>
</section>
```

Главное различие:

```text
<article> → самостоятельный материал
<section> → тематическая часть документа
```

#### Короче:

`<article>` обозначает самостоятельный материал.

`<section>` — тематический раздел документа, который не обязан иметь смысл отдельно от окружающего контента.

---

### 15. Может ли `<article>` содержать `<section>` и наоборот?

Да.

Эти элементы могут быть вложены друг в друга, если это соответствует смысловой структуре документа.

Например, `<article>` может содержать несколько тематических разделов:

```html
<article>
  <h1>HTML</h1>

  <section>
    <h2>История</h2>
    ...
  </section>

  <section>
    <h2>Семантика</h2>
    ...
  </section>
</article>
```

И наоборот, `<section>` может содержать несколько самостоятельных материалов:

```html
<section>
  <h2>Последние статьи</h2>

  <article>
    ...
  </article>

  <article>
    ...
  </article>
</section>
```

Главный критерий — семантика содержимого, а не формальное правило вложенности.

---

### 16. Для чего используется `<aside>`?

`<aside>` представляет содержимое, которое **косвенно связано с основным содержимым**, но не является его центральной частью.

Например:

```html
<aside>
  <h2>Читайте также</h2>
  ...
</aside>
```

Это может быть:

- боковая колонка;
- связанные ссылки;
- дополнительная информация;
- рекламный блок;
- биография автора;
- пояснение;
- примечание.

Смысл `<aside>` зависит от контекста.

Если он находится внутри `<article>`, дополнительный контент обычно относится к статье.

Если `<aside>` находится на уровне страницы, он может относиться к документу в целом.

---

### 17. Как правильно выбирать между `<main>`, `<section>`, `<article>`, `<aside>` и `<div>`?

Выбор определяется **ролью содержимого**.

### `<main>`

Используется для основного содержимого страницы:

```text
главная тема документа → <main>
```

### `<article>`

Используется для самостоятельного материала:

```text
самостоятельная публикация → <article>
```

### `<section>`

Используется для тематического раздела:

```text
часть документа с отдельной темой → <section>
```

### `<aside>`

Используется для дополнительного содержимого:

```text
связанный, но второстепенный контент → <aside>
```

### `<div>`

Используется, если специальной семантики нет:

```text
техническая группировка → <div>
```

Например:

```html
<main>
  <section>
    <h2>Последние статьи</h2>

    <div class="articles-grid">
      <article>
        ...
      </article>

      <article>
        ...
      </article>
    </div>
  </section>

  <aside>
    ...
  </aside>
</main>
```

Здесь каждый элемент выполняет отдельную смысловую или техническую роль.

#### Короче:

Нужно выбирать элемент по смыслу:

```text
основной контент       → main
самостоятельный материал → article
тематический раздел    → section
дополнительный контент → aside
нейтральный контейнер  → div
```

---

### 18. Почему семантическая разметка важна для accessibility?

Семантическая разметка помогает вспомогательным технологиям понимать **структуру и назначение частей документа**.

Например:

```html
<nav>
```

может быть распознан как навигационная область,

```html
<main>
```

— как основное содержимое,

```html
<button>
```

— как кнопка.

Многие семантические элементы создают соответствующие accessibility semantics без необходимости добавлять их вручную.

Например:

```html
<button>Отправить</button>
```

уже имеет семантику кнопки.

В то время как:

```html
<div>Отправить</div>
```

не сообщает вспомогательным технологиям, что элемент является интерактивным.

Семантическая структура позволяет пользователям скринридеров:

- быстрее ориентироваться по странице;
- переходить между landmarks;
- находить заголовки;
- понимать назначение элементов интерфейса.

---

### 19. Как семантическая разметка может влиять на SEO?

Семантическая разметка помогает поисковым системам лучше понимать **структуру и смысл содержимого страницы**.

Например:

```html
<article>
```

может обозначать самостоятельную публикацию,

```html
<nav>
```

— навигационную область,

```html
<h1>
```

и другие заголовки — иерархию контента.

Однако семантические элементы сами по себе не являются гарантией более высокой позиции в поисковой выдаче.

SEO зависит от большого количества факторов:

- качества контента;
- соответствия запросу;
- структуры страницы;
- доступности;
- производительности;
- ссылок;
- технического состояния сайта;
- множества других сигналов.

Поэтому корректнее говорить, что семантическая разметка **помогает машинам интерпретировать структуру документа**, а не автоматически «повышает SEO».

---

### 20. Влияет ли использование семантических тегов на специфичность CSS-селекторов?

Нет, сама **семантика элемента не увеличивает специфичность CSS**.

Специфичность зависит от типа селектора.

Например:

```css
section {
  padding: 20px;
}
```

и:

```css
div {
  padding: 20px;
}
```

имеют одинаковую специфичность, потому что оба являются селекторами типа.

Их специфичность:

```text
0-0-1
```

Селектор класса:

```css
.section {
  padding: 20px;
}
```

имеет более высокую специфичность:

```text
0-1-0
```

А `id`:

```css
#section {
  padding: 20px;
}
```

имеет ещё более высокую:

```text
1-0-0
```

Поэтому выбор между:

```html
<section>
```

и:

```html
<div>
```

должен основываться на семантике HTML, а не на CSS specificity.
