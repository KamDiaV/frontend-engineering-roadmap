## VII. Формы

### 1. Как работает HTML-форма?

HTML-форма позволяет пользователю ввести или выбрать данные и отправить их для обработки.

Форма создаётся с помощью элемента `<form>`, внутри которого размещаются элементы управления: `<input>`, `<textarea>`, `<select>`, `<button>` и другие.

Например:

```html
<form action="/submit" method="post">
  <p>
    <label for="name">Введите имя:</label>
    <input type="text" name="name" id="name" required>
  </p>

  <p>
    <label for="email">Введите email:</label>
    <input type="email" name="email" id="email" required>
  </p>

  <button type="submit">Отправить</button>
</form>
```

Пользователь заполняет поля и нажимает кнопку отправки. После этого браузер собирает данные элементов формы и отправляет их в соответствии с настройками `<form>`.

За отправку формы в основном отвечают два атрибута:

- `action` — указывает URL, куда будут отправлены данные; 
- `method` — определяет HTTP-метод отправки данных, обычно `GET` или `POST`. 

При отправке учитываются элементы управления формой, имеющие атрибут `name`. Значение `name` используется как имя параметра, а введённое пользователем значение — как его значение.

Например:

```html
<input type="text" name="name" value="Diana">
```

может быть отправлено как пара:

```text
name=Diana
```

Перед отправкой браузер также может выполнить встроенную HTML-валидацию, например для полей с `required`, `type="email"`, `minlength` и другими ограничениями.

### 2. Для чего используется `<form>`?

Элемент `<form>` используется для создания раздела документа, содержащего интерактивные элементы управления, с помощью которых пользователь может вводить и отправлять данные.

Формы используются, например, для:

- регистрации и авторизации; 
- отправки сообщений и форм обратной связи; 
- поиска; 
- оформления заказов; 
- заполнения анкет; 
- выбора параметров и настроек. 

Внутри `<form>` могут находиться различные элементы управления:

```html
<input>
<textarea>
<select>
<button>
```

Таким образом, `<form>` объединяет элементы управления, связанные с одной задачей, и определяет, как и куда должны быть отправлены введённые пользователем данные.

### 3. Чем отличаются GET и POST в атрибуте `method` формы?

Атрибут `method` определяет **HTTP-метод, который браузер использует для отправки формы**.

Основные значения — `GET` и `POST`.

#### GET

`GET` используется для **получения данных с сервера**.

При отправке формы методом `GET` данные формы добавляются к URL из атрибута `action` после символа `?` и отправляются на сервер как часть URL.

Например:

```html
<form action="/search" method="get">
  <input type="text" name="query" value="html">
  <button type="submit">Найти</button>
</form>
```

После отправки URL может выглядеть так:

```text
/search?query=html
```

То есть данные формы видны в адресной строке.

`GET` следует использовать, когда отправка формы предназначена для **получения информации и не должна изменять состояние на сервере**.

Например:

- поиск;
- фильтрация;
- сортировка.

GET-запросы могут кэшироваться при соблюдении правил HTTP-кэширования.

#### POST

`POST` используется для **отправки данных на сервер для обработки**.

При отправке формы методом `POST` данные формы передаются в **теле HTTP-запроса**, а не добавляются к URL.

Например:

```html
<form action="/register" method="post">
  <input type="text" name="username" value="Diana">
  <button type="submit">Зарегистрироваться</button>
</form>
```

В этом случае `username=Diana` передаётся в теле запроса и не появляется в адресной строке.

`POST` используется, например, когда нужно:

- отправить данные формы на обработку;
- создать новый ресурс;
- добавить данные в базу данных;
- отправить сообщение;
- зарегистрировать пользователя;
- оформить заказ.

То есть главное различие заключается не только в том, **где передаются данные**, но и в назначении методов:

- `GET` — запросить или получить данные;
- `POST` — передать данные серверу для обработки, часто с созданием или изменением данных.

#### `formmethod`

Метод, указанный в `<form>`, можно переопределить для конкретной кнопки отправки с помощью атрибута `formmethod`.

Например:

```html
<form action="/example" method="get">
  <input type="text" name="query">

  <button type="submit">Отправить GET</button>
  <button type="submit" formmethod="post">Отправить POST</button>
</form>
```

Первая кнопка отправит форму методом `GET`, а вторая — методом `POST`.

#### Коротко

| `GET` | `POST` |
| --- | --- |
| Используется для получения данных | Используется для отправки данных на обработку |
| Данные формы добавляются к URL | Данные формы передаются в теле запроса |
| Данные видны в адресной строке | Данные не отображаются в URL |
| Обычно не должен изменять состояние сервера | Может создавать или изменять данные |
| Может кэшироваться | Обычно не кэшируется без специальных указаний |

### 4. Для чего нужен атрибут `action`?

Атрибут `action` элемента `<form>` указывает **URL, куда будут отправлены данные формы при её отправке**.

Например:

```html
<form action="/submit" method="post">
  <input type="text" name="username">
  <button type="submit">Отправить</button>
</form>
```

После отправки формы браузер отправит данные по адресу:

```text
/submit
```

В качестве значения `action` можно использовать относительный или абсолютный URL.

Относительный URL:

```html
<form action="/submit">
```

Абсолютный URL:

```html
<form action="https://example.com/submit">
```

То, каким HTTP-методом будут отправлены данные, определяется отдельно с помощью атрибута `method`:

```html
<form action="/submit" method="post">
```

Здесь:

- `action="/submit"` — определяет, **куда** отправить данные;
- `method="post"` — определяет, **каким HTTP-методом** их отправить.

Если атрибут `action` не указан, данные формы отправляются на **URL текущей страницы**.

Например:

```html
<form method="get">
  <input type="text" name="query">
  <button type="submit">Отправить</button>
</form>
```

Если такая форма находится на странице:

```text
https://example.com/search
```

то данные будут отправлены на эту же страницу.

#### Синтаксис

```html
<form action="URL">
  ...
</form>
```

#### Короче:

Атрибут `action` элемента `<form>` определяет URL, куда браузер отправит данные формы после её отправки.

Он может содержать относительный или абсолютный URL. Если `action` не указан, данные отправляются на URL текущей страницы.

### 5. Для чего нужен атрибут `name` у элементов формы?

У <form> атрибут name задаёт имя формы, которое, например, позволяет обращаться к ней через document.forms.

Атрибут `name` задаёт **имя элемента управления формы**, под которым его значение передаётся при отправке формы.

Например:

```html
<form action="/submit" method="get">
  <input type="text" name="username" value="Diana">
  <button type="submit">Отправить</button>
</form>
```

При отправке формы браузер формирует данные в виде пары **имя — значение**:

```text
username=Diana
```

Здесь:

- `username` — значение атрибута `name`;
- `Diana` — значение элемента формы.

Если элементов несколько:

```html
<input type="text" name="username" value="Diana">
<input type="email" name="email" value="diana@example.com">
```

данные будут содержать несколько пар:

```text
username=Diana
email=diana@example.com
```

Если у элемента формы отсутствует `name`, его значение обычно **не включается в данные при отправке формы**.

Например:

```html
<input type="text" value="Diana">
```

Значение этого поля не будет отправлено вместе с формой, потому что у него нет атрибута `name`.

`name` также используется для объединения радиокнопок в одну группу:

```html
<input type="radio" name="delivery" value="courier">
<input type="radio" name="delivery" value="pickup">
```

Поскольку у радиокнопок одинаковый `name`, пользователь может выбрать только один вариант из этой группы.

#### Короче:

Атрибут `name` задаёт имя элемента формы, под которым его значение передаётся при отправке формы.
Данные формы передаются в виде пар `name=value`. Если у элемента управления нет `name`, его значение обычно не отправляется вместе с формой.

### 6. Почему `<label>` важен для accessibility?

Элемент `<label>` задаёт **текстовую подпись для элемента управления формы**, например `<input>`, `<select>` или `<textarea>`.

Он важен для доступности, потому что помогает пользователям понять, **какие данные нужно ввести или выбрать в конкретном поле**.

Например:

```html
<label for="email">Email:</label>
<input type="email" id="email" name="email">
```

Атрибут `for` у `<label>` связывает подпись с элементом, у которого значение `id` совпадает со значением `for`:

```text
for="email" → id="email"
```

Такая связь особенно важна для пользователей скринридеров. Когда пользователь переходит к полю формы, скринридер может сообщить связанную с ним подпись.

Кроме того, при клике на `<label>` браузер передаёт взаимодействие связанному элементу управления. Например, клик по подписи текстового поля устанавливает на нём фокус, а клик по подписи чекбокса или радиокнопки переключает его состояние.

Это увеличивает область, по которой можно нажать, что особенно полезно для пользователей с нарушениями моторики и при работе с сенсорными экранами.

Связать `<label>` с элементом можно двумя основными способами.

**Явно — через `for` и `id`:**

```html
<label for="name">Имя:</label>
<input type="text" id="name" name="name">
```

**Неявно — поместив элемент управления внутрь `<label>`:**

```html
<label>
  Имя:
  <input type="text" name="name">
</label>
```

#### Короче:

`<label>` важен для accessibility, потому что программно связывает текстовую подпись с элементом управления формы. Благодаря этому скринридеры могут сообщить пользователю назначение поля.

Кроме того, по `<label>` можно кликнуть, чтобы установить фокус или изменить состояние связанного элемента, что увеличивает область взаимодействия и делает форму удобнее.

### 7. Какие основные значения `type` у `<input>` вы знаете?

Атрибут `type` элемента `<input>` определяет **тип элемента управления и то, какие данные пользователь может вводить или выбирать**.

Основные значения:

#### Текстовые данные

- `text` — обычное однострочное текстовое поле;
- `password` — поле для ввода пароля, в котором символы визуально скрываются;
- `email` — поле для ввода email-адреса;
- `tel` — поле для ввода номера телефона;
- `url` — поле для ввода URL;
- `search` — поле для поискового запроса.

```html
<input type="text">
<input type="password">
<input type="email">
<input type="tel">
<input type="url">
<input type="search">
```

#### Числа и диапазоны

- `number` — ввод числового значения;
- `range` — выбор значения из диапазона с помощью ползунка.

```html
<input type="number">
<input type="range" min="0" max="100">
```

#### Дата и время

- `date` — выбор даты;
- `time` — выбор времени;
- `datetime-local` — выбор локальной даты и времени;
- `month` — выбор месяца и года;
- `week` — выбор недели.

```html
<input type="date">
<input type="time">
<input type="datetime-local">
<input type="month">
<input type="week">
```

#### Выбор вариантов

- `checkbox` — флажок, позволяет включить или выключить определённую опцию;
- `radio` — переключатель для выбора одного варианта из группы.

```html
<input type="checkbox">

<input type="radio" name="delivery" value="courier">
<input type="radio" name="delivery" value="pickup">
```

#### Файлы и цвет

- `file` — позволяет выбрать файл для загрузки;
- `color` — позволяет выбрать цвет.

```html
<input type="file">
<input type="color">
```

#### Кнопки

- `submit` — отправляет форму;
- `reset` — сбрасывает значения элементов формы;
- `button` — обычная кнопка без встроенного действия;
- `image` — графическая кнопка отправки формы.

```html
<input type="submit" value="Отправить">
<input type="reset" value="Сбросить">
<input type="button" value="Кнопка">
<input type="image" src="submit.png" alt="Отправить">
```

#### Скрытое поле

- `hidden` — скрытое поле, которое не отображается пользователю, но его значение может быть отправлено вместе с формой.

```html
<input type="hidden" name="userId" value="123">
```

Если атрибут `type` не указан или указано неизвестное значение, используется `type="text"`.

#### Короче:

Основные значения `type` у `<input>`: `text`, `password`, `email`, `tel`, `url`, `search`, `number`, `range`, `date`, `time`, `datetime-local`, `checkbox`, `radio`, `file`, `color`, `submit`, `reset`, `button` и `hidden`.

Тип `input` определяет назначение элемента управления, допустимые данные и в некоторых случаях встроенную валидацию и интерфейс ввода.

### 8. Чем `type="text"`, `email`, `password`, `number`, `tel` и `search` отличаются друг от друга?

Эти значения атрибута `type` создают однострочные поля ввода, но отличаются назначением, допустимыми данными, встроенной валидацией и поведением браузера.

#### `type="text"`

Обычное однострочное текстовое поле.

```html
<input type="text" name="username">
```

Используется для ввода текста, например имени, фамилии или названия.

Сам по себе `type="text"` не проверяет формат введённых данных.

---

#### `type="email"`

Поле для ввода email-адреса.

```html
<input type="email" name="email">
```

Браузер выполняет встроенную проверку формата email при валидации формы.

Например:

```text
user@example.com
```

На мобильных устройствах браузер также может показать клавиатуру, адаптированную для ввода email.

---

#### `type="password"`

Поле для ввода пароля.

```html
<input type="password" name="password">
```

Введённые символы визуально скрываются.

При этом `type="password"` **не шифрует данные**. Для безопасной передачи пароля между браузером и сервером используется HTTPS.

---

#### `type="number"`

Поле для ввода числового значения.

```html
<input type="number" name="age" min="18" max="100">
```

Поддерживает дополнительные атрибуты, например:

- `min` — минимальное значение;
- `max` — максимальное значение;
- `step` — допустимый шаг изменения значения.

Браузер может отображать элементы управления для увеличения и уменьшения числа и проверять введённое значение.

---

#### `type="tel"`

Поле для ввода номера телефона.

```html
<input type="tel" name="phone">
```

В отличие от `email`, браузер **не выполняет встроенную проверку формата номера телефона**, потому что телефонные номера имеют разные форматы в разных странах.

На мобильных устройствах обычно открывается клавиатура, предназначенная для ввода телефонного номера.

При необходимости формат можно ограничить отдельно, например с помощью атрибута `pattern`.

---

#### `type="search"`

Поле для ввода поискового запроса.

```html
<input type="search" name="query">
```

По поведению оно похоже на `type="text"`, но семантически обозначает поле поиска.

Браузер может отображать его немного иначе и предоставлять дополнительные элементы интерфейса, например кнопку очистки введённого текста.

---

#### Короче:

| `type` | Назначение | Особенность |
| --- | --- | --- |
| `text` | Обычный текст | Нет встроенной проверки формата |
| `email` | Email-адрес | Есть встроенная проверка формата |
| `password` | Пароль | Введённые символы визуально скрываются |
| `number` | Числовое значение | Поддерживает `min`, `max`, `step` |
| `tel` | Номер телефона | Обычно вызывает телефонную клавиатуру, но не проверяет формат номера |
| `search` | Поисковый запрос | Семантически предназначен для поиска, может иметь специальный интерфейс |

### 9. Чем `placeholder` отличается от `<label>` и почему `placeholder` не должен заменять `label`?

`<label>` и `placeholder` выполняют разные задачи.

**`<label>`** — это постоянная подпись элемента управления формы, которая объясняет пользователю назначение поля.

```html
<label for="email">Email:</label>
<input type="email" id="email" name="email">
```

**`placeholder`** — это текст-подсказка, который отображается внутри пустого поля.

```html
<label for="email">Email:</label>
<input
  type="email"
  id="email"
  name="email"
  placeholder="name@example.com"
>
```

В этом примере:

- `Email:` — объясняет, **что нужно ввести**;
- `name@example.com` — показывает **пример ожидаемого значения**.

`placeholder` не должен заменять `<label>` по нескольким причинам:

- текст `placeholder` исчезает, когда пользователь начинает вводить данные;
- пользователь может забыть назначение поля после начала ввода;
- `placeholder` обычно имеет менее заметное визуальное оформление;
- `<label>` создаёт программную связь с элементом управления, что важно для доступности и работы вспомогательных технологий;
- при клике на связанный `<label>` фокус переходит на соответствующий элемент управления.

Неправильно:

```html
<input
  type="email"
  name="email"
  placeholder="Email"
>
```

Лучше:

```html
<label for="email">Email:</label>
<input
  type="email"
  id="email"
  name="email"
  placeholder="name@example.com"
>
```

#### Короче:

`<label>` описывает назначение поля и создаёт программную связь с элементом управления, а `placeholder` — это дополнительная подсказка внутри пустого поля.

`placeholder` не должен заменять `<label>`, потому что он исчезает при вводе данных и не является полноценной заменой доступной подписи элемента управления.

### 10. Чем `disabled` отличается от `readonly`?

Оба атрибута ограничивают возможность изменения значения элемента формы, но работают по-разному.

#### `disabled`

Булев атрибут `disabled` делает элемент управления **неактивным**.

```html
<input type="text" name="username" value="Diana" disabled>
```

Пользователь не может изменить значение такого элемента или взаимодействовать с ним.

Элемент с `disabled`:

- нельзя редактировать;
- обычно нельзя сфокусировать;
- его значение **не отправляется вместе с формой**;
- не участвует во встроенной валидации формы.

---

#### `readonly`

Булев атрибут `readonly` делает значение элемента **доступным только для чтения**.

```html
<input type="text" name="username" value="Diana" readonly>
```

Пользователь не может изменить значение, но элемент остаётся частью формы.

Элемент с `readonly`:

- нельзя редактировать;
- можно сфокусировать;
- его значение **отправляется вместе с формой**;
- не участвует во встроенной проверке ограничений.

`readonly` применяется не ко всем элементам формы. В частности, он используется с `<textarea>` и некоторыми типами `<input>`, например `text`, `email`, `password`, `search`, `tel`, `url`, `number`, `date` и `time`.

---

#### Главное отличие

```text
disabled → элемент отключён и его значение не отправляется
readonly → значение нельзя изменить, но оно отправляется
```

| `disabled` | `readonly` |
| --- | --- |
| Элемент отключён | Элемент доступен только для чтения |
| Нельзя редактировать | Нельзя редактировать |
| Обычно нельзя сфокусировать | Можно сфокусировать |
| Значение не отправляется | Значение отправляется |
| Не участвует в валидации | Не участвует в валидации |

#### Короче:

`disabled` полностью отключает элемент управления: пользователь не может с ним взаимодействовать, а его значение не отправляется вместе с формой.

`readonly` запрещает пользователю изменять значение, но элемент можно сфокусировать, а его значение отправляется вместе с формой.

### 11. Что делают `required`, `min`, `max`, `minlength`, `maxlength` и `pattern`?

Эти атрибуты позволяют задавать **ограничения для значений элементов формы** и используются для встроенной HTML-валидации.

#### `required`

Булев атрибут `required` указывает, что поле **обязательно должно быть заполнено** перед отправкой формы.

```html
<input type="email" name="email" required>
```

Если пользователь оставит обязательное поле пустым, браузер не позволит отправить форму и сообщит об ошибке валидации.

---

#### `min`

Атрибут `min` задаёт **минимально допустимое значение**.

Например:

```html
<input type="number" name="age" min="18">
```

Значение должно быть не меньше `18`.

`min` используется с типами `<input>`, которые работают с числовыми значениями, датами и временем.

---

#### `max`

Атрибут `max` задаёт **максимально допустимое значение**.

```html
<input type="number" name="age" max="100">
```

Значение должно быть не больше `100`.

`min` и `max` можно использовать вместе:

```html
<input type="number" name="age" min="18" max="100">
```

---

#### `minlength`

Атрибут `minlength` задаёт **минимальное количество символов**, которое пользователь должен ввести.

```html
<input type="text" name="username" minlength="3">
```

В этом случае значение должно содержать минимум 3 символа.

---

#### `maxlength`

Атрибут `maxlength` задаёт **максимальное количество символов**, которое можно ввести.

```html
<input type="text" name="username" maxlength="20">
```

В этом случае пользователь сможет ввести не более 20 символов.

`minlength` и `maxlength` можно использовать вместе:

```html
<input
  type="text"
  name="username"
  minlength="3"
  maxlength="20"
>
```

---

#### `pattern`

Атрибут `pattern` задаёт **шаблон в виде регулярного выражения**, которому должно соответствовать введённое значение.

Например:

```html
<input
  type="text"
  name="code"
  pattern="[0-9]{4}"
>
```

Такое поле ожидает четыре цифры.

Например:

```text
1234
```

соответствует шаблону, а:

```text
123
abcd
```

не соответствует.

---

#### Коротко

| Атрибут | Что делает |
| --- | --- |
| `required` | Делает поле обязательным |
| `min` | Задаёт минимально допустимое значение |
| `max` | Задаёт максимально допустимое значение |
| `minlength` | Задаёт минимальное количество символов |
| `maxlength` | Задаёт максимальное количество символов |
| `pattern` | Задаёт шаблон, которому должно соответствовать значение |

#### Короче:

`required`, `min`, `max`, `minlength`, `maxlength` и `pattern` задают ограничения для значений элементов формы и используются встроенной HTML-валидацией.

`required` делает поле обязательным, `min` и `max` задают диапазон допустимых значений, `minlength` и `maxlength` ограничивают длину текста, а `pattern` задаёт шаблон в виде регулярного выражения, которому должно соответствовать введённое значение.

### 12. Что такое встроенная HTML-валидация формы?

**Встроенная HTML-валидация** — это механизм браузера, который позволяет проверять данные формы перед её отправкой без написания JavaScript.

Ограничения задаются с помощью HTML-атрибутов и типов элементов формы.

Например:

```html
<form>
  <label for="email">Email:</label>
  <input
    type="email"
    id="email"
    name="email"
    required
  >

  <button type="submit">Отправить</button>
</form>
```

Здесь браузер проверит:

- заполнено ли поле благодаря `required`;
- соответствует ли введённое значение формату email благодаря `type="email"`.

Для встроенной валидации можно использовать:

- `required` — обязательное поле;
- `min` и `max` — минимальное и максимальное значение;
- `minlength` и `maxlength` — минимальная и максимальная длина;
- `pattern` — соответствие заданному регулярному выражению;
- определённые значения `type`, например `email` и `url`.

Например:

```html
<input
  type="text"
  name="username"
  required
  minlength="3"
  maxlength="20"
>
```

Если данные не соответствуют заданным ограничениям, браузер обычно не отправляет форму и показывает пользователю сообщение об ошибке.

Для стилизации элементов в зависимости от результата валидации можно использовать CSS-псевдоклассы:

```css
input:valid {
  /* стили для валидного значения */
}

input:invalid {
  /* стили для невалидного значения */
}
```

Встроенная HTML-валидация выполняется на стороне клиента и **не заменяет серверную валидацию**, поскольку клиентскую проверку можно обойти. Сервер должен самостоятельно проверять полученные данные.

#### Короче:

Встроенная HTML-валидация — это механизм браузера для проверки данных формы перед отправкой без необходимости писать JavaScript.

Правила проверки задаются с помощью атрибутов `required`, `min`, `max`, `minlength`, `maxlength`, `pattern` и некоторых значений `type`, например `email` и `url`.

Если данные не соответствуют ограничениям, браузер может заблокировать отправку формы и показать сообщение об ошибке. При этом клиентская валидация не заменяет обязательную проверку данных на сервере.

### 13. Чем `<button type="button">` отличается от `<button type="submit">`?

Главное отличие заключается в поведении кнопки внутри формы.

#### `type="submit"`

`<button type="submit">` — это кнопка **отправки формы**.

При нажатии браузер запускает валидацию формы и, если данные валидны, отправляет форму в соответствии с атрибутами `action` и `method`.

```html
<form action="/submit" method="post">
  <input type="text" name="username" required>

  <button type="submit">Отправить</button>
</form>
```

Если обязательное поле не заполнено, встроенная HTML-валидация может остановить отправку формы.

Для `<button>` значение `submit` используется **по умолчанию**, если атрибут `type` не указан.

То есть:

```html
<button>Отправить</button>
```

внутри формы обычно работает как:

```html
<button type="submit">Отправить</button>
```

Это важно, потому что кнопка без явно указанного `type` может **неожиданно отправить форму**.

Например:

```html
<form>
  <input type="text" name="username">

  <button>Открыть подсказку</button>
</form>
```

Если кнопка предназначена только для открытия подсказки, но `type` не указан, нажатие на неё может привести к отправке формы.

Поэтому для кнопок, которые не должны отправлять форму, следует явно указывать:

```html
<button type="button">Открыть подсказку</button>
```

А для кнопки отправки:

```html
<button type="submit">Отправить</button>
```

---

#### `type="button"`

`<button type="button">` — обычная кнопка, которая **сама по себе не отправляет форму и не имеет стандартного действия**.

```html
<button type="button">Открыть меню</button>
```

Чтобы такая кнопка выполняла какое-либо действие, обычно добавляется JavaScript.

Например:

```html
<button type="button" id="button">Показать сообщение</button>
```

```js
const button = document.querySelector('#button');

button.addEventListener('click', () => {
  console.log('Кнопка нажата');
});
```

`type="button"` используют для действий, которые не должны отправлять форму, например открытия модального окна, переключения интерфейса или выполнения другого действия через JavaScript.

---

#### Короче:

| `type="submit"` | `type="button"` |
| --- | --- |
| Отправляет форму | Не отправляет форму |
| Запускает валидацию формы | Сам по себе не запускает отправку формы |
| Имеет стандартное действие | Не имеет стандартного действия |
| `submit` — значение по умолчанию для `<button>` | Поведение обычно задаётся через JavaScript |

`<button type="submit">` предназначен для отправки формы. При нажатии запускается валидация и, если данные валидны, форма отправляется.

`<button type="button">` — обычная кнопка без встроенного действия. Она не отправляет форму и обычно используется для действий, поведение которых задаётся с помощью JavaScript.

Если у `<button>` внутри формы не указать `type`, по умолчанию он работает как `type="submit"`.

### 14. Для чего используются `<fieldset>` и `<legend>`?

Элементы `<fieldset>` и `<legend>` используются для **группировки связанных элементов формы и добавления общей подписи для этой группы**.

#### `<fieldset>`

Элемент `<fieldset>` объединяет логически связанные элементы управления формы в одну группу.

Например:

```html
<fieldset>
  <legend>Способ доставки</legend>

  <label>
    <input type="radio" name="delivery" value="courier">
    Курьер
  </label>

  <label>
    <input type="radio" name="delivery" value="pickup">
    Самовывоз
  </label>
</fieldset>
```

В этом примере две радиокнопки относятся к одной группе — выбору способа доставки.

`<fieldset>` особенно полезен для групп:

- радиокнопок;
- чекбоксов;
- связанных полей формы, например контактных или платёжных данных.

---

#### `<legend>`

Элемент `<legend>` задаёт **подпись или заголовок группы**, созданной с помощью `<fieldset>`.

```html
<fieldset>
  <legend>Контактные данные</legend>

  <label for="name">Имя:</label>
  <input type="text" id="name" name="name">

  <label for="email">Email:</label>
  <input type="email" id="email" name="email">
</fieldset>
```

Здесь `<fieldset>` объединяет поля, а `<legend>` сообщает, что вся группа относится к контактным данным.

---

#### Accessibility

`<fieldset>` и `<legend>` важны для доступности, потому что создают **семантическую связь между группой элементов управления и её общей подписью**.

Это особенно важно для радиокнопок и чекбоксов, где отдельные `<label>` описывают каждый вариант, а `<legend>` объясняет назначение всей группы.

Например:

```html
<fieldset>
  <legend>Выберите размер</legend>

  <label>
    <input type="radio" name="size" value="s">
    S
  </label>

  <label>
    <input type="radio" name="size" value="m">
    M
  </label>
</fieldset>
```

Здесь:

- `<legend>` — «Выберите размер» — описывает всю группу;
- `<label>` — «S» и «M» — описывают отдельные элементы управления.

#### Короче:

`<fieldset>` используется для семантической группировки связанных элементов формы, а `<legend>` задаёт общую подпись этой группы.

Они особенно полезны для групп радиокнопок и чекбоксов и важны для accessibility, поскольку помогают вспомогательным технологиям понять связь между элементами формы и назначение всей группы.
