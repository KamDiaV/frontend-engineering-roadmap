# XI. Практические вопросы

### 1. Как бы вы семантически сверстали обычную страницу сайта: header, navigation, main content, sidebar и footer?

Для обычной страницы логично использовать семантические элементы:

```html
<body>
  <header>
    <a href="/">Логотип</a>

    <nav aria-label="Основная навигация">
      <ul>
        <li><a href="/">Главная</a></li>
        <li><a href="/catalog">Каталог</a></li>
        <li><a href="/contacts">Контакты</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <h1>Главная страница</h1>

    <section>
      <h2>Основной раздел</h2>
      <p>...</p>
    </section>

    <aside>
      <h2>Дополнительная информация</h2>
      <p>...</p>
    </aside>
  </main>

  <footer>
    <p>© 2026 Example</p>
  </footer>
</body>
```

Здесь:

- `<header>` — вводная часть страницы;
- `<nav>` — основная навигация;
- `<main>` — главное содержимое;
- `<aside>` — дополнительный контент;
- `<footer>` — завершающая часть страницы.

`<section>` внутри `<main>` используется только тогда, когда контент действительно образует самостоятельный тематический раздел.

Для технических контейнеров без семантической роли можно использовать `<div>`.

### 2. Какой элемент вы выберете для карточки новости — `<div>`, `<section>` или `<article>`? Почему?

Для карточки новости обычно лучше использовать `<article>`.

Например:

```html
<article class="news-card">
  <h2>
    <a href="/news/html">
      Новый HTML API
    </a>
  </h2>

  <p>
    Краткое описание новости.
  </p>
</article>
```

Причина в том, что новость является самостоятельным материалом, который имеет смысл отдельно от остальной страницы.

`<section>` лучше использовать для тематической группы:

```html
<section>
  <h2>Последние новости</h2>

  <article>...</article>
  <article>...</article>
</section>
```

`<div>` подходит, если контейнер нужен только для layout или стилизации и не имеет самостоятельного смысла.

### 3. Какой элемент использовать для кнопки «Добавить в корзину»?

Следует использовать `<button>`:

```html
<button type="button">
  Добавить в корзину
</button>
```

«Добавить в корзину» — это **действие**, а не переход на другой URL.

Поэтому `<a>` здесь семантически не подходит.

Если кнопка находится внутри формы и должна отправлять её, можно использовать:

```html
<button type="submit">
  Добавить в корзину
</button>
```

Если отправка формы не нужна:

```html
<button type="button">
  Добавить в корзину
</button>
```

### 4. Какой элемент использовать для ссылки «Перейти в каталог»?

Следует использовать `<a>`:

```html
<a href="/catalog">
  Перейти в каталог
</a>
```

Пользователь переходит на другой URL, поэтому это навигация.

Даже если ссылка визуально оформлена как кнопка:

```html
<a class="button" href="/catalog">
  Перейти в каталог
</a>
```

семантически она остаётся ссылкой.

### 5. Как сделать кликабельный элемент доступным с клавиатуры?

Лучший способ — использовать подходящий нативный интерактивный элемент.

Для действия:

```html
<button type="button">
  Открыть меню
</button>
```

Для навигации:

```html
<a href="/catalog">
  Каталог
</a>
```

Такие элементы уже поддерживают:

- фокус;
- `Tab`;
- клавиатурную активацию;
- семантику для вспомогательных технологий.

Не стоит делать:

```html
<div onclick="openMenu()">
  Открыть меню
</div>
```

Если по какой-то причине приходится создавать кастомный интерактивный элемент, необходимо вручную реализовать:

- правильную роль;
- фокусируемость;
- обработку клавиатуры;
- видимый focus state.

Например:

```html
<div
  role="button"
  tabindex="0"
>
  Открыть меню
</div>
```

Но даже после этого потребуется JavaScript для `Enter` и `Space`.

Поэтому предпочтителен нативный HTML.

### 6. Как правильно сверстать главное меню сайта?

Главное меню обычно размечают через `<nav>` и список ссылок.

Например:

```html
<nav aria-label="Основная навигация">
  <ul>
    <li>
      <a href="/">Главная</a>
    </li>

    <li>
      <a href="/catalog">Каталог</a>
    </li>

    <li>
      <a href="/about">О нас</a>
    </li>

    <li>
      <a href="/contacts">Контакты</a>
    </li>
  </ul>
</nav>
```

Почему здесь используется список:

- пункты меню образуют логическую группу;
- `<ul>` показывает, что элементы относятся к одному набору;
- `<nav>` обозначает навигационную область.

Если на странице несколько `<nav>`, им полезно дать различимые accessible names:

```html
<nav aria-label="Основная навигация">
  ...
</nav>

<nav aria-label="Навигация в подвале">
  ...
</nav>
```

### 7. Как правильно разметить breadcrumbs?

Breadcrumbs — это навигация, поэтому обычно используется `<nav>`.

Сам путь удобно представить упорядоченным списком `<ol>`, потому что порядок элементов имеет значение.

Например:

```html
<nav aria-label="Хлебные крошки">
  <ol>
    <li>
      <a href="/">Главная</a>
    </li>

    <li>
      <a href="/catalog">Каталог</a>
    </li>

    <li>
      Кольца
    </li>
  </ol>
</nav>
```

Для текущей страницы можно использовать `aria-current="page"`:

```html
<nav aria-label="Хлебные крошки">
  <ol>
    <li>
      <a href="/">Главная</a>
    </li>

    <li>
      <a href="/catalog">Каталог</a>
    </li>

    <li>
      <a
        href="/catalog/rings"
        aria-current="page"
      >
        Кольца
      </a>
    </li>
  </ol>
</nav>
```

Разделители вроде `/` или `›` лучше добавлять визуально через CSS, если они не несут самостоятельного смысла.

### 8. Как разметить форму поиска?

Для поиска используется обычная `<form>`.

Например:

```html
<form action="/search" method="get">
  <label for="search">
    Поиск
  </label>

  <input
    id="search"
    type="search"
    name="query"
  >

  <button type="submit">
    Найти
  </button>
</form>
```

Здесь:

- `<form>` объединяет элементы поиска;
- `<label>` задаёт подпись поля;
- `type="search"` семантически обозначает поисковый запрос;
- `name="query"` задаёт имя отправляемого параметра;
- `<button type="submit">` отправляет форму.

Если нужно явно обозначить область поиска, в современном HTML можно использовать `<search>`:

```html
<search>
  <form action="/search" method="get">
    <label for="site-search">
      Поиск
    </label>

    <input
      id="site-search"
      type="search"
      name="query"
    >

    <button type="submit">
      Найти
    </button>
  </form>
</search>
```

### 9. Как разметить группу radio-кнопок?

Логически связанную группу radio-кнопок лучше объединить с помощью `<fieldset>` и дать ей общее название через `<legend>`.

Например:

```html
<fieldset>
  <legend>
    Выберите способ доставки
  </legend>

  <label>
    <input
      type="radio"
      name="delivery"
      value="courier"
    >
    Курьер
  </label>

  <label>
    <input
      type="radio"
      name="delivery"
      value="pickup"
    >
    Самовывоз
  </label>
</fieldset>
```

Все radio-кнопки одной группы должны иметь одинаковый `name`:

```text
name="delivery"
```

Именно общий `name` объединяет их в группу, в которой можно выбрать один вариант.

`<fieldset>` и `<legend>` дополнительно описывают смысл всей группы для пользователя и вспомогательных технологий.

### 10. Как сделать изображение декоративным для screen reader?

У декоративного `<img>` следует использовать пустой `alt`:

```html
<img
  src="./images/decor.svg"
  alt=""
>
```

Это сообщает вспомогательным технологиям, что изображение не несёт самостоятельного смысла и его можно пропустить.

Не следует просто удалять `alt`:

```html
<img src="./images/decor.svg">
```

Пустой `alt` и отсутствующий `alt` имеют разный смысл.

Если декоративное изображение можно реализовать через CSS, часто ещё лучше использовать background image:

```css
.card::before {
  background-image: url("./images/decor.svg");
}
```

Тогда оно вообще не становится частью содержимого HTML.

### 11. Как реализовать модальное окно с помощью нативного HTML?

Для нативного модального окна используется `<dialog>`.

HTML:

```html
<button
  type="button"
  id="open-dialog"
>
  Удалить товар
</button>

<dialog id="confirm-dialog">
  <h2>Удалить товар?</h2>

  <p>
    Это действие нельзя отменить.
  </p>

  <form method="dialog">
    <button value="cancel">
      Отмена
    </button>

    <button value="confirm">
      Удалить
    </button>
  </form>
</dialog>
```

JavaScript:

```js
const dialog =
  document.querySelector('#confirm-dialog');

const openButton =
  document.querySelector('#open-dialog');

openButton.addEventListener('click', () => {
  dialog.showModal();
});
```

`showModal()`:

- открывает dialog как модальный;
- помещает его в top layer;
- делает остальную страницу inert.

Фон можно оформить через:

```css
dialog::backdrop {
  background: rgb(0 0 0 / 0.5);
}
```

Форма:

```html
<form method="dialog">
```

позволяет закрыть dialog через submit без обычной отправки данных на сервер.

### 12. Как реализовать раскрывающийся FAQ без JavaScript?

Для простого FAQ можно использовать `<details>` и `<summary>`.

Например:

```html
<section>
  <h2>FAQ</h2>

  <details>
    <summary>
      Как оформить заказ?
    </summary>

    <p>
      Добавьте товар в корзину и перейдите к оформлению.
    </p>
  </details>

  <details>
    <summary>
      Сколько занимает доставка?
    </summary>

    <p>
      Обычно доставка занимает 2–3 рабочих дня.
    </p>
  </details>
</section>
```

`<summary>` — интерактивный заголовок раскрывающегося блока.

`<details>` управляет состоянием раскрытия.

Открытый блок получает атрибут:

```html
<details open>
```

Для базового FAQ JavaScript не требуется — браузер предоставляет поведение нативно.
