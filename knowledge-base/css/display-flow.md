# V. Display и поток документа

## 1. Что такое Normal Flow?

**Normal Flow (нормальный поток документа)** — базовый алгоритм CSS-разметки, по которому браузер располагает элементы на странице, если их положение не изменено специальными механизмами layout или позиционирования.

Проще говоря:

> Normal Flow — это то, как браузер располагает элементы по умолчанию.

Например:

```html
<h1>Title</h1>
<p>First paragraph</p>
<p>Second paragraph</p>
```

Без дополнительного CSS браузер расположит:

```text
Title

First paragraph

Second paragraph
```

Блочные элементы следуют друг за другом в **block direction**.

В обычном горизонтальном режиме письма (`writing-mode: horizontal-tb`) это означает:

```text
сверху
  ↓
вниз
```

А inline-содержимое располагается в **inline direction** — то есть в направлении текста.

Например:

```html
<p>
  Hello <strong>CSS</strong> world
</p>
```

Элементы внутри строки располагаются последовательно:

```text
Hello CSS world
→ → → → → →
```

### Block Flow

Блочные элементы в normal flow располагаются один за другим.

Например:

```html
<div>First</div>
<div>Second</div>
<div>Third</div>
```

В обычном горизонтальном writing mode:

```text
┌─────────────┐
│ First       │
└─────────────┘

┌─────────────┐
│ Second      │
└─────────────┘

┌─────────────┐
│ Third       │
└─────────────┘
```

### Inline Flow

Inline-содержимое располагается внутри строк.

Например:

```html
<p>
  Hello <span>beautiful</span> world
</p>
```

Получаем:

```text
Hello beautiful world
```

Если места в строке недостаточно, содержимое переносится на следующую строку.

### In-flow и Out-of-flow

Элемент считается **in-flow**, если он участвует в normal flow.

Из normal flow, в частности, выводятся:

- floated elements (`float`);
- абсолютно позиционированные элементы (`position: absolute`);
- фиксированно позиционированные элементы (`position: fixed`).

Например:

```css
.element {
  position: absolute;
}
```

Такой элемент больше не занимает обычное место в потоке документа.

При этом:

```css
position: relative;
```

и:

```css
position: sticky;
```

не удаляют элемент из normal flow: место элемента в потоке сохраняется.

## 2. Что делает свойство `display`?

`display` определяет, **как элемент ведёт себя в разметке и как располагаются его дети**.

Например:

```css
.element {
  display: block;
}
```

или:

```css
.element {
  display: flex;
}
```

или:

```css
.element {
  display: grid;
}
```

---

### Outer Display Type и Inner Display Type

В современной модели CSS `display` удобно рассматривать как комбинацию двух характеристик.

#### Outer Display Type

Определяет, как **сам элемент** участвует в layout относительно соседних элементов.

Основные варианты:

```text
block
inline
```

#### Inner Display Type

Определяет, как располагается **содержимое элемента**.

Например:

```text
flow
flex
grid
```

Можно представить:

```text
display

├── outer display type
│   └── как элемент ведёт себя среди соседей
│
└── inner display type
    └── как располагаются его дети
```

---

### Распространённые значения `display`

| Значение | Назначение |
|---|---|
| `block` | Создаёт блочное поведение |
| `inline` | Создаёт строчное поведение |
| `inline-block` | Располагается в строке, но позволяет задавать размеры как отдельному блоку |
| `flex` | Создаёт гибкую раскладку Flexbox |
| `inline-flex` | Создаёт Flexbox-контейнер, который сам располагается в строке |
| `grid` | Создаёт сеточную раскладку Grid |
| `inline-grid` | Создаёт Grid-контейнер, который сам располагается в строке |
| `flow-root` | Создаёт новый контекст блочного форматирования - BFC (Block Formatting Context)|
| `none` | Элемент и его содержимое не создают областей в раскладке |
| `contents` | Собственная область элемента исчезает, но его содержимое продолжает участвовать в раскладке |

Современный CSS также поддерживает запись из нескольких ключевых слов (multi-keyword syntax), например:

```css
display: block flow;
```

или:

```css
display: inline flex;
```

Однако традиционные значения:

```css
block
inline
inline-block
flex
grid
```

по-прежнему широко используются и полностью подходят для повседневной разработки.

## 3. Чем `block` отличается от `inline`?

`block` и `inline` — два фундаментальных варианта поведения элементов в нормальном потоке.

---

### `display: block`

При:

```css
.element {
  display: block;
}
```

элемент ведёт себя как блочный.

В горизонтальном writing mode следующий block-level элемент обычно начинается на новой строке.

HTML:

```html
<div>First</div>
<div>Second</div>
```

Визуально:

```text
First
Second
```

При:

```css
div {
  display: block;
}
```

блочный элемент с:

width: auto;

обычно занимает доступную ширину своего родительского контейнера.

Можно явно задавать:

```css
width
height
margin
padding
border
```

Например:

```css
.box {
  display: block;
  width: 300px;
  height: 100px;
}
```

---

### `display: inline`

Строчный элемент располагается внутри строки вместе с текстом и другими строчными элементами.

Например:

```html
<p>
  Hello <span>CSS</span> world
</p>
```

```css
span {
  display: inline;
}
```

Результат:

```text
Hello CSS world
```

`span` не начинает новую строку.

Если в строке недостаточно места, inline-содержимое может переноситься между строками.

---

### `width` и `height`

Для обычного строчного элемента:

```css
span {
  width: 300px;
  height: 100px;
}
```

свойства `width` и `height` не определяют его размеры так же, как у block box.

Размер inline box в основном определяется его содержимым и line layout.

---

### Margin и Padding

Горизонтальные:

```css
margin-left
margin-right
padding-left
padding-right
```

у inline elements работают ожидаемо в строке.

Вертикальные padding и border могут визуально отображаться, но не раздвигают строки таким же образом, как размеры блочных элементов.

Вертикальные margins обычных строчных элементов не участвуют в построении строк как вертикальные margins блочных элементов.

---

### Сравнение

| Характеристика | `block` | `inline` |
|---|---|---|
| Обычно начинает новую строку | Да | Нет |
| Располагается внутри строки | Нет | Да |
| `width` / `height` | Обычно применяются | Не работают как у блочных элементов |
| Может переноситься вместе с текстом | Нет | Да |
| Типичные элементы | `<div>`, `<p>`, `<section>` | `<span>`, `<a>`, `<strong>` |

Важно:

> HTML-элемент не является навсегда «block» или «inline».

Его поведение можно изменить через CSS:

```css
span {
  display: block;
}
```

или:

```css
div {
  display: inline;
}
```

## 4. Чем `inline-block` отличается от `inline`?

`inline-block` сочетает строчное размещение с возможностью задавать элементу размеры как отдельному блоку.

Например:

```css
.button {
  display: inline-block;
}
```

---

### Внешнее поведение

`inline-block` элемент располагается в строке вместе с окружающим содержимым.

Например:

```html
<span>First</span>
<span class="box">Second</span>
<span>Third</span>
```

может выглядеть так:

```text
First Second Third
```

То есть `.box` не обязательно начинает новую строку.

В этом он похож на:

```css
display: inline;
```

---

### Внутреннее поведение

В отличие от обычного inline box, `inline-block` позволяет удобно задавать:

```css
width
height
padding
border
margin
```

Например:

```css
.button {
  display: inline-block;

  width: 200px;
  height: 50px;

  padding: 10px;
}
```

Размеры такого элемента учитываются как размеры одной цельной области.

---

### Главное различие

```text
inline
→ находится в строке
→ размеры в основном определяются содержимым
```

```text
inline-block
→ тоже находится в строке
→ но можно задавать width и height как блоку
```

### Сравнение

| Характеристика | `inline` | `inline-block` |
|---|---|---|
| Находится в строке | Да | Да |
| Начинает новую строку | Нет | Нет |
| Можно удобно задать `width` | Обычно нет | Да |
| Можно удобно задать `height` | Обычно нет | Да |
| Ведёт себя как цельная область | — | Да |

В современной модели `inline-block` соответствует поведению, близкому к:

```css
display: inline flow-root;
```

То есть снаружи элемент ведёт себя как строчный, а внутри создаёт отдельный контекст блочного форматирования.

## 5. Что делает `display: none`?

```css
.element {
  display: none;
}
```

означает, что элемент не создаёт область в раскладке и не участвует в ней.


Например:

```html
<p>First</p>
<p class="hidden">Second</p>
<p>Third</p>
```

```css
.hidden {
  display: none;
}
```

Визуально:

```text
First
Third
```

Элемент `Second` не занимает место между ними.

---

### Что происходит с элементом?

`display: none`:

- скрывает сам элемент;
- скрывает его потомков;
- удаляет его CSS-box из layout;
- освобождает место, которое он занимал;
- обычно удаляет элемент и потомков из accessibility tree (дерево доступности).

При этом элемент **не удаляется из DOM**.

JavaScript всё ещё может найти его:

```js
document.querySelector(".hidden");
```

---

### Потомки тоже не отображаются

Например:

```html
<div class="hidden">
  <p>Hello</p>
  <button>Save</button>
</div>
```

```css
.hidden {
  display: none;
}
```

Нельзя вернуть кнопку только так:

```css
.hidden button {
  display: block;
}
```

Пока сам родитель имеет:

```css
display: none;
```

его потомки также не генерируют boxes.

---

### Accessibility

`display: none` обычно удаляет элемент и потомков из accessibility tree, поэтому screen reader не воспринимает их как обычное доступное содержимое.

Следовательно, `display: none` подходит, когда контент действительно должен быть полностью скрыт от текущего интерфейса, а не когда его нужно скрыть только визуально.

---

## 6. Чем `display: none` отличается от `visibility: hidden`?

Оба варианта скрывают элемент визуально, но по-разному влияют на layout.

---

### `display: none`

```css
.element {
  display: none;
}
```

Элемент не создаёт область в раскладке и не занимает место.

Например:

```text
До:

First
Second
Third
```

Если Second получает:

```css
display: none;
```

результат:

```text
First
Third
```

Место исчезает.

---

### `visibility: hidden`

```css
.element {
  visibility: hidden;
}
```

Элемент становится невидимым, но его box **остаётся в layout**.

Получается:

```text
First

[пустое место]

Third
```

Размеры и положение скрытого элемента продолжают влиять на расположение соседей.

---

### Сравнение

| Характеристика | `display: none` | `visibility: hidden` |
|---|---|---|
| Видим | Нет | Нет |
| Область остаётся в раскладке | Нет | Да |
| Занимает место | Нет | Да |
| Может получать focus | Нет | Нет |
| Обычно присутствует в accessibility tree | Нет | Нет |

Важно:

`visibility: hidden` — это не способ сделать элемент «невидимым, но доступным screen reader».

Он также скрывается от accessibility tree.

### Потомки `visibility: hidden`

Есть интересная особенность.

Потомок может снова стать видимым:

```css
.parent {
  visibility: hidden;
}

.child {
  visibility: visible;
}
```

В этом случае `.child` может отображаться.

При:

```css
display: none;
```

родителя аналогичным способом вернуть потомка невозможно.

---

## 7. Что делает `display: contents`?

```css
.element {
  display: contents;
}
```

убирает собственную основную область элемента, но оставляет его содержимое участвующим в раскладке.

> Элемент остаётся в DOM, но его собственная «коробка» исчезает, а дочерние элементы располагаются так, как будто этого промежуточного контейнера в раскладке нет.

Например:

```html
<div class="grid">
  <div class="wrapper">
    <div>A</div>
    <div>B</div>
  </div>

  <div>C</div>
</div>
```

Обычная структура:

```text
.grid
├── .wrapper
│   ├── A
│   └── B
└── C
```

Если:

```css
.wrapper {
  display: contents;
}
```

для целей раскладки структура становится концептуально похожей на:

```text
.grid
├── A
├── B
└── C
```

При этом `.wrapper` **остаётся в DOM**.

JavaScript по-прежнему может получить его:

```js
document.querySelector(".wrapper");
```

---

### Практический пример с Grid

```css
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}

.wrapper {
  display: contents;
}
```

HTML:

```html
<div class="grid">
  <div class="wrapper">
    <div>A</div>
    <div>B</div>
  </div>

  <div>C</div>
</div>
```

`A`, `B` и `C` могут участвовать в grid layout почти так, как если бы были непосредственными дочерними элементами .grid.

---

### Что происходит со стилями самого wrapper?

Поскольку собственной области у .wrapper больше нет, свойства, которые требуют наличия такой области, могут не иметь обычного эффекта.

Например:

```css
.wrapper {
  display: contents;
  background: red;
  border: 2px solid black;
}
```

Нет собственной области .wrapper, на которой можно было бы нарисовать фон и границу.

При этом наследуемые свойства могут продолжить передаваться детям.

Например:

```css
.wrapper {
  display: contents;
  color: red;
}
```

`color` может наследоваться дочерними элементами.

---

### Accessibility

Согласно модели CSS, `display: contents` не должен уничтожать смысл элемента в DOM.

Однако в браузерах исторически существовали и всё ещё встречаются проблемы, при которых сам элемент с `display: contents` удаляется из accessibility tree, хотя потомки остаются.

Поэтому `display: contents` следует применять осторожно к семантически важным элементам, особенно:

- интерактивным элементам;
- структурам с важной ARIA-семантикой;
- элементам, значение которых важно screen reader.

---

## 8. Что такое Formatting Context?

**Formatting Context (контекст форматирования)** — набор правил, определяющих, как располагаются элементы внутри определённой области.

Например, существуют:

- Block Formatting Context;
- Inline Formatting Context;
- Flex Formatting Context;
- Grid Formatting Context;
- Table Formatting Context;
- Ruby Formatting Context.

---

### Block Formatting Context

Использует правила блочной раскладки.

Например, блочные элементы располагаются последовательно по блочному направлению.

---

### Inline Formatting Context

Использует правила строчной раскладки.

Например:

```html
<p>
  Hello <strong>CSS</strong> world
</p>
```

Содержимое располагается внутри строк.

---

### Flex Formatting Context

Создаётся, например:

```css
.container {
  display: flex;
}
```

Непосредственные дочерние элементы становятся элементами Flexbox и располагаются по его правилам.

---

### Grid Formatting Context

Создаётся:

```css
.container {
  display: grid;
}
```

Непосредственные дочерние элементы участвуют в сеточной раскладке.

---

### Почему Formatting Context важен?

Потому что одни и те же свойства могут взаимодействовать по-разному в разных моделях раскладки.

Например:

- в обычном блочной раскладке вертикальные margins могут схлопываться;
- между элементами Flexbox схлопывания margin не происходит;
- `float` особым образом взаимодействует с контекстом блочного форматирования;
- в flex formatting context непосредственные дети становятся flex items;
- в grid formatting context непосредственные дети становятся grid items.

Поэтому:

```text
контекст форматирования
=
набор правил раскладки для определённой области
```

---

## 9. Что такое Block Formatting Context?

**Block Formatting Context (BFC) (Контекст блочного форматирования)** — независимая область блочной раскладки, внутри которой элементы располагаются по правилам блочного форматирования и особым образом взаимодействуют с `float`, внешними отступами и соседними элементами.

Например:

```css
.container {
  display: flow-root;
}
```

создаёт новый BFC.

---

### Что происходит внутри BFC?

В обычном горизонтальном writing mode блочные элементы располагаются один под другим:

```text
┌─────────────┐
│ Block 1     │
└─────────────┘
      ↓
┌─────────────┐
│ Block 2     │
└─────────────┘
```

Но особенно важны границы такого контекста.

Создание нового BFC влияет на:

- взаимодействие с float;
- учёт внутренних плавающих элементов;
- margin collapsing;
- взаимодействие с внешними плавающими элементами.

---

### Пример

```css
.container {
  display: flow-root;
}
```

Теперь `.container` создаёт отдельный BFC.

Это позволяет браузеру рассматривать layout внутри него как отдельную самостоятельную область.

---

### Не путать BFC с Flexbox и Grid

```css
display: flex;
```

создаёт **flex formatting context**.

```css
display: grid;
```

создаёт **grid formatting context**.

Это не то же самое, что обычный BFC, хотя некоторые их свойства поведения похожи: например, они также изолируют определённые layout-взаимодействия и не допускают обычного margin collapsing между своими items.

---

## 10. Для чего может быть полезен BFC?

BFC используется для управления взаимодействием элементов в layout.

Три наиболее важных эффекта:

```text
1. учет внутренних floats
2. защита от внешних floats
3. предотвращение определённого margin collapsing
```

---

### 1. Containment внутренних Floats

Рассмотрим:

```html
<div class="parent">
  <div class="float"></div>
</div>
```

```css
.float {
  float: left;
  width: 100px;
  height: 100px;
}
```

Плавающий элемент может вести себя так, что родитель не получит ожидаемую высоту только из-за наличия float.

Создание BFC:

```css
.parent {
  display: flow-root;
}
```

позволяет контейнеру учитывать внутренние плавающие элементы.

Это современная замена старым приёмам с clearfix во многих случаях.

---

### 2. Защита от внешнего Float

BFC не должен перекрываться с плавающим элементом, находящимся рядом с ним в том же внешнем контексте.

Например:

```css
.image {
  float: left;
}

.content {
  display: flow-root;
}
```

`.content` создаёт BFC и располагается с учётом внешнего плавающего элемента.

---

### 3. Управление Margin Collapsing

Margins элементов из разных BFC не схлопываются через границу BFC обычным образом.

Например:

```css
.parent {
  display: flow-root;
}
```

может предотвратить схлопывание margin ребёнка наружу через границу контейнера.

---

### Почему лучше `display: flow-root`?

Раньше BFC часто создавали побочным способом:

```css
overflow: hidden;
```

только ради влияния на раскладку.

Но это одновременно скрывает содержимое, выходящее за границы контейнера.

Например:

```css
.container {
  overflow: hidden;
}
```

может неожиданно обрезать:

- тень;
- выпадающий элемент;
- декоративный объект.

Если задача только в том, чтобы создать BFC, понятнее написать:

```css
.container {
  display: flow-root;
}
```

Именно для явного создания отдельного контекста блочного форматирования существует `flow-root`.

---

## 11. Что такое `overflow`?

**`overflow`** — CSS-свойство, определяющее, что происходит с содержимым, которое выходит за пределы доступной области элемента.

Overflow возникает, например, если контейнер имеет ограниченную высоту:

```css
.box {
  width: 300px;
  height: 100px;
}
```

но содержимого внутри больше, чем помещается:

```html
<div class="box">
  Очень много текста...
</div>
```

Тогда содержимое может выйти за границы box.

Это и называется:

```text
overflow
```

---

### Свойство `overflow`

Например:

```css
.box {
  overflow: auto;
}
```

Браузер определяет, как обработать переполняющее содержимое.

Основные значения:

```css
visible
hidden
clip
scroll
auto
```

---

### `overflow-x` и `overflow-y`

На самом деле `overflow` является сокращённой записью для:

```css
overflow-x
overflow-y
```

То есть:

```css
overflow: hidden;
```

задаёт соответствующее поведение обеим осям.

Можно управлять ими отдельно:

```css
overflow-x: auto;
overflow-y: hidden;
```

Или использовать два значения:

```css
overflow: auto hidden;
```

Первое относится к `overflow-x`, второе — к `overflow-y`.

---

### Когда возникает переполнение?

Например, из-за:

```css
width
max-width
height
max-height
```

или слишком длинного содержимого.

Пример:

```css
.box {
  width: 150px;
  height: 80px;

  overflow: auto;
}
```

Если содержимого больше, чем помещается, браузер применит выбранную overflow-стратегию.

Начальное значение:

```css
overflow: visible;
```

То есть по умолчанию CSS предпочитает показывать содержимое, даже если оно выходит за box, а не автоматически обрезать его.

---

## 12. Чем отличаются `visible`, `hidden`, `auto`, `scroll` и `clip`?

Это основные значения свойства `overflow`.

---

### `overflow: visible`

Это начальное значение.

```css
.box {
  overflow: visible;
}
```

Если содержимое не помещается:

```text
┌──────────────┐
│ content      │
│ content      │
└──────────────┘
  content
  content
```

Оно может быть видно за пределами элемента.

Характеристики:

- content не обрезается обычным образом;
- scrollbar (полоса прокрутки) не создаётся;
- box не становится scroll container;
- новый BFC из-за этого значения не создаётся.

---

### `overflow: hidden`

```css
.box {
  overflow: hidden;
}
```

Содержимое, выходящее за границы, визуально обрезается.

```text
┌──────────────┐
│ visible      │
│ content      │
└──────────────┘
```

Внешняя часть не отображается.

Однако есть важный нюанс:

> `hidden` не означает, что прокрутка полностью невозможен.

У элемента нет пользовательских scrollbars, но содержимое может прокручиваться:

- программно через JavaScript;
- через изменение `scrollTop` / `scrollLeft`;
- в некоторых случаях при перемещении фокуса к скрытому интерактивному элементу.

Например:

```js
element.scrollTo(0, 200);
```

может изменить положение прокрутки.

`overflow: hidden` также может создавать BFC.

---

### `overflow: auto`

```css
.box {
  overflow: auto;
}
```

Если содержимое помещается:

```text
обычного scrollbar может не быть
```

Если возникает overflow:

```text
появляется возможность scrolling
```

Это одно из наиболее часто используемых значений для scrollable containers.

Например:

```css
.sidebar {
  height: 400px;
  overflow: auto;
}
```

Если содержимое sidebar превышает `400px`, его можно прокручивать.

Вид и наличие видимых scrollbar также зависят от операционной системы и пользовательских настроек.

`auto` устанавливает новый BFC.

---

### `overflow: scroll`

```css
.box {
  overflow: scroll;
}
```

Создаёт scroll container и предусматривает scrollbars независимо от того, требуется ли фактически scrolling.

Это может предотвратить появление/исчезновение scrollbar при изменении количества содержимого.

Однако в современных интерфейсах:

```css
overflow: auto;
```

часто удобнее.

Для резервирования пространства под scrolполосу прокруткиlbar также существует свойство:

```css
scrollbar-gutter
```

например:

```css
scrollbar-gutter: stable;
```

---

### `overflow: clip`

```css
.box {
  overflow: clip;
}
```

Содержимое, выходящее за границы, обрезается.

На первый взгляд это похоже на:

```css
overflow: hidden;
```

Но между ними есть принципиальная разница.

`clip`:

- обрезает overflow;
- не создаёт scroll container;
- не позволяет прокручивать содержимое пользователю;
- не позволяет программно прокручивать содержимое;
- сам по себе не создаёт BFC.

---

### `hidden` vs `clip`

Это особенно важно запомнить:

```text
hidden
→ content обрезан
→ scrollbars нет
→ механизм прокрутки сохраняется
→ программная прокрутка возможна
→ создаёт BFC
```

```text
clip
→ content обрезан
→ scrolling полностью отсутствует
→ scroll container не создаётся
→ BFC сам по себе не создаётся
```

Если необходимо одновременно:

```text
clip overflow
+
создать BFC
```

можно использовать:

```css
.box {
  overflow: clip;
  display: flow-root;
}
```

---

### Сравнительная таблица

| Значение | Переполнение видно | Возможна прокрутка | Полосы прокрутки | Создаёт BFC |
|---|---|---|---|---|
| `visible` | Да | Нет | Нет | Нет |
| `hidden` | Нет | Да, не обычным пользовательским scrollbar | Нет | Да |
| `auto` | Нет при overflow | Да | Когда нужны | Да |
| `scroll` | Нет | Да | Предусмотрены всегда | Да |
| `clip` | Нет | Нет | Нет | Нет |

Главное различие:

```text
visible
→ показать содержимое за границами

hidden
→ обрезать визуально, но сохранить механизм прокрутки

auto
→ добавить прокрутку при необходимости

scroll
→ создать прокручиваемый контейнер

clip
→ просто обрезать без scrolling
```

---

## 13. Как Overflow может влиять на Layout?

`overflow` влияет не только на то, видно ли содержимое за пределами элемента.

В некоторых случаях он меняет и поведение раскладки.

---

### 1. Может создавать Block Formatting Context

Одно из самых важных следствий.

Для блочного контейнера значения `overflow`, отличные от:

```css
visible
clip
```

создают новый контекст блочного форматирования.

Например:

```css
.container {
  overflow: auto;
}
```

или:

```css
.container {
  overflow: hidden;
}
```

создают BFC.

Из-за этого может измениться взаимодействие:

- с floats;
- с margin collapsing;
- с окружающими элементами.

Например:

```css
.parent {
  overflow: hidden;
}
```

исторически часто использовался для учёта плавающих дочерних элементов именно потому, что создавал BFC.

Но если обрезка содержимого не нужна, сегодня обычно понятнее:

```css
.parent {
  display: flow-root;
}
```

---

### 2. Может обрезать содержимое

Например:

```css
.card {
  overflow: hidden;
}
```

может обрезать:

- текст;
- изображения;
- декоративные элементы;
- box shadows потомков;
- элементы, визуально выходящие за container.

Поэтому использовать:

```css
overflow: hidden;
```

только как способ «починить раскладку» нужно осторожно.

---

### 3. Может создавать Scroll Container

Например:

```css
.sidebar {
  height: 500px;
  overflow: auto;
}
```

При overflow sidebar становится scroll container.

Теперь часть содержимого доступна через scrolling вместо того, чтобы увеличивать визуальную область container.

---

### 4. Scrollbar может влиять на доступное пространство

В системах с классическими scrollbars вертикальный scrollbar может занимать часть доступной ширины элемента.

Из-за этого внутреннему содержимому остаётся меньше места.

Например:

```text
ширина контейнера
│
├── область содержимого
└── полоса прокрутки
```

В некоторых системах используются наложенные scrollbars, которые не занимают место таким же образом.

Поэтому внешний вид может немного различаться между операционными системами.

При необходимости можно управлять резервированием места через:

```css
scrollbar-gutter
```

Например:

```css
.container {
  overflow: auto;
  scrollbar-gutter: stable;
}
```

---

### 5. Overflow по одной оси может повлиять на другую

`overflow-x` и `overflow-y` не всегда полностью независимы.

Например:

```css
.box {
  overflow-x: hidden;
  overflow-y: visible;
}
```

нельзя во всех случаях понимать буквально как:

```text
X → hidden
Y → visible
```

Если одна ось использует scrolling value, такое как:

```text
hidden
scroll
auto
```

значение `visible` другой оси при вычислении может превратиться в:

```text
auto
```

А `clip` в соответствующей комбинации может вычисляться как `hidden`.

Поэтому взаимодействие `overflow-x` и `overflow-y` следует учитывать при смешивании разных значений.

---

### 6. `overflow: clip` отличается от остальных

Важно:

```css
overflow: clip;
```

не создаёт BFC.

Поэтому:

```css
overflow: hidden;
```

и:

```css
overflow: clip;
```

могут выглядеть визуально одинаково, но layout-поведение у них отличается.

Если нужно:

```text
обрезать content
+
создать отдельный контекст блочной раскладки
```

можно написать:

```css
.container {
  overflow: clip;
  display: flow-root;
}
```

---

### 7. Overflow не следует использовать для маскировки ошибок раскладки

Например:

```css
body {
  overflow-x: hidden;
}
```

иногда используют, чтобы скрыть горизонтальную прокрутку.

Но если horizontal overflow возник из-за:

```text
элемент слишком широкий
неправильный width
используется transform
отрицательный margin
длинный текст
неадаптивный компонент
```

то `overflow-x: hidden` может только скрыть проблему.

Лучше сначала определить причину overflow.

---

### Практический пример

```css
.card {
  width: 300px;
  height: 150px;

  overflow: auto;
}
```

Если content превышает высоту:

```text
.card
┌─────────────────┐
│ content         │
│ content         │
│ content       ↕ │
│ content       ↕ │
└─────────────────┘
```

вместо увеличения видимой области контейнера пользователь получает возможность прокручивать содержимое.

---

### Главное влияние Overflow на Layout

```text
overflow
│
├── определяет обрезку содержимого
│
├── может создавать scroll container
│
├── может создавать BFC
│
├── влияет на float
│
├── влияет на margin collapsing через BFC
│
├── может изменить доступное пространство из-за scrollbar
│
└── может по-разному взаимодействовать по осям X и Y
```

Поэтому `overflow` — это не просто:

> «показать или скрыть лишний текст».

Это важная часть системы CSS layout.

---

## Общая схема темы

```text
DOCUMENT (документ)
│
└── NORMAL FLOW (нормальный поток)
    │
    ├── Block Layout (блочная раскладка)
    │   └── Block Formatting Context (контекст блочного форматирования)
    │
    └── Inline Layout (строчная раскладка)
        └── Inline Formatting Context (контекст строчного форматирования)
```

Другие модели раскладки:

```text
display: flex
→ Flex Formatting Context

display: grid
→ Grid Formatting Context
```

Свойство:

```css
display
```

определяет:

```text
как элемент участвует во внешнем layout
+
как располагается его содержимое
```

---

## Главное, что нужно запомнить

```text
Normal Flow
→ стандартное расположение элементов
```

```text
block
→ блочное поведение

inline
→ строчное поведение

inline-block
→ находится в строке, но позволяет задавать размеры
```

```text
display: none
→ элемент исчезает из раскладки
→ места не остаётся
```

```text
visibility: hidden
→ элемент не виден
→ место остаётся
```

```text
display: contents
→ собственная область элемента исчезает
→ дети продолжают участвовать в layout
```

```text
Formatting Context (контекст форматирования)
→ набор правил расположения элементов
```

```text
BFC
→ отдельная область блочного форматирования
```

Самый явный современный способ создать BFC:

```css
display: flow-root;
```

```text
overflow: visible
→ показать overflow

overflow: hidden
→ обрезать, но сохранить scroll mechanics

overflow: auto
→ scrolling при необходимости

overflow: scroll
→ создать scroll container

overflow: clip
→ обрезать без scrolling
```

И особенно важно:

```text
overflow: hidden
→ создаёт BFC

overflow: clip
→ BFC не создаёт
```
