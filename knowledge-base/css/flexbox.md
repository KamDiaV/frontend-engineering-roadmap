# VIII. Flexbox

## 1. Что такое Flexbox и какие задачи он решает?

**Flexbox (Flexible Box Layout)** — модель CSS-раскладки, предназначенная для расположения элементов преимущественно **в одном направлении**:

```text
в строку
или
в столбец
```

То есть Flexbox считается **одномерной моделью раскладки**.

Например:

```html
<div class="container">
  <div>One</div>
  <div>Two</div>
  <div>Three</div>
</div>
```

```css
.container {
  display: flex;
}
```

По умолчанию элементы расположатся в строку:

```text
┌─────┐ ┌─────┐ ┌───────┐
│ One │ │ Two │ │ Three │
└─────┘ └─────┘ └───────┘
```

Элемент:

```html
<div class="container">
```

становится **flex-контейнером**.

Его непосредственные дочерние элементы:

```html
<div>One</div>
<div>Two</div>
<div>Three</div>
```

становятся **flex-элементами**.

---

### Какие задачи решает Flexbox?

Flexbox позволяет:

- располагать элементы в строку или столбец;
- выравнивать элементы по горизонтали и вертикали;
- распределять свободное пространство;
- задавать расстояние между элементами;
- позволять элементам увеличиваться;
- позволять элементам уменьшаться;
- переносить элементы на новые строки;
- менять визуальный порядок элементов;
- легко центрировать элементы;
- создавать гибкие панели, меню, карточки и другие компоненты.

Например, горизонтальное меню:

```css
.nav {
  display: flex;
  gap: 24px;
}
```

Карточка, содержимое которой расположено вертикально:

```css
.card {
  display: flex;
  flex-direction: column;
}
```

Центрирование содержимого:

```css
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

---

### Почему Flexbox называется одномерным?

Потому что основная работа Flexbox происходит вдоль одной главной оси.

Например:

```css
flex-direction: row;
```

означает:

```text
главное направление
→ → → → →
```

А:

```css
flex-direction: column;
```

означает:

```text
главное направление
↓
↓
↓
```

Flexbox может переносить элементы на несколько строк, но каждая такая строка всё равно обрабатывается как отдельная flex-линия.

Если необходимо одновременно управлять строгой системой:

```text
строк
+
колонок
```

чаще подходит CSS Grid.

Упрощённо:

```text
Flexbox
→ в первую очередь одномерная раскладка

Grid
→ двумерная раскладка
```

Это не означает, что Flexbox нельзя использовать в сложных интерфейсах. Просто у Flexbox и Grid разные сильные стороны.

Flexbox действительно определяется спецификацией как модель, в которой элементы могут увеличиваться, уменьшаться и распределять свободное пространство вдоль главной оси.

---

## 2. Как создать flex-контейнер?

Чтобы создать flex-контейнер, нужно задать родительскому элементу:

```css
display: flex;
```

Например:

```html
<div class="container">
  <div class="item">One</div>
  <div class="item">Two</div>
  <div class="item">Three</div>
</div>
```

```css
.container {
  display: flex;
}
```

Теперь:

```text
.container
→ flex-контейнер

.item
→ flex-элементы
```

Важно:

> Flex-элементами становятся именно непосредственные дочерние элементы контейнера.

Например:

```html
<div class="container">
  <div class="wrapper">
    <span>Text</span>
  </div>
</div>
```

При:

```css
.container {
  display: flex;
}
```

flex-элементом является:

```html
<div class="wrapper">
```

Но:

```html
<span>Text</span>
```

не является непосредственным flex-элементом `.container`.

Если нужно, чтобы `.wrapper` тоже управлял своими детьми через Flexbox:

```css
.wrapper {
  display: flex;
}
```

---

### `display: inline-flex`

Существует также:

```css
display: inline-flex;
```

Разница относится к поведению самого контейнера среди окружающих элементов.

```css
display: flex;
```

обычно создаёт контейнер с блочным внешним поведением.

```css
display: inline-flex;
```

создаёт flex-контейнер, который сам участвует во внешней раскладке как строчный элемент.

При этом **внутри** оба используют Flexbox.

---

### Что происходит по умолчанию?

После:

```css
.container {
  display: flex;
}
```

основные начальные настройки можно представить примерно так:

```css
.container {
  flex-direction: row;
  flex-wrap: nowrap;
}
```

А flex-элементы по умолчанию:

```text
не растут для заполнения свободного пространства
могут сжиматься
располагаются в одну строку
```

Начальные составляющие `flex`:

```text
flex-grow: 0
flex-shrink: 1
flex-basis: auto
```

то есть:

```css
flex: 0 1 auto;
```

---

## 3. Что такое main axis и cross axis?

В Flexbox есть две оси:

```text
main axis
cross axis
```

### Main Axis — главная ось

**Main Axis (главная ось)** — направление, вдоль которого располагаются flex-элементы.

Главная ось определяется свойством:

```css
flex-direction
```

Например:

```css
flex-direction: row;
```

В обычном направлении текста слева направо:

```text
main axis
──────────────────────→

One   Two   Three
```

---

### Cross Axis — поперечная ось

**Cross Axis (поперечная ось)** проходит перпендикулярно главной.

Если главная ось горизонтальная:

```text
main axis
──────────────→

      ↓
      ↓
 cross axis
```

Если главная ось вертикальная:

```text
main axis
↓
↓
↓

cross axis
──────────────→
```

---

### При `flex-direction: row`

```css
.container {
  display: flex;
  flex-direction: row;
}
```

В обычном горизонтальном режиме письма:

```text
главная ось
→ горизонтальная

поперечная ось
↓ вертикальная
```

---

### При `flex-direction: column`

```css
.container {
  display: flex;
  flex-direction: column;
}
```

Получаем:

```text
главная ось
↓ вертикальная

поперечная ось
→ горизонтальная
```

---

### Почему это очень важно?

Потому что свойства Flexbox работают относительно осей.

Например:

```css
justify-content
```

работает по **главной оси**.

А:

```css
align-items
```

работает по **поперечной оси**.

Поэтому нельзя всегда говорить:

```text
justify-content
= горизонтальное выравнивание
```

Это верно только при:

```css
flex-direction: row;
```

Если изменить:

```css
flex-direction: column;
```

главная ось станет вертикальной.

Тогда:

```css
justify-content
```

будет управлять вертикальным расположением.

---

## 4. Что делает `flex-direction`?

`flex-direction` определяет направление **главной оси** flex-контейнера.

Основные значения:

```css
row
row-reverse
column
column-reverse
```

Начальное значение:

```css
flex-direction: row;
```

---

### `row`

```css
.container {
  display: flex;
  flex-direction: row;
}
```

Элементы располагаются вдоль строчного направления документа.

Для русского и английского текста обычно:

```text
One → Two → Three
```

Важно:

> `row` не означает буквально «всегда слева направо».

Направление зависит и от направления письма документа.

---

### `row-reverse`

```css
flex-direction: row-reverse;
```

Главная ось разворачивается.

Условно:

```text
Three ← Two ← One
```

Начало и конец главной оси меняются местами.

---

### `column`

```css
flex-direction: column;
```

Элементы располагаются столбцом:

```text
One
 ↓
Two
 ↓
Three
```

---

### `column-reverse`

```css
flex-direction: column-reverse;
```

Направление столбца разворачивается:

```text
Three
 ↑
Two
 ↑
One
```

---

### Очень важное следствие

`flex-direction` влияет на смысл других свойств.

Например:

```css
justify-content: center;
```

при:

```css
flex-direction: row;
```

центрирует элементы вдоль горизонтальной главной оси.

Но при:

```css
flex-direction: column;
```

центрирует их вдоль вертикальной главной оси.

---

### Важный нюанс доступности

Значения:

```css
row-reverse
column-reverse
```

изменяют **визуальный порядок**, но не меняют логический порядок элементов в HTML.

Поэтому использовать их для исправления неправильной структуры документа не следует.

Правильный порядок содержимого должен в первую очередь находиться в HTML.

---

## 5. Что делает `justify-content`?

`justify-content` управляет распределением flex-элементов и свободного пространства **по главной оси**.

Например:

```css
.container {
  display: flex;
  justify-content: center;
}
```

При стандартном:

```css
flex-direction: row;
```

главная ось горизонтальная, поэтому элементы будут центрированы горизонтально.

---

### `flex-start`

```css
justify-content: flex-start;
```

Элементы располагаются в начале главной оси:

```text
┌──────────────────────────────┐
│ A B C                        │
└──────────────────────────────┘
```

---

### `flex-end`

```css
justify-content: flex-end;
```

```text
┌──────────────────────────────┐
│                        A B C │
└──────────────────────────────┘
```

---

### `center`

```css
justify-content: center;
```

```text
┌──────────────────────────────┐
│            A B C             │
└──────────────────────────────┘
```

---

### `space-between`

```css
justify-content: space-between;
```

Свободное пространство распределяется **между элементами**:

```text
┌──────────────────────────────┐
│ A            B             C │
└──────────────────────────────┘
```

У начала и конца контейнера дополнительного промежутка нет.

---

### `space-around`

```css
justify-content: space-around;
```

Вокруг каждого элемента распределяется пространство.

В результате промежуток между соседними элементами получается примерно вдвое больше пространства у краёв.

```text
┌──────────────────────────────┐
│    A         B         C     │
└──────────────────────────────┘
```

---

### `space-evenly`

```css
justify-content: space-evenly;
```

Все промежутки одинаковые:

```text
край ↔ A ↔ B ↔ C ↔ край
```

---

### Современные значения `start` и `end`

Также существуют:

```css
justify-content: start;
justify-content: end;
```

Они относятся к общей системе CSS Box Alignment.

Для Flexbox всё ещё часто встречаются:

```css
flex-start
flex-end
```

---

### Нужна свободная область

Очень важный момент:

> `justify-content` распределяет **свободное пространство**.

Например:

```css
.container {
  width: 600px;
}
```

А три элемента вместе занимают:

```text
300px
```

Тогда остаётся:

```text
600 - 300 = 300px
```

Именно эти `300px` может распределить `justify-content`.

Если элементы уже занимают всю доступную ширину:

```text
свободное пространство = 0
```

эффект некоторых значений `justify-content` может быть незаметен.

---

### Главное

```text
justify-content
→ работает по главной оси
→ распределяет элементы и свободное пространство
```

---

## 6. Что делает `align-items`?

`align-items` управляет выравниванием flex-элементов **по поперечной оси**.

Например:

```css
.container {
  display: flex;
  align-items: center;
}
```

При стандартном:

```css
flex-direction: row;
```

поперечная ось вертикальная.

Поэтому:

```css
align-items: center;
```

центрирует элементы по вертикали внутри контейнера.

---

### `stretch`

Характерное стандартное поведение Flexbox:

```css
align-items: stretch;
```

Элементы могут растягиваться вдоль поперечной оси, если их соответствующий размер остаётся автоматическим.

Например:

```text
┌────────────────────────────┐
│ ┌───┐ ┌───┐ ┌───┐         │
│ │ A │ │ B │ │ C │         │
│ │   │ │   │ │   │         │
│ │   │ │   │ │   │         │
│ └───┘ └───┘ └───┘         │
└────────────────────────────┘
```

В современной общей модели `align-items` имеет начальное значение `normal`, которое для flex-элементов ведёт себя как `stretch`. Поэтому в учебных материалах часто говорят, что стандартное поведение Flexbox — `stretch`.

---

### `flex-start`

```css
align-items: flex-start;
```

Элементы прижимаются к началу поперечной оси.

При `row`:

```text
┌────────────────────────────┐
│ A   B   C                  │
│                            │
│                            │
└────────────────────────────┘
```

---

### `flex-end`

```css
align-items: flex-end;
```

```text
┌────────────────────────────┐
│                            │
│                            │
│ A   B   C                  │
└────────────────────────────┘
```

---

### `center`

```css
align-items: center;
```

```text
┌────────────────────────────┐
│                            │
│       A   B   C            │
│                            │
└────────────────────────────┘
```

---

### `baseline`

```css
align-items: baseline;
```

Элементы выравниваются по базовой линии текста.

Это полезно, когда внутри элементов используются разные размеры шрифта.

Например:

```text
Small text
BIG TEXT
```

можно выровнять так, чтобы базовые линии текста совпадали.

---

### Не путать с `justify-content`

```text
justify-content
→ главная ось

align-items
→ поперечная ось
```

При:

```css
flex-direction: row;
```

обычно:

```text
justify-content → горизонталь
align-items     → вертикаль
```

При:

```css
flex-direction: column;
```

обычно:

```text
justify-content → вертикаль
align-items     → горизонталь
```

---

## 7. Чем `align-items` отличается от `align-content`?

Это очень важное различие.

### `align-items`

Управляет расположением **самих flex-элементов внутри flex-линии** по поперечной оси.

```css
.container {
  align-items: center;
}
```

Например:

```text
одна flex-линия

┌──────────────────────────┐
│                          │
│      A   B   C           │
│                          │
└──────────────────────────┘
```

---

### `align-content`

Управляет распределением **нескольких flex-линий** по поперечной оси.

То есть для него обычно нужны:

```css
flex-wrap: wrap;
```

и несколько строк или столбцов.

Например:

```css
.container {
  display: flex;
  flex-wrap: wrap;
  align-content: center;
}
```

Условно:

```text
┌──────────────────────────┐
│                          │
│    A B C                 │
│    D E F                 │
│                          │
└──────────────────────────┘
```

Две flex-линии как группа расположены по центру контейнера.

---

### Если flex-линия только одна

При:

```css
flex-wrap: nowrap;
```

`align-content` на flex-контейнер не оказывает эффекта.

Это одна из главных причин, почему начинающий пишет:

```css
align-content: center;
```

и не видит результата.

---

### Сравнение

```text
align-items
→ выравнивает элементы
  внутри каждой линии

align-content
→ распределяет сами линии
  внутри контейнера
```

Представим:

```text
Flex container

┌─────────────────────────────┐
│                             │
│ Line 1:   A   B   C         │
│                             │
│ Line 2:   D   E   F         │
│                             │
└─────────────────────────────┘
```

`align-items` отвечает за положение:

```text
A B C
D E F
```

внутри их линий.

`align-content` отвечает за положение:

```text
Line 1
Line 2
```

как целых линий.

---

### Главное

```text
align-items
→ элементы

align-content
→ flex-линии
```

И:

```text
align-content
→ нужен многострочный flex-контейнер
```

---

## 8. Что делает `align-self`?

`align-self` позволяет изменить выравнивание **одного конкретного flex-элемента** по поперечной оси.

Например:

```css
.container {
  display: flex;
  align-items: flex-start;
}
```

Все элементы находятся у начала поперечной оси.

Но:

```css
.special {
  align-self: flex-end;
}
```

может изменить положение только одного элемента.

---

### Пример

```html
<div class="container">
  <div>A</div>
  <div class="special">B</div>
  <div>C</div>
</div>
```

```css
.container {
  display: flex;
  height: 300px;
  align-items: flex-start;
}

.special {
  align-self: flex-end;
}
```

Условно:

```text
┌────────────────────────────┐
│ A                 C        │
│                            │
│                            │
│          B                 │
└────────────────────────────┘
```

---

### Связь с `align-items`

```css
align-items
```

задаётся контейнеру и влияет на группу flex-элементов.

```css
align-self
```

задаётся конкретному flex-элементу.

Можно представить:

```text
align-items
→ правило для всех

align-self
→ исключение для одного
```

---

### `auto`

Начальное значение:

```css
align-self: auto;
```

в обычной ситуации означает, что элемент берёт соответствующее выравнивание от `align-items` своего flex-контейнера.

---

### Значения

Например:

```css
align-self: flex-start;
align-self: flex-end;
align-self: center;
align-self: stretch;
align-self: baseline;
```

---

### Главное

```text
align-items
→ задаётся контейнеру
→ выравнивает группу

align-self
→ задаётся одному flex-элементу
→ позволяет переопределить его выравнивание
```

---

## 9. Что делает `gap`?

`gap` задаёт расстояние **между flex-элементами и flex-линиями**.

Например:

```css
.container {
  display: flex;
  gap: 20px;
}
```

Получаем:

```text
A ←20px→ B ←20px→ C
```

---

### Почему `gap` удобнее `margin`?

Раньше расстояние между элементами часто задавали:

```css
.item {
  margin-right: 20px;
}
```

Но возникала проблема с последним элементом:

```text
A 20px B 20px C 20px
                 ↑
             лишний margin
```

С `gap`:

```css
.container {
  display: flex;
  gap: 20px;
}
```

расстояние добавляется **только между элементами**.

У краёв контейнера `gap` автоматически не появляется.

---

### Одно значение

```css
gap: 20px;
```

задаёт одинаковый промежуток по обеим соответствующим направлениям.

---

### Два значения

```css
gap: 20px 40px;
```

это сокращение для:

```css
row-gap: 20px;
column-gap: 40px;
```

То есть:

```text
первое значение
→ row-gap

второе
→ column-gap
```

Во Flexbox то, какое из них окажется расстоянием между элементами внутри линии, зависит от `flex-direction`.

Например, для:

```css
flex-direction: row;
```

`column-gap` находится между элементами внутри строки, а `row-gap` — между flex-линиями.

---

### Пример с переносом

```css
.container {
  display: flex;
  flex-wrap: wrap;

  row-gap: 20px;
  column-gap: 30px;
}
```

Получаем:

```text
A ←30→ B ←30→ C
      ↕ 20px
D ←30→ E ←30→ F
```

---

### `gap` не распределяет свободное пространство

Например:

```css
gap: 20px;
```

означает конкретный промежуток между элементами.

А:

```css
justify-content: space-between;
```

распределяет **оставшееся свободное пространство**.

Поэтому это разные механизмы.

И они могут использоваться вместе.

---

### Главное

```text
gap
→ расстояние между flex-элементами
→ не требует margin на каждом элементе
→ не добавляет автоматический отступ у краёв контейнера
```

`gap` является shorthand для `row-gap` и `column-gap`.

---

## 10. Что делает `flex-wrap`?

`flex-wrap` определяет, должны ли flex-элементы оставаться в одной линии или могут переноситься на новые линии.

Начальное значение:

```css
flex-wrap: nowrap;
```

---

### `nowrap`

```css
.container {
  display: flex;
  flex-wrap: nowrap;
}
```

Все элементы стараются оставаться на одной flex-линии.

```text
A B C D E F
```

Если места недостаточно, элементы могут сжиматься благодаря:

```css
flex-shrink: 1;
```

которое используется по умолчанию.

Если элементы больше не могут достаточно сжаться, может появиться переполнение.

---

### `wrap`

```css
.container {
  flex-wrap: wrap;
}
```

Элементы разрешается переносить на новые линии.

Например:

```text
A B C
D E F
```

---

### `wrap-reverse`

```css
flex-wrap: wrap-reverse;
```

Перенос тоже разрешается, но направление расположения flex-линий по поперечной оси разворачивается.

Это отличается от:

```css
flex-direction: row-reverse;
```

`row-reverse` разворачивает главную ось.

`wrap-reverse` разворачивает направление размещения **линий** по поперечной оси.

---

### Пример

```css
.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 24px;
}

.card {
  flex-basis: 300px;
}
```

Если контейнер широкий:

```text
Card Card Card
```

Если места меньше:

```text
Card Card
Card
```

---

### Flexbox всё равно остаётся одномерным

Когда используется:

```css
flex-wrap: wrap;
```

может казаться, что мы получили полноценную систему строк и колонок.

Но каждая flex-линия рассчитывается отдельно.

Например:

```text
Line 1 → распределяет своё пространство
Line 2 → распределяет своё пространство отдельно
```

Если нужна строгая двумерная сетка, где колонки разных строк должны совпадать, обычно лучше подходит CSS Grid.

---

### `flex-flow`

Свойства:

```css
flex-direction
flex-wrap
```

можно объединить:

```css
flex-flow: row wrap;
```

Это эквивалентно:

```css
flex-direction: row;
flex-wrap: wrap;
```

---

## 11. Что такое `flex-basis`?

`flex-basis` задаёт **начальный размер flex-элемента по главной оси** до распределения свободного или недостающего пространства.

Это очень важное определение.

Упрощённо алгоритм можно представить так:

```text
flex-basis
↓
с какого размера начать

flex-grow / flex-shrink
↓
как потом изменить этот размер
```

---

### Пример

```css
.item {
  flex-basis: 200px;
}
```

При:

```css
flex-direction: row;
```

главная ось горизонтальная.

Поэтому:

```text
flex-basis: 200px
```

задаёт начальную ширину примерно:

```text
200px
```

до работы механизмов увеличения и уменьшения.

---

### При `flex-direction: column`

Если:

```css
.container {
  flex-direction: column;
}
```

главная ось становится вертикальной.

Тогда `flex-basis` относится уже к начальному размеру по вертикали.

То есть Flexbox работает не в терминах:

```text
width
```

а в терминах:

```text
размер вдоль главной оси
```

---

### `flex-basis: auto`

Начальное значение:

```css
flex-basis: auto;
```

Если у элемента задан соответствующий основной размер:

```css
.item {
  width: 300px;
}
```

при стандартном `row` значение `auto` может использовать эту ширину как основу.

Если `width` тоже:

```css
width: auto;
```

размер в значительной степени определяется содержимым элемента.

---

### `flex-basis` и `width`

Например:

```css
.item {
  width: 500px;
  flex-basis: 200px;
}
```

Если главная ось горизонтальная и `flex-basis` имеет конкретное значение, Flexbox использует именно его как начальную основу для гибкого расчёта.

То есть:

```text
flex-basis: 200px
```

получает преимущество перед:

```text
width: 500px
```

для определения начального главного размера flex-элемента.

---

### `flex-basis: 0`

Например:

```css
.item {
  flex-basis: 0;
}
```

говорит Flexbox начинать распределение гибкого пространства практически от нулевой основы.

Это часто используется, когда элементы должны делить пространство прежде всего по своим `flex-grow`, а не исходя из разных размеров содержимого.

Например:

```css
.item {
  flex: 1 1 0;
}
```

---

### `auto` и `0`

Упрощённо:

```text
flex-basis: auto
→ учитывай естественный/заданный начальный размер

flex-basis: 0
→ начни распределение гибкого пространства от нулевой основы
```

Но итоговый размер всё равно может ограничиваться:

```text
min-width
max-width
min-height
max-height
размером содержимого
```

---

### Главное

```text
flex-basis
=
начальный размер flex-элемента
по главной оси
до grow/shrink
```

---

## 12. Что делает `flex-grow`?

`flex-grow` определяет, **как flex-элемент получает положительное свободное пространство контейнера**.

Начальное значение:

```css
flex-grow: 0;
```

То есть flex-элемент по умолчанию не обязан увеличиваться для заполнения свободного места.

---

### Простой пример

```css
.container {
  display: flex;
  width: 600px;
}

.item {
  flex-basis: 200px;
}
```

Допустим, внутри два элемента:

```text
200px + 200px = 400px
```

Контейнер:

```text
600px
```

Свободное пространство:

```text
600 - 400
=
200px
```

---

### Если оба имеют `flex-grow: 1`

```css
.item {
  flex-grow: 1;
}
```

Свободные `200px` делятся поровну:

```text
100px
+
100px
```

Итог:

```text
Item 1
200 + 100 = 300px

Item 2
200 + 100 = 300px
```

---

### Разные коэффициенты

```css
.first {
  flex-grow: 1;
}

.second {
  flex-grow: 2;
}
```

Есть:

```text
200px свободного места
```

Сумма коэффициентов:

```text
1 + 2 = 3
```

Первая получает:

```text
1/3 свободного пространства
```

Вторая:

```text
2/3 свободного пространства
```

---

### Важный нюанс

Очень распространённое упрощение:

> `flex-grow: 1` и `flex-grow: 2` означают, что второй элемент будет в два раза шире первого.

Это **не обязательно так**.

`flex-grow` определяет соотношение распределения **свободного пространства**, а не обязательно итоговых размеров.

Например:

```text
First basis  = 200px
Second basis = 200px

свободное пространство = 300px
```

При:

```text
grow 1
grow 2
```

распределим:

```text
100px
200px
```

Итог:

```text
First  = 300px
Second = 400px
```

А не:

```text
1 : 2
```

по полной ширине.

---

### Если свободного места нет

Если:

```text
контейнер = 400px
элементы = 400px
```

то:

```text
положительное свободное пространство = 0
```

И `flex-grow` увеличивать ничего не будет.

---

### Главное

```text
flex-grow
→ распределяет положительное свободное пространство
```

```text
0
→ не расти

1, 2, 3...
→ коэффициенты распределения свободного пространства
```

---

## 13. Что делает `flex-shrink`?

`flex-shrink` определяет, **как flex-элемент уменьшается, когда контейнеру не хватает места**.

Начальное значение:

```css
flex-shrink: 1;
```

Поэтому flex-элементы по умолчанию могут сжиматься.

---

### Пример

Контейнер:

```css
.container {
  display: flex;
  width: 500px;
}
```

Два элемента:

```css
.item {
  flex-basis: 300px;
}
```

Их общий начальный размер:

```text
300 + 300
=
600px
```

Но контейнер:

```text
500px
```

Не хватает:

```text
600 - 500
=
100px
```

Это называется отрицательным свободным пространством.

Flexbox должен убрать:

```text
100px
```

из размеров элементов.

---

### Если оба `flex-shrink: 1`

При одинаковой основе они уменьшатся примерно одинаково:

```text
300 → 250
300 → 250
```

---

### `flex-shrink: 0`

Можно запретить элементу участвовать в обычном сжатии:

```css
.icon {
  flex-shrink: 0;
}
```

Например:

```html
<div class="row">
  <img class="icon" src="icon.svg" alt="">
  <p>Очень длинный текст...</p>
</div>
```

```css
.row {
  display: flex;
}

.icon {
  width: 40px;
  flex-shrink: 0;
}
```

Теперь Flexbox не будет пытаться уменьшать иконку через механизм `flex-shrink`.

---

### Коэффициенты сжатия

Можно использовать:

```css
flex-shrink: 1;
flex-shrink: 2;
```

Но алгоритм немного сложнее, чем у `flex-grow`.

При сжатии браузер учитывает не только коэффициент `flex-shrink`, но и **начальный размер элемента**.

Упрощённо вес сжатия связан с:

```text
flex-shrink
×
flex-basis
```

Это нужно, чтобы очень большой элемент не терял столько же пикселей, сколько очень маленький, если их коэффициенты одинаковые.

---

### Пример

Первый элемент:

```text
flex-basis: 300px
flex-shrink: 1
```

Второй:

```text
flex-basis: 100px
flex-shrink: 1
```

Если нужно убрать:

```text
100px
```

эти `100px` не обязательно разделятся:

```text
50px / 50px
```

Больший элемент получает больший вес сжатия.

При отсутствии дополнительных ограничений результат приблизительно будет:

```text
300 → 225px
100 → 75px
```

---

### Но есть минимальные размеры

Даже:

```css
flex-shrink: 1;
```

не означает:

> элемент можно уменьшать бесконечно.

Flex-элемент может упереться в:

```text
min-width
min-height
минимальный размер содержимого
```

Именно поэтому иногда `flex-shrink` вроде бы установлен правильно, а элемент всё равно не уменьшается.

Это подробно разберём в вопросах 17 и 18.

---

### Главное

```text
flex-grow
→ что делать с лишним пространством

flex-shrink
→ что делать при нехватке пространства
```

```text
flex-shrink: 0
→ не участвовать в обычном сжатии
```

---

## 14. Что означает сокращённая запись `flex`?

Свойство:

```css
flex
```

является сокращённой записью для трёх свойств:

```css
flex-grow
flex-shrink
flex-basis
```

Полная последовательность:

```css
flex: grow shrink basis;
```

Например:

```css
.item {
  flex: 1 1 200px;
}
```

означает:

```css
.item {
  flex-grow: 1;
  flex-shrink: 1;
  flex-basis: 200px;
}
```

---

### Начальные значения

Если вообще не задавать `flex`, его составляющие имеют:

```css
flex-grow: 0;
flex-shrink: 1;
flex-basis: auto;
```

То есть:

```css
flex: 0 1 auto;
```

---

### `flex: initial`

```css
flex: initial;
```

эквивалентно:

```css
flex: 0 1 auto;
```

Элемент:

```text
не увеличивается для заполнения свободного пространства
может уменьшаться
начинает с auto-размера
```

---

### `flex: auto`

```css
flex: auto;
```

эквивалентно:

```css
flex: 1 1 auto;
```

Элемент:

```text
может увеличиваться
может уменьшаться
учитывает свой исходный auto-размер
```

---

### `flex: none`

```css
flex: none;
```

эквивалентно:

```css
flex: 0 0 auto;
```

Элемент:

```text
не растёт
не сжимается через flex-механизм
использует auto как основу
```

---

### `flex: 1`

Очень распространённая запись:

```css
.item {
  flex: 1;
}
```

В современных браузерах она разворачивается практически как:

```css
flex: 1 1 0%;
```

То есть:

```text
grow   = 1
shrink = 1
basis  = 0%
```

Это позволяет flex-элементам распределять доступное пространство примерно на равных условиях.

Например:

```css
.container {
  display: flex;
}

.item {
  flex: 1;
}
```

Три элемента обычно поделят доступное пространство:

```text
┌─────────┬─────────┬─────────┐
│    A    │    B    │    C    │
└─────────┴─────────┴─────────┘
```

Но их автоматические минимальные размеры всё равно могут влиять на результат.

---

### `flex: 2`

```css
.first {
  flex: 1;
}

.second {
  flex: 2;
}
```

Поскольку основа близка к нулевой, доступное пространство распределяется примерно по коэффициентам:

```text
1 : 2
```

---

### Запись с конкретной основой

```css
.sidebar {
  flex: 0 0 300px;
}
```

означает:

```text
не расти
не сжиматься
основа 300px
```

Такой вариант часто встречается для фиксированной боковой панели.

---

### Почему shorthand удобен?

Потому что свойства:

```text
grow
shrink
basis
```

очень тесно связаны.

Поэтому спецификация и MDN рекомендуют во многих типичных случаях использовать `flex` целиком, а не менять только одно из трёх свойств.

---

### Главное

```text
flex
=
flex-grow
+
flex-shrink
+
flex-basis
```

---

## 15. Что делает `order`?

`order` позволяет изменить **визуальный порядок flex-элементов**.

Начальное значение:

```css
order: 0;
```

Например:

```html
<div class="container">
  <div class="first">A</div>
  <div class="second">B</div>
  <div class="third">C</div>
</div>
```

Обычный порядок:

```text
A B C
```

---

### Пример

```css
.first {
  order: 2;
}

.second {
  order: 1;
}

.third {
  order: 3;
}
```

Визуально:

```text
B A C
```

---

### Чем меньше `order`, тем раньше элемент

Например:

```css
.first {
  order: -1;
}
```

```css
.second {
  order: 0;
}
```

```css
.third {
  order: 1;
}
```

Порядок:

```text
first
second
third
```

---

### Если `order` одинаковый

Например:

```css
A → order: 0
B → order: 0
C → order: 0
```

сохраняется их исходный порядок в HTML:

```text
A B C
```

---

### Можно использовать отрицательные числа

```css
.special {
  order: -1;
}
```

Так элемент можно визуально переместить раньше элементов с:

```css
order: 0;
```

---

### Но меняется только визуальный порядок

Это ключевой момент.

`order` не переписывает DOM.

Например:

```html
<button>A</button>
<button>B</button>
<button>C</button>
```

остаются в HTML именно в таком логическом порядке, даже если CSS визуально показывает:

```text
C A B
```

Поэтому `order` нельзя использовать как замену правильной структуре HTML.

---

## 16. Почему `order` нужно использовать осторожно с точки зрения accessibility?

Потому что `order` меняет **визуальное расположение**, но не меняет логический порядок содержимого в HTML.

Например:

```html
<button>First</button>
<button>Second</button>
<button>Third</button>
```

CSS:

```css
button:nth-child(1) {
  order: 3;
}

button:nth-child(2) {
  order: 1;
}

button:nth-child(3) {
  order: 2;
}
```

Визуально пользователь может увидеть:

```text
Second → Third → First
```

Но исходный HTML остаётся:

```text
First → Second → Third
```

---

### Что происходит при клавиатурной навигации?

При обычной последовательной навигации пользователь нажимает:

```text
Tab
```

и порядок фокуса в стандартной ситуации следует логическому порядку документа.

То есть пользователь может видеть:

```text
Second   Third   First
```

но фокус перемещается:

```text
First
↓
Second
↓
Third
```

Визуально это может выглядеть как прыжки:

```text
справа
↓
слева
↓
центр
```

---

### Что происходит с программами чтения с экрана?

Логический порядок чтения также в первую очередь связан со структурой документа, а не просто с визуальным расположением Flexbox.

Получается несоответствие:

```text
что видит пользователь
≠
логический порядок документа
```

---

### Поэтому неправильный подход

Например, HTML:

```html
<footer>Footer</footer>
<main>Main</main>
<header>Header</header>
```

и затем попытка исправить это через:

```css
header {
  order: 1;
}

main {
  order: 2;
}

footer {
  order: 3;
}
```

— плохая идея.

Правильнее сразу написать HTML в логическом порядке:

```html
<header>Header</header>
<main>Main</main>
<footer>Footer</footer>
```

---

### Когда `order` допустим?

Когда изменение визуального расположения **не меняет смысл и последовательность содержимого**.

Например, декоративный элемент:

```text
icon + label
```

может визуально переставляться в зависимости от дизайна, если логика интерфейса от этого не нарушается.

---

### То же относится к `*-reverse`

Похожую проблему могут создавать:

```css
flex-direction: row-reverse;
flex-direction: column-reverse;
```

Они тоже меняют визуальный порядок, не исправляя логический порядок HTML.

---

### Главное правило

```text
HTML
→ задаёт правильный логический порядок

Flexbox
→ управляет визуальным расположением
```

Не следует использовать:

```text
order
row-reverse
column-reverse
```

для исправления неправильной структуры документа.

Спецификация прямо предупреждает, что `order` и обратные направления Flexbox не должны использоваться как замена правильному исходному порядку, поскольку это может ухудшить доступность.

## 17. Почему flex-элемент иногда не сжимается?

Это одна из самых важных особенностей Flexbox.

Представим:

```css
.container {
  display: flex;
  width: 400px;
}

.item {
  flex-shrink: 1;
}
```

Кажется:

> Раз `flex-shrink: 1`, элемент должен спокойно уменьшиться.

Но иногда он всё равно выходит за границы контейнера.

Причина часто заключается в **автоматическом минимальном размере flex-элемента**.

---

### `min-width` по умолчанию

Начальное значение:

```css
min-width: auto;
```

Для обычного блока `auto` часто фактически не создаёт такого ограничения.

Но для flex-элемента механизм особый.

Вдоль главной оси автоматический минимальный размер flex-элемента может определяться его содержимым.

Упрощённо браузер говорит:

> Я разрешу элементу уменьшаться, но не буду по умолчанию сжимать его меньше минимального размера, необходимого содержимому.

---

### Пример с длинным текстом

```html
<div class="container">
  <div class="item">
    VeryVeryVeryVeryVeryVeryLongWord
  </div>
</div>
```

```css
.container {
  display: flex;
  width: 200px;
}

.item {
  flex-shrink: 1;
}
```

Длинное слово нельзя удобно перенести.

Поэтому минимальный размер содержимого может оказаться больше:

```text
200px
```

И элемент переполнит контейнер.

---

### Другой частый пример

```html
<div class="row">
  <div class="content">
    <h2 class="title">
      Очень длинный заголовок...
    </h2>
  </div>
</div>
```

```css
.row {
  display: flex;
}

.title {
  white-space: nowrap;
}
```

Даже если `.content` имеет:

```css
flex: 1;
```

он может отказываться уменьшаться настолько, насколько ожидает разработчик.

Причина:

```text
min-width: auto
+
минимальный размер содержимого
```

---

### Другие возможные причины

Элемент может не сжиматься из-за:

```css
flex-shrink: 0;
```

или:

```css
min-width: 300px;
```

или содержимого с большим естественным размером:

```text
изображение
длинная строка
nowrap
длинная ссылка
```

---

### `width` не всегда решает проблему

Например:

```css
.item {
  width: 100%;
  flex-shrink: 1;
}
```

это ещё не гарантирует, что элемент сможет стать уже своего автоматического минимального размера.

---

### Главное

Если flex-элемент:

```text
неожиданно не сжимается
```

проверяй:

```text
flex-shrink
min-width
содержимое
white-space
длинные слова
изображения
```

Особенно:

```css
min-width: auto;
```

Для flex-элементов автоматический минимальный размер действительно может основываться на минимальном размере содержимого.

---

## 18. Для чего используют `min-width: 0` во flex-layout?

`min-width: 0` используется, чтобы разрешить flex-элементу **сжиматься меньше его автоматического минимального размера, основанного на содержимом**.

Это один из самых важных практических приёмов Flexbox.

---

### Проблема

HTML:

```html
<div class="card">
  <div class="icon">★</div>

  <div class="content">
    <h2 class="title">
      Очень-очень-очень-длинный-заголовок
    </h2>
  </div>
</div>
```

CSS:

```css
.card {
  display: flex;
  width: 300px;
}

.content {
  flex: 1;
}

.title {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

Мы ожидаем:

```text
Очень-очень-очень...
```

Но `.content` может отказаться достаточно сжиматься и переполнить `.card`.

---

### Почему?

У flex-элемента `.content`:

```css
min-width: auto;
```

Поэтому его минимальная ширина может учитывать минимально необходимый размер содержимого.

---

### Решение

```css
.content {
  flex: 1;
  min-width: 0;
}
```

Теперь мы явно говорим:

> Этому flex-элементу разрешено уменьшаться вплоть до нулевой минимальной ширины, если остальные правила это допускают.

После этого:

```css
.title {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

может нормально работать.

---

### Схема

Без:

```css
min-width: 0;
```

может получиться:

```text
container
┌──────────────────────┐
│ ★ | ОченьОченьОченьОченьОчень...
└──────────────────────┘
                     ↑
                  overflow
```

С:

```css
min-width: 0;
```

```text
┌──────────────────────┐
│ ★ | ОченьОченьОчень… │
└──────────────────────┘
```

---

### Почему именно `0`?

Потому что мы отменяем автоматический минимальный размер:

```text
min-width: auto
→ может защищать размер содержимого
```

и задаём:

```text
min-width: 0
→ не запрещай flex-алгоритму сжимать элемент
  из-за автоматического min-content ограничения
```

Это не означает, что итоговая ширина обязательно будет `0`.

Это означает:

> `0` теперь является нижней границей свойства `min-width`, а фактический размер определяет Flexbox.

---

### Вертикальный аналог

Если главная ось вертикальная:

```css
flex-direction: column;
```

похожая проблема может потребовать:

```css
min-height: 0;
```

То есть принцип относится к **минимальному размеру по главной оси**.

---

### Когда `min-width: 0` особенно полезен?

Например:

```text
flex-строка
+
длинный текст
```

или:

```text
text-overflow: ellipsis
```

или:

```text
вложенный компонент,
который переполняет flex-контейнер
```

---

### Важно

Не нужно автоматически писать:

```css
min-width: 0;
```

на каждый элемент проекта.

Используй его там, где автоматический минимальный размер Flexbox действительно мешает нужному сжатию.

---

### Главное

```text
Flex item
по умолчанию:

min-width: auto
```

может означать:

```text
не становись уже,
чем требует содержимое
```

А:

```css
min-width: 0;
```

означает:

```text
разреши flex-алгоритму
сжимать элемент сильнее
```

---

## 19. Как центрировать элемент по горизонтали и вертикали с помощью Flexbox?

Классический вариант:

```css
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

HTML:

```html
<div class="container">
  <div class="item">Hello</div>
</div>
```

Допустим:

```css
.container {
  display: flex;

  width: 600px;
  height: 400px;

  justify-content: center;
  align-items: center;
}
```

Получаем:

```text
┌──────────────────────────────┐
│                              │
│                              │
│          ┌───────┐           │
│          │ Hello │           │
│          └───────┘           │
│                              │
│                              │
└──────────────────────────────┘
```

---

### Почему это работает?

По умолчанию:

```css
flex-direction: row;
```

Поэтому:

```text
main axis
→ горизонтальная

cross axis
→ вертикальная
```

Следовательно:

```css
justify-content: center;
```

центрирует по главной оси:

```text
→ горизонтально
```

А:

```css
align-items: center;
```

центрирует по поперечной оси:

```text
→ вертикально
```

---

### Важно: контейнеру нужна свободная высота

Например:

```css
.container {
  display: flex;
  align-items: center;
}
```

Если высота контейнера равна высоте самого содержимого:

```text
свободного вертикального пространства = 0
```

визуально центрировать практически нечего.

Поэтому в примерах часто используют:

```css
height: 400px;
```

или:

```css
min-height: 100dvh;
```

Например:

```css
.page {
  min-height: 100dvh;

  display: flex;
  justify-content: center;
  align-items: center;
}
```

---

### Что будет при `flex-direction: column`?

Если:

```css
.container {
  flex-direction: column;
}
```

оси меняются.

Теперь:

```text
main axis
↓ вертикальная

cross axis
→ горизонтальная
```

Поэтому:

```css
justify-content: center;
```

центрирует **вертикально**.

А:

```css
align-items: center;
```

центрирует **горизонтально**.

Но комбинация:

```css
justify-content: center;
align-items: center;
```

всё равно даёт центрирование по обеим осям.

---

### Альтернативный вариант через `margin: auto`

В Flexbox можно также использовать:

```css
.item {
  margin: auto;
}
```

Например:

```css
.container {
  display: flex;
  width: 600px;
  height: 400px;
}

.item {
  margin: auto;
}
```

Автоматические внешние отступы заберут доступное пространство вокруг элемента, и он окажется по центру.

Но наиболее узнаваемый вариант:

```css
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

---

### Главное

Для стандартного Flexbox-центрирования:

```css
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

Запоминаем через оси:

```text
justify-content
→ главная ось

align-items
→ поперечная ось
```

а не:

```text
justify-content
→ всегда горизонталь

align-items
→ всегда вертикаль
```

---
