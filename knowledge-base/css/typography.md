# XI. Текст и типографика

## 1. Что делают `font-family`, `font-size`, `font-weight`?

Эти три свойства управляют основными характеристиками шрифта.

```css
.text {
  font-family: "Inter", Arial, sans-serif;
  font-size: 16px;
  font-weight: 400;
}
```

---

### `font-family`

`font-family` задаёт **семейство шрифтов**, которым должен отображаться текст.

Например:

```css
body {
  font-family: "Inter", Arial, sans-serif;
}
```

Значения перечисляются по приоритету:

```text
1. Inter
2. Arial
3. любой доступный sans-serif
```

Браузер проверяет список по порядку и выбирает подходящий шрифт.

Важно:

> Выбор может происходить даже отдельно для конкретных символов.

Например, если основной шрифт существует, но в нём нет нужного символа, браузер может взять этот символ из следующего шрифта в списке.

---

### `font-size`

`font-size` задаёт **размер текста**.

Например:

```css
p {
  font-size: 16px;
}
```

или:

```css
h1 {
  font-size: 3rem;
}
```

Можно использовать разные единицы:

```text
px
rem
em
%
vw
clamp(...)
```

Например:

```css
.title {
  font-size: clamp(2rem, 4vw, 4rem);
}
```

---

### `font-weight`

`font-weight` задаёт **насыщенность шрифта** — насколько тонкими или жирными выглядят его штрихи.

Например:

```css
.text {
  font-weight: 400;
}
```

Распространённые значения:

```text
100 → очень тонкий
200
300 → light
400 → normal
500 → medium
600
700 → bold
800
900 → очень жирный
```

Ключевые слова:

```css
font-weight: normal;
font-weight: bold;
font-weight: lighter;
font-weight: bolder;
```

Обычно:

```text
normal ≈ 400
bold   ≈ 700
```

---

### Современный нюанс

В современных спецификациях `font-weight` не ограничен только шагами:

```text
100
200
...
900
```

Допустимы числовые значения в более широком диапазоне, а переменные шрифты могут поддерживать промежуточные значения.

Например:

```css
.title {
  font-weight: 537;
}
```

будет иметь смысл, если конкретный переменный шрифт поддерживает такую ось насыщенности.

---

### Главное

```text
font-family
→ какой шрифт использовать

font-size
→ какого размера текст

font-weight
→ насколько жирный или тонкий текст
```

---

## 2. Что такое Fallback Fonts?

**Fallback Fonts (резервные шрифты)** — шрифты, которые браузер использует, если основной шрифт недоступен или не содержит нужного символа.

Например:

```css
body {
  font-family:
    "Inter",
    "Helvetica Neue",
    Arial,
    sans-serif;
}
```

Браузер идёт по списку:

```text
Inter
↓
Helvetica Neue
↓
Arial
↓
sans-serif
```

Если `Inter` доступен:

```text
используется Inter
```

Если нет:

```text
проверяется Helvetica Neue
```

и так далее.

---

### Generic Font Family

В конце списка обычно указывают **общее семейство шрифтов**.

Например:

```text
serif
sans-serif
monospace
cursive
fantasy
system-ui
```

Пример:

```css
font-family: "Roboto", Arial, sans-serif;
```

Если ни `Roboto`, ни `Arial` недоступны, браузер выберет системный шрифт без засечек.

MDN рекомендует включать хотя бы одно общее семейство в конце списка, потому что конкретный шрифт нельзя гарантировать на каждом устройстве.

---

### Почему fallback важен даже при Web Font?

Даже если шрифт загружается с сайта:

```css
@font-face {
  ...
}
```

он может:

```text
ещё загружаться
не загрузиться из-за сети
быть заблокирован
не содержать нужный символ
```

Поэтому:

```css
body {
  font-family: "MyFont", Arial, sans-serif;
}
```

надёжнее, чем:

```css
body {
  font-family: "MyFont";
}
```

---

### Fallback влияет на Layout

Разные шрифты имеют разные:

```text
ширины символов
высоту букв
метрики
межстрочные расстояния
```

Поэтому при переключении:

```text
fallback
↓
web font
```

текст может немного изменить размер и вызвать сдвиг макета.

По этой причине при выборе резервного шрифта желательно подбирать вариант с похожими метриками.

---

## 3. Что такое Web Fonts?

**Web Fonts (веб-шрифты)** — шрифты, которые браузер может загрузить специально для конкретного сайта.

Они не обязаны быть заранее установлены у пользователя.

Например:

```text
шрифт лежит на сервере сайта
↓
браузер загружает файл
↓
использует его для текста
```

---

### Без Web Fonts

Если написать:

```css
body {
  font-family: Arial;
}
```

браузеру нужен Arial на устройстве пользователя.

---

### С Web Font

Можно подключить собственный файл:

```css
@font-face {
  font-family: "MyFont";
  src: url("/fonts/my-font.woff2") format("woff2");
}
```

После этого:

```css
body {
  font-family: "MyFont", sans-serif;
}
```

---

### Популярный современный формат

Для веба обычно предпочтителен:

```text
WOFF2
```

Он специально предназначен для использования шрифтов в вебе и хорошо сжат.

---

### Один шрифт может иметь несколько файлов

Например:

```text
Regular
Medium
Bold
Italic
```

Если это отдельные статические файлы, для каждого начертания обычно создаётся свой `@font-face`.

Например:

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
}

@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-bold.woff2") format("woff2");
  font-weight: 700;
  font-style: normal;
}
```

Браузер затем сам выбирает нужный файл по:

```css
font-weight
font-style
```

---

### Variable Fonts

Современные переменные шрифты могут содержать множество вариантов в одном файле.

Например:

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-variable.woff2") format("woff2");
  font-weight: 100 900;
}
```

Теперь один файл может покрывать диапазон насыщенности.

---

## 4. Как подключить шрифт через `@font-face`?

`@font-face` позволяет зарегистрировать шрифт в CSS.

Пример:

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
```

После этого:

```css 
body {
  font-family: "Inter", Arial, sans-serif;
}
```

---

### `font-family`

Внутри:

```css 
@font-face {
  font-family: "Inter";
}
```

мы задаём имя, под которым будем использовать этот шрифт в CSS.

Затем:

```css
font-family: "Inter";
```

связывается именно с этим `@font-face`.

---

### `src`

```css 
src: url("/fonts/inter-regular.woff2") format("woff2");
```

указывает:

```text
где находится файл
+
какого он формата
```

---

### `font-weight`

```css
font-weight: 400;
```

говорит браузеру:

> Этот конкретный файл соответствует весу 400.

---

### `font-style`

```css
font-style: normal;
```

или:

```css
font-style: italic;
```

описывает начертание файла.

---

### Несколько начертаний

Например:

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-medium.woff2") format("woff2");
  font-weight: 500;
  font-style: normal;
  font-display: swap;
}

@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-bold.woff2") format("woff2");
  font-weight: 700;
  font-style: normal;
  font-display: swap;
}
```

Теперь:

```css
.title {
  font-weight: 700;
}
```

может использовать именно `inter-bold.woff2`.

---

### Почему не нужно давать каждому файлу новое family-name?

Не обязательно писать:

```text
Inter Regular
Inter Medium
Inter Bold
```

Лучше объединять их в одно семейство:

```text
Inter
```

и различать через:

```text
font-weight
font-style
```

Это соответствует модели выбора шрифтов CSS.

---

### Современный базовый вариант

```css
@font-face {
  font-family: "MyFont";
  src: url("/fonts/my-font.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
```

## 5. Что такое FOIT и FOUT?

FOIT и FOUT описывают, что пользователь может увидеть **пока Web Font загружается**.

---

### FOIT

**FOIT — Flash of Invisible Text**.

Упрощённо:

> Текст уже существует на странице, но некоторое время остаётся невидимым, пока браузер ждёт основной шрифт.

Схема:

```text
страница загрузилась

текст:
[невидим]

↓ web font загрузился

текст:
Hello world
```

Это может быть неприятно, потому что пользователь не может читать содержимое во время загрузки шрифта.

---

### FOUT

**FOUT — Flash of Unstyled Text**.

В контексте веб-шрифтов точнее думать так:

> Сначала текст показывается резервным шрифтом, а затем переключается на Web Font.

Например:

```text
Arial
↓
Inter
```

Пользователь видит текст сразу, но его внешний вид может измениться после загрузки основного шрифта.

---

### Почему может произойти сдвиг?

Например:

```text
fallback font:
Hello World

web font:
Hello World
```

у этих двух шрифтов могут отличаться:

```text
ширина букв
высота
метрики строк
```

Поэтому после замены шрифта элементы страницы могут немного сдвинуться.

---

### Три периода загрузки шрифта

Современная модель `font-display` рассматривает загрузку через три периода:

```text
block period
↓
swap period
↓
failure period
```

Во время периода блокировки браузер может использовать невидимый резервный шрифт.

Во время периода замены — показывает fallback и может заменить его на загруженный шрифт.

После периода отказа браузер считает загрузку неуспешной и оставляет fallback.

---

### Главное

```text
FOIT
→ временно невидимый текст
```

```text
FOUT
→ сначала fallback
→ затем web font
```

---

## 6. Что делает `font-display`?

`font-display` управляет тем, **как браузер показывает текст во время загрузки Web Font**.

Используется внутри:

```css
@font-face
```

Например:

```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter.woff2") format("woff2");
  font-display: swap;
}
```

Основные значения:

```css
auto
block
swap
fallback
optional
```

---

### `auto`

```css
font-display: auto;
```

Браузер самостоятельно выбирает стратегию отображения.

Это начальное значение.

---

### `block`

```css
font-display: block;
```

Даёт шрифту короткий период блокировки.

В это время текст может быть невидим.

Если шрифт не успел загрузиться, браузер переходит на fallback.

После этого, если Web Font позже загрузится, он всё ещё может заменить fallback.

Упрощённо:

```text
короткое ожидание
→ возможен FOIT

потом fallback

потом web font,
если загрузился
```

---

### `swap`

```css
font-display: swap;
```

Период невидимого текста минимален.

Браузер почти сразу показывает fallback.

Когда Web Font загрузится:

```text
fallback
↓
web font
```

происходит замена.

То есть:

```text
текст виден быстро
+
возможен FOUT
```

---

### `fallback`

```css
font-display: fallback;
```

Имеет очень короткий период блокировки и ограниченный период, в течение которого Web Font разрешено заменить fallback.

Если шрифт загрузился слишком поздно:

```text
fallback остаётся
```

---

### `optional`

```css
font-display: optional;
```

Даёт очень короткую возможность загрузить шрифт и не предусматривает обычного длительного периода замены.

Если шрифт не успел:

```text
страница может остаться на fallback
```

Это может быть полезно, когда скорость и стабильность отображения важнее обязательного использования фирменного шрифта.

---

### Сравнение

| Значение | Что происходит |
|---|---|
| `auto` | стратегию выбирает браузер |
| `block` | короткое ожидание невидимого текста, потом возможна замена |
| `swap` | fallback показывается почти сразу, Web Font заменяет его после загрузки |
| `fallback` | короткий шанс на замену, затем fallback может остаться |
| `optional` | Web Font используется только если успел достаточно быстро |

Точные длительности периодов могут немного различаться между браузерами. Спецификация сознательно допускает такую свободу.

---

### Практический вариант

Очень часто используют:

```css
font-display: swap;
```

потому что текст становится доступен пользователю почти сразу.

Но универсального значения «лучше для всех случаев» нет.

---

## 7. Чем `line-height` отличается от `font-size`?

`font-size` и `line-height` связаны, но отвечают за разные вещи.

---

### `font-size`

```css
p {
  font-size: 16px;
}
```

задаёт размер шрифта.

Упрощённо:

```text
font-size
→ размер символов
```

---

### `line-height`

```css
p {
  line-height: 24px;
}
```

задаёт высоту строки текста.

То есть:

```text
line-height
→ пространство,
  выделенное под одну строку
```

MDN точнее определяет `line-height` как высоту line box в горизонтальном режиме письма.

---

### Пример

```css
p {
  font-size: 16px;
  line-height: 24px;
}
```

Текст имеет размер:

```text
16px
```

а каждая строка получает высоту:

```text
24px
```

Схематично:

```text
┌──────────────────────┐
│ Text line            │ ← 24px line-height
└──────────────────────┘
┌──────────────────────┐
│ Next line            │
└──────────────────────┘
```

---

### `line-height` — не просто «отступ между строками»

Это распространённое упрощение.

Нельзя точно сказать:

```text
24px - 16px = 8px
→ значит между строками всегда ровно 8px
```

Потому что на фактическое положение букв влияют метрики самого шрифта.

Правильнее:

> `line-height` задаёт высоту строкового бокса, внутри которого размещается текст.

---

### Пример с коэффициентом

```css
p {
  font-size: 16px;
  line-height: 1.5;
}
```

Результирующая высота строки:

```text
16 × 1.5
=
24px
```

---

### Главное

```text
font-size
→ размер шрифта

line-height
→ высота строки
```

---

## 8. Почему для `line-height` часто используют значение без единицы?

Для `line-height` можно написать:

```css
line-height: 1.5;
```

Это означает:

> Высота строки равна `font-size × 1.5`.

Например:

```css
p {
  font-size: 20px;
  line-height: 1.5;
}
```

получаем:

```text
20px × 1.5
=
30px
```

---

### Почему это удобно?

Главная причина — **наследование**.

Допустим:

```css
body {
  line-height: 1.5;
}
```

Дочерний элемент:

```css
h1 {
  font-size: 40px;
}
```

получает тот же коэффициент:

```text
40px × 1.5
=
60px
```

То есть каждый элемент рассчитывает `line-height` относительно **своего собственного `font-size`**.

---

### Сравним с `em`

Например:

```css
body {
  font-size: 16px;
  line-height: 1.5em;
}
```

На родителе:

```text
1.5 × 16px
=
24px
```

Это значение может быть вычислено как конкретная длина и затем унаследовано.

Если ребёнок имеет:

```css
h1 {
  font-size: 40px;
}
```

он может получить всё те же:

```text
24px
```

что уже слишком мало для текста `40px`.

---

### Безразмерное значение

```css
line-height: 1.5;
```

наследует именно коэффициент.

Поэтому:

```text
body 16px
→ 24px line-height

h1 40px
→ 60px line-height
```

Это делает типографику гораздо более устойчивой.

MDN прямо рекомендует безразмерное значение как наиболее удобный вариант для наследования.

---

### Практический пример

```css
body {
  line-height: 1.5;
}
```

часто является хорошей базой.

Но конкретное значение зависит от:

```text
шрифта
размера текста
назначения текста
дизайна
```

---

## 9. Что делает `letter-spacing`?

`letter-spacing` управляет дополнительным расстоянием **между символами текста**.

Например:

```css
.title {
  letter-spacing: 2px;
}
```

Текст станет более разреженным.

Условно:

```text
TEXT
```

превращается визуально ближе к:

```text
T E X T
```

---

### Начальное значение

```css
letter-spacing: normal;
```

означает стандартное расстояние, определяемое шрифтом и алгоритмом браузера.

---

### Положительное значение

```css
letter-spacing: 0.1em;
```

увеличивает расстояние.

---

### Отрицательное значение

```css
letter-spacing: -0.02em;
```

уменьшает расстояние между символами.

---

### Частый пример

Для заголовков заглавными буквами:

```css
.label {
  text-transform: uppercase;
  letter-spacing: 0.08em;
}
```

Такое увеличение часто улучшает визуальное восприятие короткого текста в верхнем регистре.

---

### Единицы

Можно использовать, например:

```text
px
em
rem
```

Для типографики часто удобно:

```css
letter-spacing: 0.05em;
```

потому что расстояние будет масштабироваться вместе со шрифтом.

---

### Осторожно с большими значениями

Слишком большое:

```css
letter-spacing: 10px;
```

или слишком сильное отрицательное значение может ухудшить читаемость.

---

## 10. Что делает `text-align`?

`text-align` определяет, как **строчное содержимое** выравнивается внутри своего контейнера.

Например:

```css
p {
  text-align: center;
}
```

Текст внутри `<p>` будет центрирован.

---

### `start`

```css
text-align: start;
```

Выравнивает текст по началу направления письма.

Для:

```text
LTR
```

это обычно слева.

Для:

```text
RTL
```

обычно справа.

Это делает `start` удобным для интерфейсов с разными языками.

---

### `end`

```css
text-align: end;
```

выравнивает по концу направления текста.

---

### `left`

```css
text-align: left;
```

по левому краю.

---

### `right`

```css
text-align: right;
```

по правому краю.

---

### `center`

```css 
text-align: center;
```

по центру.

---

### `justify`

```css
text-align: justify;
```

растягивает строки так, чтобы они заполняли доступную ширину.

Условно:

```text
|Text   text   text|
|More  text   here|
```

При этом обычно изменяются промежутки между словами.

Использовать `justify` нужно осторожно: слишком неравномерные промежутки могут ухудшить читаемость, особенно для некоторых пользователей.

---

### Важно: `text-align` не центрирует сам блок

Например:

```css
.box {
  width: 300px;
  text-align: center;
}
```

центрируется содержимое внутри `.box`.

Но сам `.box` не перемещается в центр родителя.

Для самого блока понадобятся другие механизмы:

```text
margin-inline: auto
Flexbox
Grid
```

---

## 11. Что делает `text-transform`?

`text-transform` изменяет **визуальное представление регистра текста**.

Например:

```css
.title {
  text-transform: uppercase;
}
```

HTML:

```html
<h1>Hello world</h1>
```

визуально станет:

```text
HELLO WORLD
```

---

### `none`

```css
text-transform: none;
```

не применяет преобразование.

---

### `uppercase`

```css
text-transform: uppercase;
```

переводит текст визуально в верхний регистр.

---

### `lowercase`

```css 
text-transform: lowercase;
```

например:

```text
HELLO
↓
hello
```

---

### `capitalize`

```css
text-transform: capitalize;
```

преобразует начальные буквы слов.

Например:

```text
hello world
↓
Hello World
```

---

### Важно

`text-transform` не переписывает сам текст в HTML.

Например:

```html
<p class="text">hello</p>
```

с:

```css
.text {
  text-transform: uppercase;
}
```

в DOM по-прежнему хранится:

```text
hello
```

а браузер визуально показывает:

```text 
HELLO
```

---

### Преобразование зависит от языка

Некоторые языки имеют специальные правила регистра.

Поэтому CSS может учитывать язык текста.

Хорошо указывать корректный язык документа:

```html 
<html lang="ru">
```

или для отдельных фрагментов соответствующий `lang`.

---

### Главное

```text 
text-transform
→ визуально меняет регистр текста
→ исходный текст в DOM не переписывает
```

Основные значения `uppercase`, `lowercase` и `capitalize` остаются стандартной частью CSS Text.

---

## 12. Что делает `text-decoration`?

`text-decoration` управляет декоративными линиями текста.

Например:

```css
a {
  text-decoration: underline;
}
```

---

### Основные виды линий

```css 
text-decoration: underline;
```

подчёркивание.

```css
text-decoration: overline;
```

линия над текстом.

```css 
text-decoration: line-through;
```

зачёркивание.

```css 
text-decoration: none;
```

убирает собственную декорацию.

---

### Это shorthand

Современное:

```css 
text-decoration
```

является сокращением для:

```css 
text-decoration-line
text-decoration-color
text-decoration-style
text-decoration-thickness
```

---

### Пример

```css 
.link {
  text-decoration:
    underline
    wavy
    red
    2px;
}
```

Можно управлять отдельно:

```css 
.link {
  text-decoration-line: underline;
  text-decoration-style: wavy;
  text-decoration-color: red;
  text-decoration-thickness: 2px;
}
```

---

### Стили линии

Например:

```text 
solid
double
dotted
dashed
wavy
```

---

### Ссылки

Браузеры обычно подчёркивают ссылки:

```html 
<a href="/">Home</a>
```

Иногда дизайн убирает подчёркивание:

```css 
a {
  text-decoration: none;
}
```

Но важно не лишить пользователя понятного признака того, что текст является ссылкой.

Если подчёркивание убирается, ссылка должна оставаться узнаваемой за счёт:

```text 
цвета
hover
focus
других визуальных признаков
```

---

### Семантика и оформление

Если текст действительно удалён из документа по смыслу, лучше использовать:

```html 
<del>Old price</del>
```

а не только:

```css 
text-decoration: line-through;
```

CSS отвечает за оформление, а HTML — за смысл. MDN также рекомендует использовать семантические элементы, если зачёркивание имеет смысл удаления текста.

---

## 13. Как работает `text-overflow: ellipsis`?

```css
text-overflow: ellipsis;
```

говорит браузеру:

> Если текст обрезается из-за переполнения, покажи в месте обрезания многоточие.

Например:

```text
Очень длинный текст который...
```

В действительности браузер обычно использует символ:

```text
…
```

а не три отдельные точки.

---

### Но `text-overflow` сам ничего не обрезает

Это очень важно.

Если написать только:

```css
.title {
  text-overflow: ellipsis;
}
```

многоточие обычно не появится.

Нужно, чтобы текст действительно:

```text
не помещался
+
был обрезан
```

---

### Пример

```css
.title {
  width: 200px;

  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

Если текст:

```text
Очень длинное название товара
```

не помещается:

```text
Очень длинное назва…
```

---

### Текст остаётся в DOM

Многоточие — визуальное представление.

Исходный текст не удаляется из HTML.

JavaScript по-прежнему увидит полное содержимое.

---

### `clip`

Начальное значение:

```css
text-overflow: clip;
```

просто обрезает текст без многоточия.

---

## 14. Какие свойства нужны для однострочного Ellipsis?

Классический и надёжный вариант:

```css
.title {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

Также у элемента должно быть **ограничение доступной ширины**, чтобы переполнение вообще могло возникнуть.

Например:

```css
.title {
  width: 250px;

  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

---

### Что делает каждое свойство?

#### `white-space: nowrap`

```css
white-space: nowrap;
```

запрещает обычный перенос текста на новую строку.

Вместо:

```text
Очень длинный
заголовок
```

получаем одну строку:

```text
Очень длинный заголовок
```

---

#### `overflow: hidden`

```css
overflow: hidden;
```

скрывает часть текста, которая выходит за границы.

---

#### `text-overflow: ellipsis`

```css
text-overflow: ellipsis;
```

показывает:

```text
…
```

в месте обрезания.

---

### Flexbox-нюанс

Очень частая ситуация:

```html
<div class="row">
  <div class="content">
    <p class="title">
      Очень длинный заголовок
    </p>
  </div>
</div>
```

```css
.row {
  display: flex;
}

.content {
  flex: 1;
}
```

Иногда ellipsis не работает, потому что flex-элемент не хочет достаточно сжиматься.

Тогда:

```css
.content {
  flex: 1;
  min-width: 0;
}
```

и:

```css
.title {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

Это тот самый случай, который мы уже разбирали в Flexbox.

---

### Главное

Для одной строки:

```css
overflow: hidden;
white-space: nowrap;
text-overflow: ellipsis;
```

плюс ограниченная доступная ширина.

`text-overflow` предназначен именно для обозначения уже обрезанного строчного переполнения.

---

## 15. Как сделать многострочное обрезание текста?

Задача:

```text
показать, например,
только 3 строки

а всё остальное
обрезать
```

---

### Свойство `line-clamp`

Стандартный синтаксис:

```css
.description {
  line-clamp: 3;
  overflow: hidden;
}
```

`line-clamp: 3` означает:

> Ограничить содержимое тремя строками.

---

### Но есть важный нюанс поддержки

На 2026 год стандартный:

```css
line-clamp: 3;
```

всё ещё отмечен MDN как **не полностью Baseline**, то есть поддержка в популярных браузерах ещё не абсолютно единообразна.

Поэтому в реальных проектах всё ещё часто используется старый совместимый паттерн:

```css
.description {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;

  overflow: hidden;
}
```

---

### Что здесь происходит?

```css
-webkit-line-clamp: 3;
```

ограничивает количество строк.

```css
-webkit-box-orient: vertical;
```

задаёт вертикальное направление старой box-модели, необходимое для этого совместимого механизма.

```css
overflow: hidden;
```

скрывает всё после нужного количества строк.

---

### Почему используются устаревшие `-webkit-*` свойства?

Это необычная ситуация.

Хотя:

```css
display: -webkit-box;
-webkit-box-orient: vertical;
```

относятся к старому механизму, их сочетание с:

```css
-webkit-line-clamp
```

формализовано и продолжает поддерживаться ради совместимости. MDN прямо отмечает эту зависимость.

---

### Практический вариант

Если проекту нужна широкая совместимость:

```css
.description {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;

  overflow: hidden;
}
```

---

### В будущем

По мере расширения поддержки можно ориентироваться на стандартный:

```css
line-clamp: 3;
```

Но на 2026 год при production-разработке совместимость ещё нужно проверять.

---

## 16. Что делают `white-space`, `word-break`, `overflow-wrap`?

Эти свойства управляют **переносами текста**, но решают разные задачи.

---

### `white-space`

`white-space` управляет двумя основными вещами:

```text 
как обрабатываются пробелы и переносы в исходном тексте

+

разрешён ли автоматический перенос строк
```

В современном CSS `white-space` фактически является shorthand для более низкоуровневых свойств обработки пробелов и переноса строк.

---

#### `white-space: normal`

```css
white-space: normal;
```

обычное поведение текста.

Несколько пробелов в HTML схлопываются:

```html
Hello     world
```

визуально:

```text
Hello world
```

Текст переносится на новые строки при необходимости.

---

#### `white-space: nowrap`

```css 
white-space: nowrap;
```

пробелы обычно схлопываются, но автоматический перенос строки запрещён.

Например:

```text
This text does not wrap and can overflow →
```

Часто используется для однострочного ellipsis.

---

#### `white-space: pre`

```css
white-space: pre;
```

сохраняет пробелы и переносы примерно так, как они написаны в исходном тексте.

Например:

```html 
<div>
Hello     world
Second line
</div>
```

может сохранять исходное форматирование.

При этом обычного переноса по ширине контейнера нет.

Поведение похоже на:

```html
<pre>
```

---

#### `white-space: pre-wrap`

```css 
white-space: pre-wrap;
```

сохраняет:

```text 
пробелы
переносы строк
```

но при этом позволяет тексту дополнительно переноситься по ширине контейнера.

---

#### `white-space: pre-line`

```css 
white-space: pre-line;
```

сохраняет явные переводы строк, но последовательности обычных пробелов схлопывает.

---

#### `break-spaces`

Современное значение:

```css
white-space: break-spaces;
```

во многом похоже на `pre-wrap`, но сохраняет пробельные последовательности ещё строже и предоставляет больше возможностей переноса вокруг сохранённых пробелов.

Для большинства базовых задач достаточно сначала хорошо понимать:

```text 
normal
nowrap
pre
pre-wrap
pre-line
```

---

### `word-break`

`word-break` определяет, **где браузеру разрешено разрывать слова при переносе строк**.

---

#### `normal`

```css
word-break: normal;
```

используются обычные языковые правила переноса.

---

#### `break-all`

```css
word-break: break-all;
```

позволяет разрывать слово практически между любыми символами, чтобы избежать переполнения.

Например:

```text
Supercalifragilisticexpialidocious
```

может стать:

```text 
Supercalif
ragilistic
expialid...
```

даже если слово можно было бы целиком перенести на следующую строку.

Поэтому `break-all` довольно агрессивен.

---

#### `keep-all`

```css
word-break: keep-all;
```

в первую очередь влияет на правила переноса CJK-языков:

```text
Chinese
Japanese
Korean
```

Для обычного латинского текста его поведение похоже на `normal`.

---

#### `auto-phrase`

Современный CSS также описывает:

```css
word-break: auto-phrase;
```

Он пытается учитывать языковые фразы и не ставить разрывы в неудачных местах.

Но это значение на 2026 год всё ещё относится к более новым возможностям и не должно восприниматься как универсально доступный базовый инструмент.

---

#### `word-break: break-word`

Такое значение можно встретить в старом коде:

```css
word-break: break-word;
```

Но оно считается устаревшим.

Для современных решений лучше понимать:

```css 
overflow-wrap: anywhere;
```

---

### `overflow-wrap`

`overflow-wrap` определяет, может ли браузер **сломать слишком длинную непрерывную строку**, чтобы она не вышла за границы контейнера.

Например:

```text
https://veryveryveryveryverylongurl.example.com
```

может не иметь удобных мест переноса.

---

#### `normal`

```css
overflow-wrap: normal;
```

используются обычные возможности переноса.

---

#### `anywhere`

```css 
overflow-wrap: anywhere;
```

если слово или URL иначе переполнит контейнер, браузер может перенести его практически в любом подходящем месте.

Например:

```text 
veryveryveryverylongword
```

может разбиться:

```text 
veryveryvery
verylongword
```

Это одно из наиболее удобных решений для защиты адаптивного интерфейса от длинных строк.

---

#### `break-word`

По визуальному поведению он похож на `anywhere`, но есть техническая разница в расчёте минимального размера содержимого.

Для современного layout чаще понятнее использовать:

```css
overflow-wrap: anywhere;
```

---

#### `word-wrap`

Можно встретить:

```css 
word-wrap: break-word;
```

`word-wrap` — старое название свойства.

Сегодня:

```text 
word-wrap
→ alias для overflow-wrap
```

То есть современное основное имя:

```css 
overflow-wrap
```

---

### Главное различие трёх свойств

```text 
white-space
→ общие правила пробелов
  и переноса строк
```

```text 
word-break
→ где разрешено разрывать слова
```

```text 
overflow-wrap
→ можно ли разорвать
  слишком длинную строку,
  чтобы избежать overflow
```

---

### Практический пример

Для обычного текста:

```css 
.text {
  white-space: normal;
  overflow-wrap: anywhere;
}
```

Так:

```text 
обычные слова
→ переносятся нормально

слишком длинное слово или URL
→ может быть разорвано
```

---

### Когда использовать `word-break: break-all`?

Обычно только если действительно нужно агрессивно разрешить разрыв практически между любыми символами.

Для обычного текста чаще предпочтительнее:

```css 
overflow-wrap: anywhere;
```

потому что он вмешивается прежде всего тогда, когда без разрыва возникло бы переполнение.
