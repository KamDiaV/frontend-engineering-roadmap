# X. Responsive Design

## 1. Что такое Responsive Design?

**Responsive Design (адаптивный дизайн)** — подход к созданию сайтов и приложений, при котором интерфейс автоматически подстраивается под разные размеры экрана, разрешения и условия использования.

Главная цель:

> один сайт должен оставаться удобным и читаемым на телефоне, планшете, ноутбуке и большом мониторе.

Например, на широком экране сайт может выглядеть так:

```text
┌──────────────────────────────────────┐
│ Header                               │
├───────────┬──────────────────────────┤
│ Sidebar   │ Main                     │
│           │                          │
└───────────┴──────────────────────────┘
```

А на узком:

```text
┌──────────────────┐
│ Header           │
├──────────────────┤
│ Main             │
│                  │
├──────────────────┤
│ Sidebar          │
└──────────────────┘
```

То есть содержимое остаётся тем же, но его расположение и размеры меняются.

---

### Адаптивный дизайн — это не одна технология

Он создаётся с помощью комбинации инструментов:

```text
гибкие размеры
+
Flexbox
+
Grid
+
относительные единицы
+
media queries
+
container queries
+
адаптивные изображения
+
адаптивная типографика
```

Например:

```css
.container {
  width: min(100% - 2rem, 1200px);
  margin-inline: auto;
}
```

Контейнер:

- уменьшается вместе с экраном;
- оставляет отступы по краям;
- не становится шире `1200px`.

При этом здесь вообще не используется `@media`.

Это важный принцип современного адаптивного дизайна:

> Media queries полезны, но не каждое изменение размера должно требовать breakpoint.

Современные Flexbox, Grid, `min()`, `max()`, `clamp()` и относительные единицы сами по себе позволяют создавать много гибкого поведения.

---

### Важный элемент для мобильных устройств

Обычно в HTML должен присутствовать:

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1"
/>
```

Он сообщает мобильному браузеру, что ширина области просмотра должна соответствовать ширине устройства.

Без корректной настройки viewport адаптивные стили на мобильных устройствах могут работать не так, как ожидается.

---

### Главное

```text
Responsive Design
=
интерфейс адаптируется
к доступному пространству
и условиям использования
```

---

## 2. Что такое Mobile First?

**Mobile First** — подход к адаптивной разработке, при котором сначала создаются базовые стили для узкого экрана, а затем интерфейс постепенно усложняется для более широких экранов.

Например:

```css
.cards {
  display: grid;
  grid-template-columns: 1fr;
}
```

Это базовый вариант:

```text
телефон

┌─────────────┐
│ Card        │
├─────────────┤
│ Card        │
├─────────────┤
│ Card        │
└─────────────┘
```

Затем при увеличении ширины:

```css
@media (min-width: 48rem) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

получаем:

```text
планшет / более широкий экран

┌──────────┬──────────┐
│ Card     │ Card     │
├──────────┼──────────┤
│ Card     │ Card     │
└──────────┴──────────┘
```

А ещё шире:

```css
@media (min-width: 64rem) {
  .cards {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

```text
┌────────┬────────┬────────┐
│ Card   │ Card   │ Card   │
└────────┴────────┴────────┘
```

---

### Логика Mobile First

```text
сначала
→ простая версия для маленькой ширины

затем
→ добавляем возможности
  по мере появления пространства
```

Чаще всего Mobile First использует:

```css
min-width
```

Например:

```css
@media (min-width: 48rem) {
  ...
}

@media (min-width: 64rem) {
  ...
}
```

---

### Почему этот подход удобен?

На узком экране интерфейс обычно проще:

```text
одна колонка
короткая навигация
меньшие отступы
компактные компоненты
```

Поэтому удобно сначала построить простую основу, а затем расширять её.

MDN описывает Mobile First именно как подход, в котором базовый узкий макет создаётся первым, а более сложная раскладка добавляется для широких экранов.

---

## 3. Чем Mobile First отличается от Desktop First?

Разница заключается в том, **с какого состояния интерфейса начинается разработка**.

---

### Mobile First

Сначала стили для узких экранов:

```css
.menu {
  display: none;
}
```

Затем для более широких:

```css
@media (min-width: 48rem) {
  .menu {
    display: flex;
  }
}
```

Логика:

```text
маленький экран
↓
средний
↓
большой
```

---

### Desktop First

Сначала создаётся широкая версия:

```css
.menu {
  display: flex;
}
```

А затем интерфейс упрощается:

```css
@media (max-width: 48rem) {
  .menu {
    display: none;
  }
}
```

Логика:

```text
большой экран
↓
средний
↓
маленький
```

---

### Сравнение

| Подход | Базовые стили | Чаще используется |
|---|---|---|
| Mobile First | Для узких экранов | `min-width` |
| Desktop First | Для широких экранов | `max-width` |

---

### Важно

Это не означает:

```text
Mobile First = всегда правильно

Desktop First = всегда неправильно
```

Оба подхода допустимы.

Однако Mobile First часто удобен для современных адаптивных интерфейсов, потому что позволяет начинать с простой структуры и постепенно добавлять сложность.

---

### Главное

```text
Mobile First

база
→ маленький экран

@media min-width
→ расширяем интерфейс
```

```text
Desktop First

база
→ большой экран

@media max-width
→ упрощаем интерфейс
```

---

## 4. Что такое Media Query?

**Media Query (медиазапрос)** — условие, которое позволяет применять CSS только тогда, когда характеристики среды соответствуют заданным требованиям.

Например:

```css
@media (min-width: 768px) {
  .container {
    display: grid;
  }
}
```

Означает:

> Применить этот CSS, если ширина области просмотра не меньше `768px`.

---

### Media Query может проверять не только ширину

Например:

```css
@media (orientation: landscape) {
  ...
}
```

проверяет ориентацию.

---

Можно проверить возможность наведения:

```css
@media (hover: hover) {
  ...
}
```

---

Можно учитывать предпочтение пользователя уменьшить анимации:

```css
@media (prefers-reduced-motion: reduce) {
  ...
}
```

---

Можно учитывать цветовую тему:

```css
@media (prefers-color-scheme: dark) {
  ...
}
```

---

### Поэтому Media Query — это не только адаптивная ширина

Он может проверять:

```text
ширину
высоту
ориентацию
разрешение
возможность hover
тип указателя
цветовую тему
предпочтение уменьшенных анимаций
и другие характеристики среды
```

Media queries являются механизмом условного применения CSS в зависимости от характеристик браузера, области просмотра и устройства.

---

## 5. Как работает `@media`?

`@media` — CSS at-rule, внутри которого размещаются стили, применяемые только при выполнении определённого media query.

Например:

```css
.card {
  padding: 16px;
}

@media (min-width: 768px) {
  .card {
    padding: 32px;
  }
}
```

---

### Что делает браузер?

Сначала:

```text
ширина < 768px
```

работает:

```css
.card {
  padding: 16px;
}
```

Когда условие становится истинным:

```text
ширина >= 768px
```

добавляется:

```css
.card {
  padding: 32px;
}
```

И благодаря каскаду более позднее правило переопределяет предыдущее.

---

### Несколько условий

Можно использовать:

```css
@media (min-width: 48rem) and (max-width: 80rem) {
  ...
}
```

Это означает:

```text
ширина >= 48rem
И
ширина <= 80rem
```

---

### Современный синтаксис диапазонов

Современный CSS также позволяет писать:

```css
@media (width >= 48rem) {
  ...
}
```

вместо:

```css
@media (min-width: 48rem) {
  ...
}
```

И:

```css
@media (width <= 80rem) {
  ...
}
```

вместо:

```css
@media (max-width: 80rem) {
  ...
}
```

Можно даже задавать диапазон:

```css
@media (48rem <= width <= 80rem) {
  ...
}
```

---

### Несколько media queries

Например:

```css
@media (min-width: 40rem) {
  ...
}

@media (min-width: 64rem) {
  ...
}

@media (min-width: 80rem) {
  ...
}
```

При большой ширине одновременно могут быть истинными несколько условий.

Например:

```text
viewport = 90rem
```

Тогда истинны:

```text
>= 40rem
>= 64rem
>= 80rem
```

И итог определяется обычным CSS Cascade.

---

### Главное

```text
@media
→ условный блок CSS

условие true
→ стили применяются

условие false
→ стили не применяются
```

---

## 6. Что такое Breakpoint?

**Breakpoint (контрольная точка адаптива)** — значение, при котором интерфейсу требуется изменить раскладку или стили.

Например:

```css
@media (min-width: 48rem) {
  ...
}
```

Здесь:

```text
48rem
```

является breakpoint.

---

### Что происходит в этой точке?

Допустим, карточки сначала располагаются:

```text
Card
Card
Card
```

Но при увеличении ширины появляется достаточно места для двух колонок.

Тогда вводится:

```css
@media (min-width: 48rem) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

Breakpoint означает:

> С этого размера текущая раскладка может измениться.

---

### Breakpoint может менять не только количество колонок

Например:

```text
навигацию
отступы
размеры текста
расположение элементов
видимость некоторых элементов
размеры сетки
```

---

### Главное

```text
Breakpoint
=
точка, в которой дизайн
требует изменения
```

MDN определяет breakpoints именно как точки, в которых вводятся media queries и изменяется раскладка.

---

## 7. Как выбирать Breakpoints?

Breakpoint следует выбирать **по поведению содержимого и макета**, а не просто по популярным размерам телефонов.

Допустим:

```css
.cards {
  grid-template-columns: repeat(3, 1fr);
}
```

При уменьшении окна карточки становятся слишком узкими:

```text
┌──┬──┬──┐
│A │B │C │
└──┴──┴──┘
```

В этот момент дизайн начинает выглядеть плохо.

Именно здесь стоит изменить сетку:

```css
@media (max-width: 60rem) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

---

### Практический алгоритм

Сначала создаём интерфейс.

Затем постепенно уменьшаем или увеличиваем ширину браузера.

Смотрим:

```text
текст начинает плохо помещаться?

навигация ломается?

карточки становятся слишком узкими?

слишком большие пустые пространства?

элементы начинают перекрываться?
```

Когда дизайн перестаёт работать хорошо:

```text
↓
нужен breakpoint
```

---

### Breakpoint не обязан быть красивым числом

Например, дизайн ломается на:

```text
53rem
```

Нет необходимости обязательно выбирать:

```text
768px
1024px
1440px
```

только потому, что эти размеры часто встречаются.

---

### Относительные единицы

Для media queries часто удобно использовать:

```text
em
rem
```

например:

```css
@media (min-width: 48rem) {
  ...
}
```

MDN рекомендует ориентироваться на потребности макета и использовать относительные единицы вместо жёсткой привязки к размеру конкретного устройства.

---

## 8. Почему не стоит ориентироваться только на конкретные устройства?

Потому что размеров экранов огромное количество.

Например:

```text
маленький телефон
большой телефон
планшет
планшет горизонтально
ноутбук
монитор
ультраширокий монитор
окно браузера не на весь экран
split screen
```

Даже один и тот же ноутбук может иметь окно браузера:

```text
1400px
```

или:

```text
700px
```

если пользователь разместил два окна рядом.

---

### Проблема подхода «под iPhone»

Например:

```css
@media (max-width: 390px) {
  ...
}
```

потому что:

> У определённого телефона ширина 390px.

Такой breakpoint ничего не говорит о том, **почему дизайн должен измениться именно здесь**.

На другом устройстве с:

```text
400px
430px
500px
```

интерфейс тоже должен оставаться нормальным.

---

### Лучше спрашивать

Не:

> Какой сейчас размер iPhone?

А:

> На какой ширине этот компонент перестаёт хорошо выглядеть?

---

### Современный принцип

```text
breakpoints
→ определяет содержимое

а не
→ каталог устройств
```

Это делает дизайн устойчивее к новым устройствам и необычным размерам окон. MDN также рекомендует не строить адаптивность вокруг абсолютных размеров конкретных устройств.

---

## 9. Что означает `min-width` в Media Query?

Например:

```css
@media (min-width: 768px) {
  ...
}
```

означает:

> Применить стили, если ширина области просмотра **не меньше 768px**.

То есть:

```text
width >= 768px
```

---

### Пример

```css
.card {
  padding: 16px;
}

@media (min-width: 768px) {
  .card {
    padding: 32px;
  }
}
```

При:

```text
500px
```

используется:

```text
16px
```

При:

```text
768px
```

используется:

```text
32px
```

При:

```text
1200px
```

тоже:

```text
32px
```

---

### Современная запись

То же самое можно записать:

```css
@media (width >= 768px) {
  ...
}
```

---

### Связь с Mobile First

`min-width` особенно часто встречается в Mobile First.

Например:

```css
/* базовые стили */

@media (min-width: 48rem) {
  /* более широкий экран */
}

@media (min-width: 64rem) {
  /* ещё более широкий */
}
```

Логика:

```text
начинаем с маленькой ширины
↓
расширяем интерфейс
```

---

## 10. Что означает `max-width` в Media Query?

Например:

```css
@media (max-width: 768px) {
  ...
}
```

означает:

> Применить стили, если ширина области просмотра **не больше 768px**.

То есть:

```text
width <= 768px
```

---

### Пример

```css
.navigation {
  display: flex;
}

@media (max-width: 768px) {
  .navigation {
    display: none;
  }
}
```

На широком экране:

```text
navigation видна
```

На экране `768px` или меньше:

```text
navigation скрывается
```

---

### Современная запись

То же условие можно записать:

```css
@media (width <= 768px) {
  ...
}
```

---

### Связь с Desktop First

`max-width` часто используется при подходе Desktop First:

```text
базовый desktop
↓
max-width
↓
упрощаем интерфейс
```

---

### `min-width` и `max-width`

```text
min-width: 48rem
→ начиная с 48rem и шире
```

```text
max-width: 48rem
→ до 48rem включительно
```

---

## 11. Что такое Responsive Typography?

**Responsive Typography (адаптивная типографика)** — подход, при котором размеры и параметры текста подстраиваются под доступное пространство и остаются удобными для чтения на разных экранах.

Например, заголовок на телефоне может быть:

```text
32px
```

а на большом мониторе:

```text
64px
```

---

### Простой способ через Media Queries

```css
.title {
  font-size: 2rem;
}

@media (min-width: 64rem) {
  .title {
    font-size: 4rem;
  }
}
```

Получаем:

```text
маленький экран
→ 2rem

большой экран
→ 4rem
```

---

### Но размер может меняться плавно

Например:

```css
.title {
  font-size: clamp(2rem, 5vw, 4rem);
}
```

Теперь размер изменяется постепенно.

---

### Адаптивная типографика — это не только `font-size`

Также важны:

```text
line-height
max-width текста
letter-spacing
отступы
контраст
длина строки
```

Например:

```css
.article {
  max-width: 65ch;
  line-height: 1.6;
}
```

---

### Почему нельзя бездумно использовать только `vw`?

Например:

```css
.title {
  font-size: 5vw;
}
```

Размер полностью привязан к viewport.

Это может привести к проблемам с масштабированием текста и сделать размер слишком маленьким или слишком большим.

Поэтому предпочтительнее ограничивать диапазон:

```css
font-size: clamp(2rem, 1rem + 3vw, 4rem);
```

MDN отдельно предупреждает, что viewport-единицы не стоит использовать как единственный компонент размера текста; лучше сочетать их с относительным размером вроде `rem`.

---

## 12. Как использовать `clamp()` для адаптивного размера шрифта?

Функция:

```css
clamp()
```

позволяет задать:

```text
минимальный размер
предпочтительный размер
максимальный размер
```

Синтаксис:

```css
clamp(min, preferred, max)
```

---

### Пример

```css
.title {
  font-size: clamp(2rem, 5vw, 4rem);
}
```

Здесь:

```text
2rem
→ минимум

5vw
→ динамическое значение

4rem
→ максимум
```

---

### Как работает?

Если:

```text
5vw < 2rem
```

используется:

```text
2rem
```

Если:

```text
2rem < 5vw < 4rem
```

используется рассчитанное `5vw`.

Если:

```text
5vw > 4rem
```

используется:

```text
4rem
```

---

### Более удобный вариант для доступности

Часто предпочтительно смешивать `rem` и viewport-единицы:

```css
.title {
  font-size: clamp(
    2rem,
    1rem + 3vw,
    4rem
  );
}
```

Почему?

Потому что:

```text
rem
→ связан с размером шрифта

vw
→ реагирует на ширину viewport
```

Вместе они позволяют получить более гибкое поведение.

---

### Пример поведения

```text
маленькая ширина
→ 2rem

ширина увеличивается
→ размер плавно растёт

очень большой экран
→ максимум 4rem
```

---

### `clamp()` уменьшает количество Media Queries

Вместо:

```css
.title {
  font-size: 2rem;
}

@media (min-width: 48rem) {
  .title {
    font-size: 3rem;
  }
}

@media (min-width: 80rem) {
  .title {
    font-size: 4rem;
  }
}
```

можно иногда написать:

```css
.title {
  font-size: clamp(
    2rem,
    1rem + 3vw,
    4rem
  );
}
```

Это не означает, что `clamp()` полностью заменяет media queries.

Он просто отлично подходит для значений, которые должны **плавно изменяться в диапазоне**. `clamp()` именно для этого принимает минимум, предпочтительное значение и максимум.

---

## 13. Как делать адаптивные изображения с помощью CSS?

Базовый вариант:

```css
img {
  max-width: 100%;
  height: auto;
}
```

---

### Что делает `max-width: 100%`?

Изображение не становится шире своего контейнера.

Например:

```text
контейнер 300px
изображение 800px
```

оно уменьшается:

```text
до 300px
```

и не вызывает горизонтальное переполнение.

---

### Что делает `height: auto`?

Высота рассчитывается автоматически с сохранением естественных пропорций изображения.

То есть изображение не превращается в:

```text
растянутую
или
сплющенную картинку
```

---

### Почему часто используют `max-width`, а не `width`?

Сравним:

```css
img {
  width: 100%;
}
```

Если контейнер шире исходного изображения, браузер может растянуть изображение больше его естественного размера.

А:

```css
img {
  max-width: 100%;
}
```

говорит:

> Уменьшай изображение при необходимости, но не заставляй его становиться шире только из-за контейнера.


---

### Для изображений-карточек

Часто используют:

```css
.card__image {
  width: 100%;
  aspect-ratio: 4 / 3;
  object-fit: cover;
}
```

`aspect-ratio` задаёт область:

```text
4 : 3
```

А:

```css
object-fit: cover;
```

позволяет изображению заполнить её, сохраняя свои пропорции.

При необходимости часть изображения обрезается.

---

### Пример круглого аватара

```css
.avatar {
  width: 5rem;
  aspect-ratio: 1;
  object-fit: cover;
  border-radius: 50%;
}
```

---

### Важно задавать размеры изображения в HTML

Например:

```html
<img
  src="photo.jpg"
  alt="..."
  width="1200"
  height="800"
/>
```

Эти атрибуты помогают браузеру заранее определить пропорции изображения и зарезервировать место до загрузки файла.

Это уменьшает неожиданные скачки макета.

---

### CSS решает не всю задачу Responsive Images

CSS может сделать **отображение изображения гибким**.

Но если нужно на телефоне загружать маленький файл, а на большом экране — большой, используются возможности HTML:

```text
srcset
sizes
<picture>
<source>
```

Например, это позволяет не скачивать огромную фотографию на маленьком мобильном экране.

CSS отвечает прежде всего за отображение, а HTML Responsive Images — за выбор подходящего ресурса.

---

### Главное

Базовый адаптивный вариант:

```css
img {
  max-width: 100%;
  height: auto;
}
```

Для изображений фиксированной формы:

```css
img {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}
```

## 14. Что такое Container Queries?

**Container Queries (контейнерные запросы)** позволяют изменять стили компонента в зависимости от характеристик **его контейнера**, а не всей области просмотра браузера.

Например:

```text
Media Query
→ насколько широк viewport?

Container Query
→ насколько широк контейнер компонента?
```

---

### Зачем это нужно?

Представим одну карточку:

```text
Product Card
```

Она может использоваться:

```text
в sidebar
→ ширина 250px

в main
→ ширина 700px
```

При одинаковой ширине браузера карточка получает совершенно разное доступное пространство.

Media Query видит только:

```text
viewport = 1200px
```

Но компоненту важнее знать:

```text
мой контейнер = 250px
```

или:

```text
мой контейнер = 700px
```

---

### Container Query позволяет написать

```css
.card-wrapper {
  container-type: inline-size;
}

@container (min-width: 30rem) {
  .card {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}
```

Теперь `.card` меняется не из-за ширины браузера, а из-за ширины `.card-wrapper`.

---

### Современные Container Queries

В современном CSS контейнерные запросы могут работать не только с размером.

Существуют, в частности:

- запросы размера;
- запросы стилей;
- запросы состояния прокрутки.

Но для адаптивных компонентов в первую очередь важно понимать **size container queries** — запросы по размеру контейнера.

---

## 15. Чем Container Queries отличаются от Media Queries?

Главное различие — **что именно проверяется**.

---

### Media Query

```css
@media (min-width: 64rem) {
  ...
}
```

проверяет:

```text
ширину viewport
```

То есть весь браузер.

---

### Container Query

```css
@container (min-width: 30rem) {
  ...
}
```

проверяет:

```text
ширину подходящего контейнера
```

---

### Пример

Viewport:

```text
1200px
```

Внутри страницы:

```text
Sidebar
300px

Main
900px
```

Один и тот же компонент может находиться в обеих областях.

Media Query видит в обоих случаях:

```text
1200px
```

Container Query может видеть:

```text
300px
```

или:

```text
900px
```

---

### Сравнение

| Характеристика | Media Query | Container Query |
|---|---|---|
| Проверяет viewport | Да | Нет, если речь о size query |
| Проверяет размер контейнера | Нет | Да |
| Удобен для общей раскладки страницы | Да | Да, но реже основная роль |
| Удобен для переиспользуемых компонентов | Иногда | Особенно хорошо |
| At-rule | `@media` | `@container` |

---

### Когда Media Query лучше?

Например:

```text
общая навигация страницы
глобальная структура
общий desktop/mobile layout
системные предпочтения пользователя
```

---

### Когда Container Query лучше?

Когда компонент должен адаптироваться к **своему собственному доступному пространству**.

Например:

```text
карточка
виджет
sidebar component
product card
dashboard panel
```

MDN описывает container queries именно как аналог media queries, но с условиями, основанными на контейнере вместо viewport.

---

## 16. Как работает `@container`?

Для размерного Container Query обычно нужны два шага.

---

### Шаг 1. Создать query container

Например:

```css
.card-wrapper {
  container-type: inline-size;
}
```

Это означает:

> Размер контейнера по строчной оси можно использовать для Container Queries.

При обычном горизонтальном письме это прежде всего его ширина.

---

### Шаг 2. Написать `@container`

```css
@container (min-width: 30rem) {
  .card {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}
```

Если контейнер имеет ширину меньше:

```text
30rem
```

базовые стили остаются.

Когда ширина контейнера становится:

```text
>= 30rem
```

применяется правило внутри `@container`.

---

### Полный пример

```html
<div class="card-wrapper">
  <article class="card">
    <img src="product.jpg" alt="">
    <div class="card__content">
      ...
    </div>
  </article>
</div>
```

```css
.card-wrapper {
  container-type: inline-size;
}

.card {
  display: block;
}

@container (min-width: 30rem) {
  .card {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}
```

Получаем:

```text
узкий container

┌──────────────┐
│ Image        │
├──────────────┤
│ Content      │
└──────────────┘
```

Широкий container:

```text
┌────────────┬──────────────────┐
│ Image      │ Content          │
│            │                  │
└────────────┴──────────────────┘
```

---

### Именованные контейнеры

Можно дать контейнеру имя:

```css
.sidebar {
  container-name: sidebar;
  container-type: inline-size;
}
```

После этого:

```css
@container sidebar (min-width: 30rem) {
  ...
}
```

Так удобно, если вокруг элемента есть несколько возможных контейнеров.

---

### Сокращённое свойство

Существуют:

```css
container-name
container-type
```

и shorthand:

```css
container
```

Например:

```css
.sidebar {
  container: sidebar / inline-size;
}
```

---

### Современный синтаксис условия

Можно также встретить:

```css
@container (width >= 30rem) {
  ...
}
```

вместо:

```css
@container (min-width: 30rem) {
  ...
}
```

---

### Важно

Размерный `@container` не просто ищет любой родительский элемент.

Он ищет подходящего предка, который установлен как контейнер для соответствующего типа запроса.

`container-type` используется именно для создания такого контекста размерных запросов.

---

## 17. Когда Container Queries особенно полезны?

Container Queries особенно полезны для **переиспользуемых компонентов**, которые могут находиться в разных частях интерфейса.

---

### Пример: одна карточка в разных местах

Карточка товара может находиться в:

```text
широком каталоге
```

```text
┌───────────────────────────────┐
│ Image | Product information   │
└───────────────────────────────┘
```

или в:

```text
узком sidebar
```

```text
┌────────────┐
│ Image      │
├────────────┤
│ Product    │
└────────────┘
```

Viewport при этом может быть одинаковым.

Например:

```text
1440px
```

Но доступная ширина компонента разная.

---

### Без Container Queries

Приходилось ориентироваться на весь экран:

```css
@media (min-width: 1024px) {
  .card {
    ...
  }
}
```

Но компонент не знает, находится ли он:

```text
в колонке 300px

или

в области 900px
```

---

### С Container Queries

Компонент может сказать:

```css
@container (min-width: 30rem) {
  .card {
    ...
  }
}
```

То есть:

> Мне неважно, насколько велик весь экран. Если **мне самому** дали достаточно места — меняю раскладку.

---

### Особенно полезно для:

```text
карточек товаров

виджетов

dashboard

sidebar-компонентов

панелей

форм

модульных дизайн-систем

переиспользуемых UI-компонентов
```

---

### Компонент становится более независимым

Это важное архитектурное преимущество.

Вместо:

```text
компонент знает,
на каком устройстве он находится
```

получаем:

```text
компонент знает,
сколько пространства ему дали
```

Это делает компонент проще для повторного использования.

---

### Media Queries всё равно остаются нужны

Container Queries не заменяют полностью:

```css
@media
```

Например, Media Queries всё ещё отлично подходят для:

```text
глобальной структуры страницы

prefers-reduced-motion

prefers-color-scheme

orientation

hover

pointer
```

А Container Queries особенно сильны на уровне компонентов.

---

### Хорошая современная схема

```text
Media Queries
→ адаптивность страницы и среды

Container Queries
→ адаптивность компонентов
```

Именно возможность строить компоненты относительно собственного контейнера является одной из главных причин использования Container Queries.
