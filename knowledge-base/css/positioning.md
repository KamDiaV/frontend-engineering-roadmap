# VII. Позиционирование

## 1. Какие значения свойства `position` существуют?

Свойство:

```css
position
```

определяет, **по какому алгоритму браузер будет рассчитывать положение элемента на странице**.

Основные значения:

```css
position: static;
position: relative;
position: absolute;
position: fixed;
position: sticky;
```

### `static`

Стандартное значение.

Элемент располагается в обычном потоке документа.

```css
.element {
  position: static;
}
```

---

### `relative`

Элемент остаётся в обычном потоке, но его можно визуально сместить относительно его первоначального положения.

```css
.element {
  position: relative;
  top: 20px;
}
```

---

### `absolute`

Элемент удаляется из обычного потока и позиционируется относительно своего содержащего блока.

```css
.element {
  position: absolute;
  top: 0;
  right: 0;
}
```

---

### `fixed`

Элемент удаляется из обычного потока и обычно позиционируется относительно области просмотра браузера.

```css
.element {
  position: fixed;
  top: 0;
  right: 0;
}
```

При прокрутке страницы он обычно остаётся на одном месте.

---

### `sticky`

Элемент остаётся в обычном потоке, но при прокрутке может «прилипнуть» к заданной границе.

```css
.element {
  position: sticky;
  top: 0;
}
```

Например, так можно сделать заголовок, который при прокрутке закрепляется сверху.

---

`static` является начальным значением `position`. Все значения, кроме `static`, делают элемент позиционированным.

---

## 2. Как работает `position: static`?

```css
.element {
  position: static;
}
```

`static` — стандартное позиционирование элемента.

Элемент располагается по правилам обычного потока документа.

Например:

```html
<div class="first">First</div>
<div class="second">Second</div>
<div class="third">Third</div>
```

Без специального позиционирования:

```text
First
Second
Third
```

Элементы занимают свои обычные места и влияют на расположение соседних элементов.

### `top`, `right`, `bottom`, `left`

При:

```css
position: static;
```

свойства:

```css
top
right
bottom
left
```

не влияют на положение элемента.

Например:

```css
.box {
  position: static;
  top: 100px;
  left: 100px;
}
```

Элемент не сместится на `100px`.

### `z-index`

В обычном случае `z-index` также не применяется к статически позиционированному элементу.

Например:

```css
.box {
  position: static;
  z-index: 100;
}
```

само по себе не поднимет обычный блок над другими позиционированными элементами.

Позже важно помнить исключение: элементы Flexbox и Grid могут использовать `z-index`, даже если сами не получили обычное позиционирование.

---

## 3. Как работает `position: relative`?

При:

```css
position: relative;
```

элемент **остаётся в обычном потоке документа**, но его можно визуально сместить относительно его первоначального положения.

Например:

```css
.box {
  position: relative;
  top: 20px;
  left: 30px;
}
```

Элемент будет смещён:

```text
20px вниз
30px вправо
```

### Почему `top: 20px` двигает вниз?

Потому что `top` задаёт смещение от верхней стороны первоначального положения.

Можно представить:

```text
исходное положение

┌──────────┐
│   box    │
└──────────┘

top: 20px
      ↓

┌──────────┐
│   box    │
└──────────┘
```

А:

```css
left: 30px;
```

отодвигает левую сторону элемента на `30px` от первоначального положения, поэтому элемент движется вправо.

---

### Исходное место сохраняется

Это одна из важнейших особенностей `relative`.

Допустим:

```html
<div class="first">First</div>
<div class="second">Second</div>
<div class="third">Third</div>
```

```css
.second {
  position: relative;
  top: 30px;
}
```

`.second` визуально переместится вниз.

Но `.third` останется там, где находился бы, если бы `.second` вообще не был смещён.

То есть:

```text
первоначальное место .second
в потоке сохраняется
```

Соседние элементы не перестраиваются вслед за визуальным смещением.

---

### Очень распространённое применение

`position: relative` часто устанавливают родителю для абсолютно позиционированного дочернего элемента:

```css
.card {
  position: relative;
}

.card__badge {
  position: absolute;
  top: 10px;
  right: 10px;
}
```

Теперь `.card__badge` можно позиционировать относительно `.card`.

---

### Создаёт ли `relative` новый контекст наложения?

Сам по себе:

```css
position: relative;
```

с:

```css
z-index: auto;
```

не создаёт отдельный контекст наложения.

Но:

```css
position: relative;
z-index: 1;
```

создаёт.

---

## 4. Как работает `position: absolute`?

При:

```css
position: absolute;
```

элемент **удаляется из обычного потока документа**.

То есть место, которое он раньше занимал, больше не резервируется.

Например:

```html
<div class="first">First</div>
<div class="second">Second</div>
<div class="third">Third</div>
```

```css
.second {
  position: absolute;
}
```

Для обычной раскладки `.second` больше не занимает своё прежнее место.

Условно:

```text
First
Third
```

а `.second` располагается отдельно поверх или рядом с ними в зависимости от координат.

---

### Положение задаётся через отступы

Например:

```css
.second {
  position: absolute;
  top: 20px;
  right: 30px;
}
```

Положение рассчитывается относительно **содержащего блока** этого элемента.

---

### Практический пример

```html
<div class="card">
  <img src="photo.jpg" alt="">
  <span class="badge">New</span>
</div>
```

```css
.card {
  position: relative;
}

.badge {
  position: absolute;
  top: 10px;
  right: 10px;
}
```

Получаем:

```text
.card
┌─────────────────────┐
│               New   │
│                     │
│       image         │
│                     │
└─────────────────────┘
```

`.badge` больше не участвует в обычной раскладке содержимого карточки.

---

### Размеры absolute-элемента

Абсолютно позиционированный элемент можно растянуть между двумя сторонами.

Например:

```css
.element {
  position: absolute;

  left: 0;
  right: 0;
}
```

если `width` остаётся `auto`, браузер может растянуть элемент по доступной горизонтальной области.

Аналогично:

```css
.element {
  position: absolute;

  top: 0;
  bottom: 0;
}
```

при автоматической высоте может растянуть элемент по вертикали.

---

### Контекст блочного форматирования

Абсолютно позиционированный элемент создаёт независимый контекст форматирования для своего содержимого.

---

### Контекст наложения

`position: absolute` сам по себе не обязательно создаёт новый контекст наложения.

Но сочетание:

```css
position: absolute;
z-index: 1;
```

его создаёт.

---

## 5. Относительно какого элемента позиционируется absolute-элемент?

Это один из самых важных вопросов в теме позиционирования.

Упрощённое правило:

> `position: absolute` обычно позиционируется относительно ближайшего предка, у которого `position` отличается от `static`.

Например:

```html
<div class="card">
  <span class="badge">New</span>
</div>
```

```css
.card {
  position: relative;
}

.badge {
  position: absolute;
  top: 10px;
  right: 10px;
}
```

У `.badge`:

```css
position: absolute;
```

Браузер идёт вверх по DOM:

```text
.badge
   ↑
.card
```

и находит:

```css
.card {
  position: relative;
}
```

Поэтому именно `.card` становится ориентиром для позиционирования `.badge`.

---

### Какие значения `position` у предка подходят?

Любое значение кроме:

```css
position: static;
```

То есть, например:

```text
relative
absolute
fixed
sticky
```

---

### Пример с несколькими предками

```html
<div class="page">
  <div class="card">
    <span class="badge">New</span>
  </div>
</div>
```

```css
.page {
  position: relative;
}

.card {
  position: static;
}

.badge {
  position: absolute;
  top: 0;
  right: 0;
}
```

Браузер проверяет:

```text
.badge
↓
.card → static → не подходит
↓
.page → relative → подходит
```

Поэтому `.badge` позиционируется относительно `.page`.

---

### Если подходящего предка нет

Если подходящий содержащий блок среди предков не найден, абсолютное позиционирование будет связано с начальным содержащим блоком документа.

На экране он связан с областью просмотра страницы.

---

### Важный современный нюанс

Правило:

> «absolute ищет ближайшего `position != static`»

очень полезно для начала, но оно не описывает все случаи CSS.

Некоторые другие свойства предка тоже могут сделать его содержащим блоком для `absolute`.

Например:

```css
.parent {
  transform: translateX(0);
}
```

даже без:

```css
position: relative;
```

может стать содержащим блоком для абсолютно позиционированного потомка.

То же возможно при некоторых значениях:

```text
transform
filter
backdrop-filter
perspective
contain
will-change
content-visibility
```

Например:

```css
.parent {
  transform: rotate(0deg);
}

.child {
  position: absolute;
  top: 0;
}
```

`.parent` становится содержащим блоком для `.child`.

---

### Что запомнить на начальном этапе?

В большинстве обычных компонентов используется именно такой шаблон:

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
}
```

То есть:

```text
relative у родителя
+
absolute у ребёнка
```

Это создаёт понятную локальную систему координат.

---

## 6. Как работает `position: fixed`?

```css
.element {
  position: fixed;
}
```

удаляет элемент из обычного потока документа.

Место под него больше не резервируется.

По умолчанию на обычной веб-странице такой элемент позиционируется относительно **viewport — области просмотра браузера**.

Например:

```css
.button {
  position: fixed;
  right: 20px;
  bottom: 20px;
}
```

Кнопка будет находиться:

```text
20px от правого края
20px от нижнего края
viewport
```

---

### Что происходит при прокрутке?

Допустим:

```css
.chat {
  position: fixed;
  right: 24px;
  bottom: 24px;
}
```

Пользователь прокручивает страницу:

```text
↓
↓
↓
↓
```

а кнопка остаётся в том же месте экрана.

Поэтому `fixed` часто используется для:

- плавающих кнопок;
- фиксированной навигации;
- кнопки чата;
- элементов управления;
- некоторых модальных интерфейсов.

---

### `fixed` удаляется из потока

Например:

```css
.header {
  position: fixed;
  top: 0;
  height: 80px;
}
```

Следующий элемент не будет автоматически учитывать эти `80px`.

Поэтому содержимое может оказаться под шапкой.

Иногда требуется:

```css
main {
  padding-top: 80px;
}
```

---

### Важный нюанс

Говорить:

> `fixed` всегда позиционируется относительно viewport

не совсем точно.

Обычно — да.

Но некоторые свойства предка могут создать новый содержащий блок.

Например:

```css
.wrapper {
  transform: translateX(0);
}

.child {
  position: fixed;
  top: 0;
}
```

В такой ситуации `.child` может позиционироваться относительно `.wrapper`, а не обычного viewport.

Такое поведение могут вызывать, в частности:

```text
transform
perspective
filter
contain
```

и некоторые связанные свойства.

---

### Контекст наложения

`position: fixed` всегда создаёт новый контекст наложения.

Даже если:

```css
z-index: auto;
```

---

## 7. Как работает `position: sticky`?

`position: sticky` сочетает особенности обычного и закреплённого позиционирования.

Например:

```css
.header {
  position: sticky;
  top: 0;
}
```

Сначала элемент располагается в обычном потоке.

Он прокручивается вместе со страницей:

```text
страница
↓
↓
header
↓
↓
```

Когда его верхняя сторона достигает:

```css
top: 0;
```

элемент начинает удерживаться у верхней границы области прокрутки.

---

### Пример

```html
<article>
  <h2 class="title">CSS</h2>

  <p>...</p>
  <p>...</p>
  <p>...</p>
</article>
```

```css
.title {
  position: sticky;
  top: 0;
}
```

Пока заголовок находится далеко от верхнего края:

```text
он ведёт себя как обычный элемент
```

Когда пользователь докручивает его до:

```text
top: 0
```

он закрепляется.

---

### В отличие от `fixed`

Очень важно:

```text
fixed
→ удаляется из обычного потока
```

```text
sticky
→ остаётся в обычном потоке
```

То есть исходное место sticky-элемента учитывается при раскладке.

---

### Относительно чего работает `sticky`?

Он ориентируется не всегда непосредственно на окно браузера.

Sticky-элемент связан с ближайшим предком, который создаёт механизм прокрутки.

Это может произойти, например, при:

```css
overflow: auto;
overflow: scroll;
overflow: hidden;
```

Поэтому:

```css
.sidebar {
  height: 500px;
  overflow: auto;
}

.title {
  position: sticky;
  top: 0;
}
```

`.title` будет закрепляться внутри `.sidebar`, а не обязательно относительно всей страницы.

---

### Sticky ограничен своим контейнером

Элемент не может бесконечно оставаться закреплённым.

Когда заканчивается его содержащий блок, sticky-элемент тоже должен покинуть область закрепления.

Это позволяет делать, например:

```text
Section A
[sticky title A]
...
конец Section A

Section B
[sticky title B]
...
```

---

### Создаёт ли `sticky` новый контекст наложения?

Да.

```css
position: sticky;
```

создаёт новый контекст наложения даже при:

```css
z-index: auto;
```

---

## 8. Почему `position: sticky` иногда не работает?

У `sticky` есть несколько важных условий.

Если одно из них нарушено, элемент может выглядеть так, будто:

```css
position: sticky;
```

вообще ничего не делает.

---

### 1. Не задана граница закрепления

Очень распространённая ошибка:

```css
.header {
  position: sticky;
}
```

Но браузеру не сказали:

> где именно элемент должен закрепиться?

Обычно необходимо:

```css
.header {
  position: sticky;
  top: 0;
}
```

Или, например:

```css
bottom: 20px;
```

Для нужной оси хотя бы одно соответствующее свойство смещения должно иметь значение, отличное от `auto`.

Иначе по этой оси `sticky` практически ведёт себя как `relative`.

---

### 2. У предка неожиданно установлен `overflow`

Например:

```css
.wrapper {
  overflow: hidden;
}
```

```css
.title {
  position: sticky;
  top: 0;
}
```

Sticky ищет ближайшего предка с механизмом прокрутки.

Поэтому `.wrapper` может стать тем контейнером, относительно которого он пытается закрепляться.

В результате разработчик ожидает:

```text
sticky относительно страницы
```

а получает:

```text
sticky относительно .wrapper
```

Это одна из наиболее частых причин неожиданного поведения.

---

### 3. Контейнер не имеет пространства для прокрутки

Sticky-элементу необходимо пространство, в котором он сможет:

```text
двигаться
↓
достичь границы
↓
оставаться закреплённым
```

Если родитель очень низкий:

```text
┌──────────────┐
│ sticky       │
└──────────────┘
```

ему может просто не хватать пространства, чтобы эффект стал заметен.

---

### 4. Sticky-элемент слишком высокий

Если сам элемент занимает практически всю высоту контейнера:

```text
container
┌────────────────┐
│ sticky         │
│                │
│                │
│                │
└────────────────┘
```

ему практически некуда перемещаться внутри содержащего блока.

---

### 5. Flexbox или Grid растянул элемент

Flexbox по умолчанию часто использует растягивание элементов по поперечной оси.

Например:

```css
.container {
  display: flex;
}
```

при обычных настройках элементы могут растягиваться.

Если sticky-элемент растянулся до высоты контейнера, для его движения может не остаться свободного пространства.

Иногда помогает:

```css
.sticky {
  position: sticky;
  top: 0;

  align-self: flex-start;
}
```

или соответствующая настройка выравнивания контейнера.

В Flexbox начальное выравнивание приводит к растягиванию элементов по поперечной оси, если их размер позволяет это.

---

### 6. Sticky привязан не к тому контейнеру, который ожидался

Например:

```html
<div class="outer">
  <div class="scroll">
    <div class="sticky"></div>
  </div>
</div>
```

Если `.scroll` имеет:

```css
overflow: auto;
```

именно он становится ближайшим контейнером прокрутки для `.sticky`.

---

### Алгоритм проверки

Если `sticky` не работает, проверь:

```text
1. Есть ли position: sticky?

2. Есть ли top / bottom / left / right?

3. Какой предок имеет overflow?

4. Кто является ближайшим scroll container?

5. Есть ли у контейнера место для прокрутки?

6. Не растянут ли sticky-элемент Flexbox/Grid?

7. Не равен ли sticky-элемент по размеру всему контейнеру?
```

---

## 9. Что делают `top`, `right`, `bottom`, `left`?

Эти свойства задают **смещения позиционированного элемента**.

```css
top
right
bottom
left
```

Их поведение зависит от значения:

```css
position
```

---

### При `position: static`

Они не работают:

```css
.box {
  position: static;
  top: 20px;
}
```

Элемент не сместится.

---

### При `position: relative`

Они смещают элемент относительно его первоначального положения.

Например:

```css
.box {
  position: relative;
  top: 20px;
  left: 30px;
}
```

Получаем:

```text
top: 20px
→ элемент вниз на 20px

left: 30px
→ элемент вправо на 30px
```

---

### При `position: absolute`

Значения задают расстояние от соответствующих сторон содержащего блока.

Например:

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
  top: 10px;
  right: 20px;
}
```

Получаем:

```text
.parent
┌──────────────────────────┐
│             10px         │
│              ↓           │
│       ┌─────────┐ ←20px  │
│       │ .child  │        │
│       └─────────┘        │
└──────────────────────────┘
```

---

### При `position: fixed`

Обычно задают расстояние от краёв viewport.

Например:

```css
.button {
  position: fixed;
  right: 20px;
  bottom: 20px;
}
```

---

### При `position: sticky`

Определяют границу, начиная с которой элемент должен удерживаться при прокрутке.

```css
.header {
  position: sticky;
  top: 0;
}
```

---

### Значение `auto`

Начальное значение:

```css
top: auto;
right: auto;
bottom: auto;
left: auto;
```

означает, что соответствующее смещение не задаётся явно.

---

### Можно использовать отрицательные значения

Например:

```css
.element {
  position: relative;
  top: -10px;
}
```

Элемент сместится вверх.

---

### Логические аналоги

В современном CSS существуют также свойства:

```css
inset-block-start
inset-block-end
inset-inline-start
inset-inline-end
```

Они учитывают направление текста и режим письма.

Например, вместо физического:

```css
left: 0;
```

в некоторых интерфейсах удобнее использовать логическое направление:

```css
inset-inline-start: 0;
```

---

## 10. Что такое `inset`?

`inset` — сокращённое CSS-свойство для:

```css
top
right
bottom
left
```

Вместо:

```css
.element {
  top: 10px;
  right: 20px;
  bottom: 30px;
  left: 40px;
}
```

можно написать:

```css
.element {
  inset: 10px 20px 30px 40px;
}
```

---

### Синтаксис похож на `margin`

Одно значение:

```css
inset: 20px;
```

означает:

```text
top    20px
right  20px
bottom 20px
left   20px
```

---

Два значения:

```css
inset: 10px 20px;
```

означают:

```text
top/bottom → 10px
left/right → 20px
```

---

Три значения:

```css
inset: 10px 20px 30px;
```

означают:

```text
top        → 10px
left/right → 20px
bottom     → 30px
```

---

Четыре:

```css
inset: 10px 20px 30px 40px;
```

порядок:

```text
top
right
bottom
left
```

---

### Очень распространённый пример

```css
.overlay {
  position: absolute;
  inset: 0;
}
```

Это эквивалентно:

```css
.overlay {
  position: absolute;

  top: 0;
  right: 0;
  bottom: 0;
  left: 0;
}
```

При подходящих размерах такой элемент растягивается по области своего содержащего блока.

---

### Например, затемнение изображения

```css
.card {
  position: relative;
}

.card::before {
  content: "";
  position: absolute;
  inset: 0;

  background: rgb(0 0 0 / 0.4);
}
```

Псевдоэлемент покрывает всю карточку.

---

### Важно

`inset` задаёт именно **физические** стороны:

```text
top
right
bottom
left
```

Для логических направлений существуют:

```css
inset-block
inset-inline
```

и:

```css
inset-block-start
inset-block-end
inset-inline-start
inset-inline-end
```

---

### Не путать с `inset()`

Существует также функция:

```css
clip-path: inset(...);
```

Например:

```css
clip-path: inset(20px);
```

Это **другая возможность CSS**.

```css
inset: 20px;
```

— свойство позиционирования.

```css
clip-path: inset(20px);
```

— функция создания формы для обрезки.

---

### Главное

```text
inset
=
shorthand для:

top
right
bottom
left
```

---

## 11. Что такое Stacking Context?

**Stacking Context (контекст наложения)** — отдельная область, внутри которой браузер определяет, какие элементы должны отображаться выше или ниже других элементов по оси Z.

Обычно страницу представляют в двух измерениях:

```text
X → слева направо
Y → сверху вниз
```

Но когда элементы перекрываются, появляется условная третья ось:

```text
Z
```

Можно представить страницу как стопку прозрачных слоёв:

```text
пользователь
    ↑

┌───────────────┐  верхний слой
│   element C   │
└───────────────┘

┌───────────────┐
│   element B   │
└───────────────┘

┌───────────────┐  нижний слой
│   element A   │
└───────────────┘
```

Контекст наложения определяет правила расположения таких слоёв.

---

### Контексты могут быть вложенными

Например:

```html
<div class="parent">
  <div class="child"></div>
</div>

<div class="other"></div>
```

Допустим:

```css
.parent {
  position: relative;
  z-index: 1;
}

.child {
  position: relative;
  z-index: 9999;
}

.other {
  position: relative;
  z-index: 2;
}
```

Получаем два основных контекста:

```text
root
│
├── .parent → z-index: 1
│   └── .child → z-index: 9999
│
└── .other → z-index: 2
```

Очень важно:

`.child` со своим:

```css
z-index: 9999;
```

не может просто выйти из контекста `.parent`.

Сначала браузер сравнивает:

```text
.parent → 1
.other  → 2
```

И весь `.parent` вместе со своими потомками находится ниже `.other`.

---

### Каждый контекст независим

Это главный принцип:

> Значения `z-index` сравниваются прежде всего внутри одного контекста наложения.

После того как браузер расположил все элементы внутри дочернего контекста, весь этот контекст рассматривается снаружи как единая группа.

---

### Корневой контекст

Корневой элемент документа:

```html
<html>
```

создаёт корневой контекст наложения.

Внутри него могут находиться другие вложенные контексты.

---

### Главное

```text
Stacking Context
=
отдельная система слоёв по оси Z
```

Контексты могут быть:

```text
root
│
├── context A
│   ├── element
│   └── element
│
└── context B
    ├── element
    └── element
```

И `z-index` дочернего элемента действует **внутри его собственного контекста**, а не глобально по всей странице.

---

## 12. Что такое `z-index`?

`z-index` управляет порядком наложения элементов по условной оси Z.

Например:

```css
.first {
  position: relative;
  z-index: 1;
}

.second {
  position: relative;
  z-index: 2;
}
```

Если элементы перекрываются:

```text
.second
```

будет отображаться выше:

```text
.first
```

потому что:

```text
2 > 1
```

---

### Значения

Можно использовать:

```css
z-index: auto;
```

или целые числа:

```css
z-index: -1;
z-index: 0;
z-index: 1;
z-index: 10;
z-index: 100;
```

---

### Положительные значения

```css
z-index: 10;
```

могут поднимать элемент выше других элементов **в том же контексте наложения**.

---

### Отрицательные значения

```css
z-index: -1;
```

могут расположить элемент на более низком уровне текущего контекста.

Но это не означает:

> обязательно спрятать элемент под всей страницей.

Он всё равно ограничен правилами своего контекста наложения.

---

### `z-index: auto`

Начальное значение:

```css
z-index: auto;
```

не создаёт отдельный локальный контекст наложения в обычном случае.

---

### Целое значение создаёт контекст

Для позиционированного элемента:

```css
position: relative;
z-index: 1;
```

создаётся новый контекст наложения.

То же относится, например, к:

```css
position: absolute;
z-index: 5;
```

---

### `z-index` работает не только с `position`

В современном CSS Flexbox- и Grid-элементы тоже могут использовать:

```css
z-index
```

без обязательного:

```css
position: relative;
```

Например:

```css
.container {
  display: grid;
}

.first {
  z-index: 2;
}

.second {
  z-index: 1;
}
```

Если элементы Grid перекрываются, `z-index` может управлять их порядком.

---

### Большое число не делает `z-index` глобальным

Например:

```css
z-index: 999999;
```

не означает:

> элемент теперь выше всего на странице.

Это число имеет смысл внутри соответствующей системы контекстов наложения.

---

### Главное

```text
z-index
→ управляет порядком наложения по оси Z
```

```text
больше число
→ обычно выше

меньше число
→ обычно ниже
```

Но только после того, как учтены **контексты наложения**.

---

## 13. Почему большой `z-index` иногда не помогает?

Потому что `z-index` не является одним глобальным числом для всей страницы.

Например:

```html
<div class="first">
  <div class="modal"></div>
</div>

<div class="second"></div>
```

CSS:

```css
.first {
  position: relative;
  z-index: 1;
}

.modal {
  position: absolute;
  z-index: 999999;
}

.second {
  position: relative;
  z-index: 2;
}
```

На первый взгляд можно подумать:

```text
999999 > 2
```

значит `.modal` должна быть сверху.

Но нет.

Структура контекстов:

```text
root
│
├── .first
│   z-index: 1
│
│   └── .modal
│       z-index: 999999
│
└── .second
    z-index: 2
```

Сначала браузер сравнивает:

```text
.first  → 1
.second → 2
```

`.second` выше.

А `.modal` заперта внутри:

```text
.first
```

и не может своим `999999` перепрыгнуть соседний родительский контекст.

---

### Что проверять, если `z-index` не работает?

Нужно смотреть не только на сам элемент, но и на его предков.

Например:

```css
opacity: 0.9;
```

может создать новый контекст наложения.

То же может сделать:

```css
transform: translateX(0);
```

или:

```css
filter: blur(0);
```

или:

```css
isolation: isolate;
```

Поэтому проблема часто находится не здесь:

```css
.modal {
  z-index: 99999;
}
```

а значительно выше по DOM:

```css
.parent {
  transform: translateZ(0);
}
```

---

### Типичная ошибка

Разработчик начинает увеличивать числа:

```text
10
100
1000
10000
99999999
```

но ничего не меняется.

Это хороший сигнал:

> Нужно искать родительский stacking context, а не увеличивать `z-index`.

---

### Ещё один важный случай — Top Layer

Некоторые элементы браузер может поместить в специальный **Top Layer**.

Например, определённые:

- `<dialog>`;
- popover;
- fullscreen-элементы.

Top Layer находится поверх обычных контекстов документа.

Поэтому обычный:

```css
z-index: 999999999;
```

не позволит обычному элементу перепрыгнуть элемент, находящийся в Top Layer.

---

### Главное

```text
огромный z-index
≠
выше всего на странице
```

Нужно учитывать:

```text
родительские stacking contexts
↓
их z-index
↓
stacking context самого элемента
↓
z-index внутри него
```

---

## 14. Какие свойства могут создавать новый Stacking Context?

Новый контекст наложения создаётся не только через:

```css
position
+
z-index
```

Современный CSS содержит довольно много причин его появления.

---

### 1. Корневой элемент `<html>`

```html
<html>
```

создаёт корневой контекст наложения.

---

### 2. `position: relative` или `absolute` + `z-index`

Например:

```css
.element {
  position: relative;
  z-index: 1;
}
```

или:

```css
.element {
  position: absolute;
  z-index: 1;
}
```

При этом:

```css
z-index: auto;
```

не создаёт контекст только из-за `relative` или `absolute`.

---

### 3. `position: fixed`

```css
.element {
  position: fixed;
}
```

создаёт контекст наложения независимо от `z-index`.

---

### 4. `position: sticky`

```css
.element {
  position: sticky;
}
```

также всегда создаёт новый контекст наложения.

---

### 5. Flexbox-элемент с `z-index`

Например:

```css
.parent {
  display: flex;
}

.child {
  z-index: 1;
}
```

`.child` может создать собственный контекст наложения, даже без:

```css
position: relative;
```

---

### 6. Grid-элемент с `z-index`

Аналогично:

```css
.parent {
  display: grid;
}

.child {
  z-index: 1;
}
```

---

### 7. `opacity` меньше `1`

Например:

```css
.element {
  opacity: 0.9;
}
```

создаёт контекст наложения.

Важно:

```css
opacity: 1;
```

не создаёт его по этой причине.

---

### 8. `transform`

Например:

```css
.element {
  transform: translateX(10px);
}
```

или:

```css
transform: rotate(10deg);
```

создаёт новый контекст наложения.

Также это относится к отдельным современным свойствам:

```css
translate
rotate
scale
```

если их значение отличается от `none`.

---

### 9. `filter`

Например:

```css
.element {
  filter: blur(5px);
}
```

создаёт контекст наложения.

---

### 10. `backdrop-filter`

Например:

```css
.element {
  backdrop-filter: blur(10px);
}
```

тоже может создать новый контекст.

---

### 11. `perspective`

```css
.element {
  perspective: 1000px;
}
```

создаёт контекст наложения.

---

### 12. `clip-path`

Например:

```css
.element {
  clip-path: circle(50%);
}
```

создаёт контекст наложения.

---

### 13. Маски

Например:

```css
mask-image: linear-gradient(...);
```

Также сюда относятся:

```text
mask
mask-image
mask-border
```

при соответствующих значениях.

---

### 14. `mix-blend-mode`

Например:

```css
.element {
  mix-blend-mode: multiply;
}
```

Если значение отличается от:

```css
normal
```

создаётся контекст наложения.

---

### 15. `isolation: isolate`

```css
.element {
  isolation: isolate;
}
```

намеренно создаёт новый контекст наложения.

Это особенно полезно, когда разработчик **специально хочет ограничить работу `z-index` внутри компонента**.

Например:

```css
.card {
  isolation: isolate;
}
```

Теперь внутренние слои карточки можно контролировать более локально.

---

### 16. `contain`

Некоторые значения:

```css
contain: layout;
contain: paint;
```

создают новый контекст наложения.

То же относится к составным значениям, содержащим эти виды изоляции:

```css
contain: content;
contain: strict;
```

---

### 17. `container-type`

Например:

```css
.container {
  container-type: inline-size;
}
```

или:

```css
container-type: size;
```

также создаёт новый контекст наложения.

Это важно при работе с Container Queries.

---

### 18. `will-change`

Например:

```css
.element {
  will-change: transform;
}
```

браузер может заранее создать структуры, которые появились бы при применении `transform`.

Если указанное свойство при обычном неначальном значении создаёт контекст наложения, `will-change` также может привести к его созданию.

Не стоит добавлять:

```css
will-change
```

повсюду без необходимости — это средство оптимизации, а не обычный способ создавать слои.

---

### 19. Top Layer

Элементы, помещённые браузером в специальный верхний слой, создают контекст наложения.

Например:

```text
fullscreen
dialog в modal-состоянии
popover
```

Соответствующий:

```css
::backdrop
```

тоже участвует в Top Layer и создаёт свой контекст.

---

### 20. Некоторые CSS-анимации

Если свойство, способное создавать stacking context, анимируется через:

```css
@keyframes
```

и после анимации значение сохраняется через:

```css
animation-fill-mode: forwards;
```

элемент также может сохранить созданный контекст наложения.

---

### Основные причины, которые важно запомнить в первую очередь

Для начинающего в первую очередь стоит хорошо помнить:

```text
<html>

position: relative / absolute
+
z-index != auto

position: fixed

position: sticky

flex/grid item
+
z-index != auto

opacity < 1

transform

filter

isolation: isolate
```

А затем добавить:

```text
container-type

mix-blend-mode

perspective

clip-path

mask

contain

will-change

Top Layer
```

Полный современный перечень именно таких причин приводит MDN.

---

## Главное, что нужно запомнить

```text
position: static
→ обычное положение
→ top/right/bottom/left не работают
```

```text
position: relative
→ остаётся в обычном потоке
→ можно визуально смещать
→ исходное место сохраняется
```

```text
position: absolute
→ удаляется из обычного потока
→ позиционируется относительно содержащего блока
```

Самый распространённый паттерн:

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
}
```

```text
position: fixed
→ удаляется из обычного потока
→ обычно привязан к viewport
→ остаётся на месте при прокрутке
```

```text
position: sticky
→ остаётся в обычном потоке
→ при прокрутке может закрепляться
→ нужен top/right/bottom/left
```

```text
top
right
bottom
left
→ задают смещения позиционированного элемента
```

```text
inset
→ сокращённая запись для:

top
right
bottom
left
```

```text
Stacking Context
→ отдельная система наложения элементов по оси Z
```

```text
z-index
→ управляет порядком наложения
  внутри соответствующего stacking context
```

```text
огромный z-index
≠
гарантия, что элемент будет выше всего
```

Если `z-index` не помогает:

```text
проверить stacking context самого элемента
↓
```
